# Карточка контрагента (`/suppliers/:id`)

Паспорт организации-подрядчика: шапка со сводным статусом, пулом и датой аккредитации, блок трёх проверок (СБ, юрист, финансы) с примечаниями, ключевые реквизиты и виды работ, теги, и восемь вкладок — «Основное», «Финансы», «Документы и файлы», «Опыт и допуски», «Участие», «Контакты», «Пользователи», «Активность».

Связанные разделы: бизнес-логика — [../02-business-logic/suppliers.md](../02-business-logic/suppliers.md); API — [../04-api/endpoints-suppliers.md](../04-api/endpoints-suppliers.md), вложения — [../04-api/endpoints-files.md](../04-api/endpoints-files.md), приглашение в тендер — [../04-api/endpoints-tenders.md#post-tenderstender_idinvitations](../04-api/endpoints-tenders.md#post-tenderstender_idinvitations); реестр — [suppliers.md](suppliers.md); роли — [../01-product/users-and-roles.md §4](../01-product/users-and-roles.md#4-матрица-роль--действие).

## Маршрут

- `/suppliers/:id`, `:id` — числовой id контрагента.
- `?tab=<вкладка>` (`overview`, `finance`, `documents`, `experience`, `participation`, `contacts`, `users`, `activity`) — открыть сразу нужную вкладку (так ведут виджеты очередей СБ и юриста на главной). Дальше вкладка — состояние страницы, в адрес не пишется.
- В крошках — «Список контрагентов / <название>»; пока название не загрузилось — id.

## Назначение

Одно место, где сотрудник видит всё о подрядчике и ведёт его квалификацию: СБ и юрист выставляют результаты своих проверок с обязательным комментарием, специалист — пул, дату аккредитации, опыт и допуски, администратор — всё, плюс удаление в корзину. Отсюда же контрагента приглашают в тендер и выдают его сотрудникам вход в личный кабинет.

## Роли и права

| Роль | Что видит и может (интерфейс) |
|---|---|
| Администратор | Всё: меню «Действия» (статус СБ, юридический, финансовый, пул), «Пригласить в тендер», «Удалить контрагента», переименование названия на месте, все три проверки и пул правятся на месте |
| Тендерный специалист | Меню «Действия»: «Сменить финансовый статус» (только при праве видеть финансы) и «Сменить пул»; дата аккредитации; проверки СБ и юриста — только чтение; нет удаления и переименования |
| Служба безопасности | «Действия» → «Сменить статус СБ»; редактируется только строка «Проверка СБ»; вкладка «Финансы» замаскирована («Финансовый блок скрыт…»), если нет права видеть финансы |
| Юрист | «Действия» → «Сменить юридический статус»; редактируется только строка «Юрист»; финансы — как у СБ |
| Поставщик, лид, владелец площадки | Нет доступа (перенаправление); свою карточку поставщик видит в кабинете |

Общие для всех сотрудников (включая СБ и юриста) действия: правка ИНН/КПП, даты создания, видов работ, тегов, комментария, штата, выручки, допусков, опыта, контактов, пользователей ЛК, загрузка файлов, «Пригласить в тендер» — интерфейс их не ограничивает (см. [открытые вопросы](../_oq/SCR-3.md)). Серверные правила — [BL §6](../02-business-logic/suppliers.md#6-права-доступа).

![Специалист: в меню «Действия» — финансовый статус и пул; проверки СБ и юриста только для чтения](assets/supplier-card--specialist.png)

На снимке специалиста: ① финансы правятся на месте, ② проверка СБ — только чтение (примечание текстом), ③ название — заголовок без переименования.

![Служба безопасности: в меню только «Сменить статус СБ»](assets/supplier-card--security.png)

![Юрист: в меню только «Сменить юридический статус»](assets/supplier-card--lawyer.png)

**Маска контактов.** Право `suppliers.contacts.view` и настройка сервера `CONTACTS_MASK_ENABLED` на этой карточке **не применяются**: ИНН, телефоны и email показываются полностью любому сотруднику. Маскирование (`78•••••825`, `k•••••@domain`, `+7 952 ••• •• 16`) действует только в сравнительной таблице тендера, её выгрузке и протоколе ([tender-card.md](tender-card.md#роли-и-права)). Распространять ли маску на карточку — [открытый вопрос](../_oq/SCR-3.md).

## Как попасть

- Строка реестра [suppliers.md](suppliers.md); ссылки «Открыть контрагента» из карточки тендера, сравнительной таблицы, ленты активности; виджеты очередей СБ/юриста на главной (с `?tab=`); «→ Открыть» в ошибке дубля ИНН.

### Смена статуса проверки

Два пути, результат один (`PATCH /suppliers/{id}/sb-status | legal-status | finance-status`, [описание](../04-api/endpoints-suppliers.md#статусная-модель)):

1. **На месте.** Клик по капсуле → меню шкалы оси (СБ и юрист: «Не требуется», «Ожидает», «На проверке», «Пройдена», «Пройдена с замечаниями», «Не пройдена»; финансы: «Ожидает», «Одобрено», «Одобрено с лимитом», «Отказ»). Выбор подсвечивает поле примечания («Укажите обязательное примечание…»), справа — «Сохранить» и «Отмена»; Enter — сохранить, Esc — отменить. Без примечания — «Укажите примечание». «Пройдена с замечаниями» и «Одобрено с лимитом» сразу открывают окно (нужен развёрнутый комментарий / сумма лимита).
2. **Окном** из меню «Действия»: «Статус проверки СБ» / «Юридический статус» / «Статус финансового блока», описание «Комментарий обязателен — он попадёт во вкладку «Активность».»; поля «Статус», «Комментарий» * (многострочный, «Что именно проверили и почему такой статус»), для «Одобрено с лимитом» — «Сумма лимита (₽)» * (число > 0). «Сохранить» неактивна без комментария (и без лимита > 0).

После сохранения сервер пересчитывает сводный статус, дату аккредитации и (для «с замечаниями») пул; карточки, открытые у других сотрудников, обновляются сами по событию живого потока.

## Вкладки

### «Основное»

![Вкладка «Основное»](assets/supplier-card--tab-overview.png)

- **«Реквизиты организации»** (только чтение, копирование): ИНН и ОГРН с кнопкой копирования, КПП, «Налоговый режим» («не указан»), «Номер анкеты» `АНК-00207` (id с ведущими нулями до 5 знаков), «Дата создания», «В реестре с» (если пусто — «не указана» и кнопка «Отметить поданной» для заведённого вручную; правила обязательных документов те же, что у анкеты, отказ — окном «Не удалось отметить анкету поданной»), «Анкета отправлена» (дата или «не отправлена»).
- **«Согласие на обработку ПДн»**: капсула «Получено» / «Не получено», «Дата», «Документ-основание» («не приложен»), приложенные файлы с кнопкой «Скачать «…»», зона загрузки «Перетащите файл сюда или выберите с устройства» — «PDF, JPG или PNG — до 25 МБ» (больше — «Файл больше 25 МБ — такой не примем. Пришлите скан меньшего размера.»). Файл ложится во вложения контрагента с типом «Согласие на обработку ПДн».
- **«Участие в тендерах»** — свёрнутая сводка «N тендеров, M побед» и кнопка «Все тендеры» (переключает на вкладку «Участие»).
- **«Комментарий тендерного специалиста»** — многострочное поле («Например: обнаружен арбитраж — запросить пояснения») и «Сохранить».

### «Финансы»

![Вкладка «Финансы»](assets/supplier-card--tab-finance.png)

- **«Выручка по годам»**: строки «год × выручка, тыс. ₽»; опорный (последний завершённый) год помечен «опорный», пустой — «Внесите выручку за 2025»; по умолчанию видны 3 года, «Показать все годы (N)» / «Свернуть до трёх лет»; «Сохранить выручку» (`PUT /suppliers/{id}/revenues`), после — «Сохранено».
- **«Динамика выручки»** — график-область по годам (подсказка «2024 год (опорный) · Выручка: 2 910 000 тыс. ₽» / «— (не заполнено)»).
- **«Штат»** — число, «чел.», «Сохранить».
- Без права видеть финансы — вместо выручки «Финансовый блок скрыт — режим коммерческой тайны. Нужно специальное право просмотра: его выдаёт администратор.» (штат остаётся).

![Финансы скрыты (служба безопасности)](assets/supplier-card--finance-masked.png)

### «Документы и файлы»

![Вкладка «Документы и файлы»](assets/supplier-card--tab-documents.png)

- **«Документы»** — документы анкеты (название, дата) или «Документы не приложены».
- **«Файлы контрагента»** — слоты обязательных документов анкеты «Устав», «Выписка ЕГРЮЛ / свидетельство ИНН», «Документ, подтверждающий полномочия подписанта» с капсулами «Приложен» / «Не приложен»; список файлов (имя, дата, размер, тип, «Скачать»; у ссылки — «ссылка», у незагруженного — «файл не загружен»); блок «Загрузите файл»: «Тип документа» («Без типа», «Устав», «Выписка ЕГРЮЛ / свидетельство ИНН», «Полномочия подписанта», «Выписка ЕГРЮЛ», «Допуск СРО», «Лицензия МЧС», «Лицензия Минкультуры», «Финансовая отчётность», «Согласие на обработку ПДн», «Прочее») и зона перетаскивания «До 25 МБ на файл». Загрузка — общий механизм вложений ([endpoints-files.md](../04-api/endpoints-files.md)).
- **«Документы к КП (от поставщика)»** — если поставщик приложил файлы к КП.

### «Опыт и допуски»

![Вкладка «Опыт и допуски»](assets/supplier-card--tab-experience.png)

- **«Допуски и сертификаты»**: «СРО», «Лицензия МЧС», «Лицензия Минкультуры» (плейсхолдер «Номер, дата, кем выдана») и «Сохранить»; у роли контрагента — только чтение («нет допуска» / «нет лицензии»).
- **«Опыт (свободный текст, до 17.09.2026)»** — только если остался старый свободный текст: подсказка разнести его по таблицам и значок «Очистить старый текст» (подтверждение «… Это действие необратимо.»).
- **«Опыт работ»** — по группе на каждый вид работ контрагента: «Договоров: N» или «Опыт не заявлен», «+» «Добавить договор: <вид работ>». Колонки: «Заказчик», «Объект и адрес», «Работы по договору», «Роль» (Генподрядчик / Подрядчик), «Сроки» (`ММ.ГГГГ — ММ.ГГГГ` или «по н.в.»), «Стоимость» (тыс. ₽), «Статус» («Завершён» / «В процессе»), «Действия» (изменить, удалить с подтверждением «Удалить договор с заказчиком «…»?»). Нет видов работ — «Виды работ не выбраны. Укажите виды работ в шапке карточки, чтобы вести опыт.».

Окно **«Добавить договор» / «Изменить договор»** (API `…/work-experience`):

### «Участие»

![Вкладка «Участие»](assets/supplier-card--tab-participation.png)

Группа «Участие в тендерах» (подсказка: отозванные приглашения не показываются; сумма — итог текущей версии поданного КП): показатели «Тендеров» (подпись «подал КП: N»), «Побед» («N% от завершённых (M)» / «завершённых пока нет»), «Сумма выигранных заявок» (если были победы); таблица «Тендер» (название + номер, ссылка на карточку тендера), «Дата приглашения», «Роль» («Победитель» / «Участник»), «Сумма заявки» (₽ или «—»), «Итог» («Победа», «Не победил», «КП не подано», «В процессе», «Отказался», «Тендер отменён»). Пусто — «Контрагента ещё не приглашали ни в один тендер…». Данные — `GET /suppliers/{id}/participation`.

### «Контакты»

![Вкладка «Контакты»](assets/supplier-card--tab-contacts.png)

- Шапка «Контакты» · «Представителей: N», подсказка (представители — лица компании, а не учётные записи; доступ в ЛК — на вкладке «Пользователи»), «+» «Добавить контакт».
- **«Организация»**: «Руководитель», «Телефон», «Email» (пусто — «не указан — письма по тендерам не уходят»), «Сайт»; у значений — «Позвонить»/«Написать письмо» и «Скопировать»; карандаш «Изменить контакты организации» превращает блок в форму (ФИО руководителя — проверка ФИО; телефон; email — «На этот адрес уходят письма по тендерам»; сайт — «https:// подставится сам», ошибки «Адрес сайта пишется без пробелов», «Адрес сайта начинается с http:// или https://», «Укажите адрес сайта, например stroyprof.ru» и др.) с «Сохранить»/«Отмена». Сохраняются только изменённые поля.
- **Таблица представителей**: «Представитель» (аватар-инициалы, ФИО, должность), «Телефон», «Email», «Пометки» («Основной»; «Получает рассылки» — email совпадает с email организации; «Нет ни телефона, ни email — связаться не получится»; «Этот email есть у контрагента …»), действия: карандаш «Изменить», «Ещё» → «Сделать основным», «Удалить». Удаление — с отменой: строка гаснет, тост «Контакт «…» удалён» с кнопкой «Отменить» 5 секунд, потом запрос `DELETE`.
- Значение, которое сервер не смог расшифровать, показывается «Не удалось прочитать — введите заново» с карандашом.
- В узком блоке таблица превращается в карточки.

![Окно «Новый контакт»](assets/supplier-card--contact-form.png)

Окно **«Новый контакт» / «Изменить контакт»**: «ФИО» * («Укажите ФИО»), «Должность» («Менеджер по тендерам»), «Телефон» (правила телефона, см. [suppliers.md](suppliers.md#ручное-добавление-контрагента)), «Email», флажок «Основной контакт» (первый контакт всегда основной; снять у основного нельзя — «Основной контакт всегда один: чтобы сменить его, отметьте основным другой контакт.»). Кнопки «Добавить»/«Сохранить». Ошибки сервера — по полям.

### «Пользователи»

![Вкладка «Пользователи»](assets/supplier-card--tab-users.png)

Учётные записи, которым открыт личный кабинет контрагента («Всего: N»). Колонки: «ФИО», «Email», «Учётная запись» («Активна» / «Деактивирована»), «Действия» — «Отвязать» (подтверждение «Отвязать «…» от этого контрагента? Учётная запись останется, но кабинет контрагента он больше не увидит.»). Кнопки:

- значок «Привязать существующего пользователя» → окно «Привязать пользователя»: «Пользователь» * (список со строкой email; не-контрагенты помечены «· сейчас не контрагент»; подсказка «Уже привязанные … не показаны. Привязка переводит пользователя в роль «контрагент».») → «Привязать» (`POST …/cabinet-users`);
- «Выдать вход» → окно «Выдать вход в кабинет»: «Email» * («Пароль сгенерируется и покажется один раз. Адрес должен быть свободен — одна учётная запись на email.») → «Выдать» (`POST …/cabinet-login`) → окно «Вход выдан» с полем «Пароль» («Показывается один раз — сохраните его сейчас.») и «Готово».

Пусто — «В личный кабинет этого контрагента пока никто не входит. Привяжите существующего пользователя или выдайте новый вход.».

### «Активность»

![Вкладка «Активность»: события контрагента](assets/supplier-card--tab-activity.png)

Лента «Активность контрагента» (`GET /suppliers/{id}/activity`, [описание](../04-api/endpoints-suppliers.md#get-supplierssupplier_idactivity)): переключатель «Только этот контрагент» (по умолчанию) / «Весь тендер» (все события тендеров, куда приглашён контрагент; пометка «Виден контрагенту» у того, что покажет его кабинет); фильтры «Все типы» (КП, Раунды, Сообщения, Тендер, Участники, Аккредитация — это и есть история статусов и решений по проверкам), «Все тендеры», период «Всё время / 7 дней / 30 дней», «Поиск по событиям» (на сервер после паузы ввода). События сгруппированы по дням, новые сверху, страницами по 30 («Показать ещё»). ## Чего на карточке нет

По коду в интерфейсе **отсутствуют** (есть только API): блок проверок по открытым реестрам (ЕГРЮЛ, СРО, арбитраж, банкротство, РНП — `GET/POST …/checks`), отдельная история решений по квалификации (`…/qualification-history`; решения видны событиями типа «Аккредитация» в ленте), выставление решения по квалификации («Одобрен / Одобрен с лимитом / Отклонён», `status`). См. [BL §3.7, §4.15](../02-business-logic/suppliers.md#37-решение-по-квалификации-status) и [открытые вопросы](../_oq/SCR-3.md).

## Данные и обновление

`GET /suppliers/{id}` (карточка с флагом `finance_masked`), справочник видов работ (общий кэш), `GET /portfolios` (список тендеров для окна приглашения); вкладки грузят свои данные сами при открытии. Карточка подписана на живой поток: событие «контрагент изменён» перечитывает карточку, ленту и участие, не сбрасывая черновики полей.

## Сложность

**XL** в целом: шапка с тремя осями проверки и правкой на месте — L; вкладки: Основное (ПДн, загрузка) — M, Финансы (таблица + график) — M, Документы — M, Опыт (таблицы по видам работ + форма) — M, Участие — S, Контакты (организация, представители, отмена удаления, нечитаемые значения) — L, Пользователи ЛК (привязка, выдача входа с паролем) — M, Активность (лента с фильтрами и курсором) — M; модальные окна — M.
