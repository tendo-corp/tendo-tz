# Карта сложности и рисков

Где в системе основная трудоёмкость и где риск ошибиться в оценке. Шкала:
**S** — простой CRUD или экран без особой логики; **M** — заметная логика, но типовая;
**L** — много точных правил, интеграций или состояний; **XL** — ядро продукта, без которого
он не имеет ценности: сложная предметная логика, большой объём экранов, высокий риск
регрессий. Часы и деньги не указаны намеренно — их определяет исполнитель.

Этапы и критерии приёмки — [work-breakdown.md](work-breakdown.md), стек —
[tech-stack.md](tech-stack.md).

## 1. Объём исходной реализации (для калибровки)

Цифры приведены, чтобы исполнитель мог сопоставить масштаб со своим опытом. Повторять
объём кода не требуется.

| Показатель | Значение |
|---|---|
| Доменов бэкенда | 18 + общее ядро (`platform`) + ИИ-библиотека |
| Строк Python в бэкенде (без тестов) | ≈ 71 тыс. |
| Автотестов бэкенда | ≈ 1 500 (≈ 36 тыс. строк), в т. ч. архитектурные, матрица доступа, ИИ с заглушкой |
| HTTP-операций / путей | 333 / 270 |
| Таблиц БД / SQL-миграций | 82 / 27 |
| Маршрутов фронтенда | 43 (+ экран «не найдено») |
| Строк TS/TSX фронтенда (без тестов и сгенерированного клиента) | ≈ 112 тыс., из них ≈ 20 тыс. — карточка тендера, ≈ 4,6 тыс. — мастер создания, ≈ 5,3 тыс. — форма КП поставщика |
| Строк CSS | ≈ 30 тыс. |
| Файлов тестов фронтенда | ≈ 175 (vitest + assert-скрипты чистых функций) |

Самый крупный по коду домен — тендеры: ≈ 20 тыс. строк бэкенда и столько же экранного кода
карточки. За ним идут поставщики, ИИ-слой, insights, распознавание ФКП и общее ядро
(по 5,5–6,3 тыс. строк каждый).

## 3. Главные риски оценки

| # | Риск | Почему опасен | Как снизить |
|---|---|---|---|
| R1 | **Распознавание Excel-смет** | Реальные сметы Заказчика отличаются от примеров: объединённые ячейки, многоуровневые разделы, итоговые строки, разные названия колонок и единиц. Недооценка здесь — главный источник перерасхода | Получить у Заказчика 20–30 реальных смет до оценки; заложить итерацию «распознали → поправили правила» ([fkp-import](../02-business-logic/fkp-import.md)) |
| R2 | **Формулы СТ и их согласованность** | Одни и те же числа (итоги, «заполнено», минимумы) показываются в СТ, форме поставщика, реестре, отчётах, выгрузках и ИИ-снимке. Расхождение между экранами сразу видно пользователю | Один расчётный модуль на сервере; эталонные примеры из [end-to-end-scenarios](../02-business-logic/end-to-end-scenarios.md) как автотесты |
| R3 | **Объём фронтенда** | Около 40 экранов, из них 3 очень крупных: карточка тендера, мастер создания, форма КП. Плотные таблицы с закреплением, выделением и виртуализацией | Дизайн-система и табличный компонент — до экранов; приёмка по скриншотам [03-screens](../03-screens/screen-map.md) |
| R4 | **ИИ** | Качество зависит от модели и провайдера; без проверки чисел возможны недостоверные выводы; данные уходят за периметр | Сначала детерминированная часть, затем ИИ поверх; заглушка шлюза в тестах; выбор контура ИИ — решение Заказчика ([ai-features](../06-ai/ai-features.md)) |
| R5 | **Права и границы доступа** | Ошибка выдаёт поставщику чужие цены или раскрывает ПДн. В исходной системе есть такие пробелы, их нельзя переносить ([users-and-roles](../01-product/users-and-roles.md)) | Тест матрицы доступа на каждую ручку; ревью безопасности до приёмки |
| R6 | **Realtime и фоновые задачи на PostgreSQL** | Один процесс-лидер очереди, `LISTEN/NOTIFY`, догон событий. Ошибки проявляются только под нагрузкой и при рестартах | Нагрузочный прогон и тест «рестарт посреди задания» ([scalability](../07-architecture/scalability.md)) |
| R7 | **Почта** | Статусы доставки, повторы, шаблоны, разные SMTP Заказчика | Тестовое письмо из настроек, перехватчик почты на стендах |
| R8 | **Неясные требования** | В [../99-open-questions.md](../99-open-questions.md) больше 200 вопросов. Часть из них меняет объём: мультиарендность, целевые нагрузки, СКЗИ, контур ИИ, интеграции с реестрами | Закрыть вопросы с пометкой «влияет на оценку» до фиксации цены |
| R10 | **Проверки по открытым реестрам** | В исходной системе ЕГРЮЛ и «Заполнить по ИНН» работают через неофициальный публичный веб-поиск ФНС (возможны CAPTCHA и смена формата), РНП — разбором HTML, а СРО, арбитраж и банкротства — только ссылками для ручной проверки. Блока проверок в интерфейсе нет | Решить с Заказчиком: официальный платный API-агрегатор, ручные ссылки или отказ ([suppliers](../02-business-logic/suppliers.md)); оценивать отдельно |
| R9 | **Перенос данных** | Если Заказчик захочет перенести данные из текущей системы, понадобится отдельная миграция, включая расшифровку и перешифровку ПДн | Отдельная оценка после решения ([tables](../05-data-model/tables.md)) |

## 4. Что можно упростить без потери ценности

- Биллинг ИИ, заявки с лендинга, SIEM, пересылку логов и демо-инструменты делать во
  второй очереди (флаги, см. [scope-and-mvp](../01-product/scope-and-mvp.md)).
- ИИ-сопоставление позиций не делать: в исходной системе оно выключено, точность не измерена.
- Отчёты начинать с выгрузок в Excel, графики добавлять потом.
- Пользовательские статусы и шаблоны тендеров можно перенести в Should, если сроки жёсткие.
