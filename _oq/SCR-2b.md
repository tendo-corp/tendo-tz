# Открытые вопросы SCR-2b (рабочее место тендерного специалиста: главная, реестр, мастер создания, входящие КП, карточка КП, шаблоны, стенд плотной матрицы)

## Главная (`home.md`)

- [03-screens/home] Ссылки «Все N» в блоке «Требуют внимания» и «Реестр тендеров» ведут в реестр без фильтра «Требует внимания» — пользователь видит весь список, а не те тендеры, о которых шла речь. Должна ли ссылка включать фильтр? — мелкая правка, но влияет на сценарий «разобрать то, что горит» — код рабочего стола и реестра, проверено на стенде.
- [03-screens/home] Очередь аккредитации для СБ и юриста на стенде пуста; снимок сделан с подменой ответа API, состояние после отправки приглашений не снималось. Нужны тестовые данные Заказчика или подтверждение, что очередь выглядит так же при реальных анкетах — влияет на приёмку экрана — стенд, код блока очереди.

## Реестр тендеров (`tenders-registry.md`)

- [03-screens/tenders-registry] Ошибка выгрузки реестра в Excel пользователю не показывается (в обработчике нет ветки ошибки — кнопка просто перестаёт крутиться). Какой текст показывать? — S, но без него пользователь не узнает об отказе — код кнопки выгрузки.
- [03-screens/tenders-registry] Кнопка «Выгрузить» показывается всем сотрудникам без проверки права `reports.view`; при отсутствии права отказ приходит только с сервера (и, см. выше, не показывается). Прятать кнопку по праву? — матрица прав и UX — код панели реестра.
- [03-screens/tenders-registry] Реестр загружает все тендеры одним списком (`GET /portfolios`), фильтрует и сортирует на клиенте, серверной пагинации нет; черновики во вкладке «Незавершённые» ограничены 20 последними. На каком объёме (сотни/тысячи тендеров) это должно работать и нужна ли серверная пагинация? — влияет на оценку (S → M для серверного поиска и пагинации) — код реестра и API портфелей.
- [03-screens/tenders-registry] При группировке строка-заголовок группы зажата шириной закреплённой колонки «№» (название группы обрезается) — видно на снимке `tenders-registry--grouped.png`. Дефект или так задумано? — мелкая правка вёрстки — стенд.
- [03-screens/tenders-registry] Подписи шагов в карточках вкладки «Незавершённые» («1 · Файл / 2 · Состав / 3 · Параметры / 4 · Контрагенты») не совпадают с полосой шагов мастера («Загрузка файла / Проверка структуры / Загрузка документов / Контрагенты и ссылки»). Какие подписи принять единственными? — согласованность UI — код вкладки и мастера.
- [03-screens/tenders-registry] Тултип значка «i» у колонок «Лучшая цена» и «Мин. неполного КП» снять не удалось (в автоматическом прогоне не проявился по наведению); поведение описано по коду. Нужна ли формулировка справки от Заказчика? — мелочь для приёмки — стенд, код заголовков колонок.

## Мастер создания тендера (`tender-create.md`)

- [03-screens/tender-create] Плашка «Файл разобран ИИ…» показывается всегда после разбора, даже когда файл разобран без ИИ (на стенде ИИ выключен), и при запуске из шаблона, где файла нет; там же карточка файла «Файл 0 КБ». Показывать плашку только при фактическом участии ИИ и скрывать карточку файла при запуске из шаблона? — честность интерфейса, S — код шагов 1–2, проверено на стенде.
- [03-screens/tender-create] Этапы разбора («Чтение листов…», «Определение шапки…», «Извлечение позиций…», «Распознавание доп. условий») переключаются по таймеру, а не по реальному ходу задания на сервере. Нужен ли настоящий прогресс от сервера? — влияет на объём фонового задания (+S) — код индикатора и ответ опроса задания.
- [03-screens/tender-create] Бизнес-логика называет итоговую кнопку шага 2 «Создать тендер», в интерфейсе она «Отправить». Какую подпись принять? — согласованность ТЗ — раздел бизнес-логики и код шага 2.
- [03-screens/tender-create] Поле «Объект» на шаге 2 по умолчанию заполняется первым объектом из доступных — риск создать тендер не на том объекте. Оставить или требовать явный выбор? — UX и качество данных — код формы шага 2.
- [03-screens/tender-create] Список недостающих полей, показанный после неудачной попытки отправки, не обновляется при исправлении полей (пропадает только при новой попытке). Должен ли он обновляться «на лету»? — UX, S — код шага 2.
- [03-screens/tender-create] В полосе шагов шаг 3 помечается «Документы приложены», даже если пользователь нажал «Пропустить». Нужна ли отдельная пометка «пропущено»? — мелочь, S — код полосы шагов.
- [03-screens/tender-create] Если черновик мастера не был создан (ошибка сохранения черновика), после создания тендера пользователь сразу попадает в карточку тендера — шаги 3–4 пропускаются. Так задумано? — сценарий «мастер всегда из четырёх шагов» — код отправки шага 2.
- [03-screens/tender-create] Работу ИИ (подсказки полей модели, резервный ИИ-разбор нестандартного файла, ИИ-подбор единиц измерения, ответ 402 при исчерпании токенов в реальном сценарии) снять не удалось — ИИ на стенде выключен; описано по коду, 402 снят с подменой ответа. Нужен ли стенд с включённым ИИ для приёмки? — влияет на приёмку разделов с ИИ — стенд, код мастера.

## Входящие КП и карточка КП (`quotes-inbox.md`, `quote-card.md`)

- [03-screens/quote-card] Кнопки решений в карточке КП («Принять КП», «Отклонить», «Запросить доработку», решения по корректировкам, смена ответственного и пользовательского статуса) не прячутся и не блокируются по правам пользователя — отказ приходит с сервера сообщением. Прятать по правам? — матрица прав и UX, S — код карточки КП.
- [03-screens/quote-card] Ссылка из карточки КП на тендер передаёт `?supplier={id}`, но экран тендера этот параметр не обрабатывает (открывается вкладка «Обзор» без выделения поставщика). Что должно открываться? — сценарий перехода, S — код карточки КП и карточки тендера.
- [03-screens/quote-card] В блоке «Другие КП» капсулы статуса переносятся по слогам в узкой колонке («Пода но»). Дефект вёрстки — подтвердить ширину колонки или сокращённые подписи — стенд.
- [03-screens/quote-card] Аватар автора в обсуждении КП для сотрудников зашит буквой «З» («Закупки»), а не инициалами автора. Так задумано (обезличенно от лица отдела) или показывать автора? — UX и требования к журналу — код обсуждения, стенд.

## Для координатора (публикация)

- [публикация] В данных стенда коды бюджетных позиций и часть сведений, похоже, не обезличены (латинские коды позиций бюджета; во вложенном Excel одного тендера — реквизиты реальной компании; во встроенном примере файла мастера — реальный адрес и кадастровый номер). В снимках SCR-2b коды заменены, вложенный Excel стенда и встроенный пример не использовались — нужно проверить снимки других авторов и решить, обезличивать ли данные стенда — риск публикации — данные стенда.
