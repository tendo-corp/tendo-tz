- [portfolios] Кнопки «Новый портфель», «Новый объект», пункты «Переименовать / Архивировать / На верхний уровень» показываются любому сотруднику с доступом к экрану; право `portfolios.manage` и грант на портфель проверяет только сервер (отказ — окном с текстом 403). Скрывать ли действия по правам? — объём работ по ролям и тест-кейсы — `PortfoliosPage.tsx` (проверок прав нет), `portfolios/transport`.
- [portfolios] Перенос объекта в интерфейсе — только «На верхний уровень»; API `PATCH /projects/{id}` принимает любого родителя в том же портфеле. Нужен ли выбор произвольного родителя (диалог с деревом)? — +S к экрану — `PortfoliosPage.tsx liftRow`.
- [portfolios] Длина названия портфеля/объекта на форме не ограничена (БД — 255 символов), длина адреса — тоже. Какие лимиты и тексты ошибок закладывать? — валидация форм — `EntityModal` в `PortfoliosPage.tsx`, `schema.hcl` (`portfolios.name varchar(255)`).
- [portfolios] Горячая клавиша ⌘N / Ctrl+N «Новый портфель»: в Chrome/Edge под Windows Ctrl+N зарезервирован браузером и до страницы не доходит. Оставить, заменить или убрать? — UX — `PortfoliosPage.tsx onKeyDown`.
- [portfolios] При ошибке загрузки дерева левая колонка показывает «Портфелей пока нет» (вводит в заблуждение), справа — «Портфели не загрузились». Считаем дефектом (в ТЗ — показывать ошибку в обеих колонках)? — снимок `portfolios--error.png`.
- [portfolios / object-card] Подсказка «Как устроена страница» упоминает кнопку «Открыть карточку объекта», которой на экране нет (объект открывается в правой колонке). На отдельную карточку `/portfolios/objects/:id` ведёт только ссылка «Объект» из журнала ИБ. Нужна ли отдельная карточка объекта в продукте, или достаточно режима объекта на `/portfolios`? — дублирующий экран (S) — `PortfoliosPage.tsx HINTS`, `ObjectCardPage.tsx`, `entities/security/api/security.api.ts`.
- [suppliers] Фильтр «Вид работ» в окне «Фильтры» допускает несколько значений, но в запрос уходит только первый выбранный (`work_type_id` — один id, сервер принимает один). Делать мультивыбор на сервере или ограничить выбор одним значением? — корректность фильтра — `SuppliersPage.tsx listFilters.workTypeId`, `GET /suppliers`.
- [suppliers] Массовых действий и выгрузки в реестре контрагентов нет (выгрузка — только отчётом «По контрагентам»). Требование «массовые действия» в постановке есть — нужны ли они (какие: смена пула, приглашение в тендер, удаление)? — объём (M) — `SuppliersPage.tsx`.
- [suppliers] Журнал выданных ссылок-приглашений на анкету (`GET /suppliers/invitations/list`) в интерфейсе не выводится; управлять ранее выданной ссылкой можно только в момент её создания. Нужен ли список ссылок с перевыпуском/обнулением? — +S — `SuppliersPage.tsx` (состояние `inviteActionId` осталось от удалённого журнала).
- [supplier-card] Плейсхолдер поля «Наименование организации — Заказчик» в окне опыта работ содержит название реального застройщика. Заменить на нейтральный пример («АО «Заказчик»») — так и сделано на снимке ТЗ — `entities/supplier/ui/SupplierWorkExperienceModal.tsx`.
- [supplier-card] СБ и юрист видят в карточке значок «Пригласить в тендер» и могут править ИНН/КПП, виды работ, теги, комментарий, контакты, выручку, штат, допуски, пользователей ЛК (интерфейс проверяет только «не контрагент»). Тендеров СБ/юристу не выдано — список в окне приглашения пуст. Ограничить по ролям? — тест-кейсы ролей — `SupplierDetailPage.tsx isStaff`.
- [supplier-card] Маска контактов (`suppliers.contacts.view`, настройка `CONTACTS_MASK_ENABLED`) применяется только в сравнительной таблице тендера, её выгрузке и протоколе; карточка и реестр контрагентов показывают ИНН, телефоны и почту полностью любому сотруднику. Должна ли маска действовать и в карточке? — требование ИБ, объём S — `backend app/platform/contact_mask.py` (используется только в `tenders/service/comparison*.py`).
- [supplier-card] Блок «Проверки по открытым реестрам» (`GET /suppliers/{id}/checks`, `POST …/checks/run`) и история решений по квалификации (`GET …/qualification-history`), а также решение по квалификации (`status`: одобрен / с лимитом / отклонён) в карточке не выводятся — есть только API. Выводить ли их в карточку (вкладка «Проверки» / «История решений»)? — M — `SupplierDetailPage.tsx`, BL suppliers §3.7, §4.15.
