# Открытые вопросы SCR-3 — справочники, контрагенты, бюджет, отчёты, ИБ, администрирование, владелец площадки

- [portfolios] Кнопки «Новый портфель», «Новый объект», пункты «Переименовать / Архивировать / На верхний уровень» показываются любому сотруднику с доступом к экрану; право `portfolios.manage` и грант на портфель проверяет только сервер (отказ — окном с текстом 403). Скрывать ли действия по правам? — объём работ по ролям и тест-кейсы — `PortfoliosPage.tsx` (проверок прав нет), `portfolios/transport`.
- [portfolios] Перенос объекта в интерфейсе — только «На верхний уровень»; API `PATCH /projects/{id}` принимает любого родителя в том же портфеле. Нужен ли выбор произвольного родителя (диалог с деревом)? — +S к экрану — `PortfoliosPage.tsx liftRow`.
- [portfolios] Длина названия портфеля/объекта на форме не ограничена (БД — 255 символов), длина адреса — тоже. Какие лимиты и тексты ошибок закладывать? — валидация форм — `EntityModal` в `PortfoliosPage.tsx`, `schema.hcl` (`portfolios.name varchar(255)`).
- [portfolios] Горячая клавиша ⌘N / Ctrl+N «Новый портфель»: в Chrome/Edge под Windows Ctrl+N зарезервирован браузером и до страницы не доходит. Оставить, заменить или убрать? — UX — `PortfoliosPage.tsx onKeyDown`.
- [portfolios] При ошибке загрузки дерева левая колонка показывает «Портфелей пока нет» (вводит в заблуждение), справа — «Портфели не загрузились». Считаем дефектом (в ТЗ — показывать ошибку в обеих колонках)? — снимок `portfolios--error.png`.
- [portfolios / object-card] Подсказка «Как устроена страница» упоминает кнопку «Открыть карточку объекта», которой на экране нет (объект открывается в правой колонке). На отдельную карточку `/portfolios/objects/:id` ведёт только ссылка «Объект» из журнала ИБ. Нужна ли отдельная карточка объекта в продукте, или достаточно режима объекта на `/portfolios`? — дублирующий экран (S) — `PortfoliosPage.tsx HINTS`, `ObjectCardPage.tsx`, `entities/security/api/security.api.ts`.
