# Открытые вопросы API-2 (контрагенты, тендеры, шаблоны, черновики)

- [04-api/suppliers] `DELETE /suppliers/{id}/hard` удаляет виды работ, контакты и документы анкеты, но не проверки по реестрам, связки ЛК, приглашения в тендеры, переписку и уведомления, ссылающиеся на контрагента без каскада, — такое удаление сейчас падает ошибкой сервера (500). Как должно быть: запрет с 409 «есть участие в тендерах» или полный каскад? — влияет на объём работ по корзине и целостность истории тендеров — код сервиса корзины и внешние ключи схемы БД.
- [04-api/suppliers] При удалении насовсем файлы документов анкеты остаются в хранилище (удаляются только строки вложений). Нужно ли чистить объекты хранилища? — объём хранения и требования 152-ФЗ к удалению ПДн — сервис корзины.
- [04-api/suppliers] `PUT /suppliers/{id}/revenues` (финансы, коммерческая тайна) не пишет событие в журнал ИБ, хотя просмотр финансов (`finance_viewed`) пишется. Нужен ли аудит правки выручки? — состав журнала ИБ — сервис выручки.
- [04-api/suppliers] `POST /suppliers/{id}/cabinet-login` при сгенерированном пароле возвращает его в ответе и не отправляет письмо контрагенту (в отличие от анкеты). Должна ли система слать письмо с доступом? — сценарий выдачи ЛК — сервис пользователей ЛК.
- [04-api/suppliers] `PATCH /suppliers/{id}` (реквизиты, виды работ, теги, комментарий) открыт любому сотруднику, включая СБ и юриста, тогда как опыт работ и дату аккредитации правят только тендерный специалист и администратор. Так задумано или нужна единая ролевая проверка правки карточки? — влияет на матрицу прав — транспорт и сервис карточки контрагента.
- [04-api/suppliers-registration] Повторный вызов `POST /suppliers/register/{id}/complete` снова пишет событие «анкета отправлена» и снова рассылает уведомления СБ/юристу/специалисту (у ручного `questionnaire/submit` повтор — без эффекта). Нужна ли идемпотентность? — лишние уведомления — сервис регистрации.
- [04-api/suppliers-registration] У многоразовой ссылки (`mode=multi`) приглашение помнит только последнего зарегистрировавшегося; файлы анкеты и финализация пускаются, только если `supplier_id` совпадает с последним. Если по одной ссылке параллельно регистрируются две организации, первая не сможет догрузить документы. Допустимо ли? — сценарий массовой регистрации — сервис регистрации.
- [04-api/suppliers-registration] `GET /suppliers/invitations/{token}/check` и `GET /suppliers/register/work-types` не закрыты лимитом частоты (в отличие от остальных публичных ручек анкеты). Нужен ли лимит? — защита от перебора токенов — транспорт контрагентов.
- [04-api/tenders] Ответы `POST /tenders`, `PATCH /tenders/{id}`, `PUT …/structure`, `PATCH/POST …/items` возвращают карточку с плановой суммой без учёта права «Цены» (маскирует только `GET /tenders/{id}`). Нужно ли маскировать и здесь? — утечка коммерческих данных пользователю с `tenders.manage` без права на финансы — сервис карточки тендера (`build_tender_detail` без флага права).
- [04-api/tenders] Решения по корректировкам (`…/review`, `…/review-batch`) и запрос доработки (`…/request-revision`) не проверяют статус тендера — их можно выполнить в завершённом/отменённом тендере (правило «заморозки» в бизнес-логике перечисляет только отклонение КП, а решение по объёму после закрытия меняет объём позиции и переоткрывает строки участникам). Нужна ли проверка? — целостность результата закрытого тендера — сервис КП.
- [04-api/tenders-templates] `POST /templates/from-tender/{tender_id}` не проверяет доступ сотрудника к объекту тендера — состав любого тендера можно скопировать в шаблон по id. Нужна ли проверка доступа? — разграничение по объектам — сервис шаблонов.
- [04-api/tenders-analysis] `GET /tenders/{id}/insights` (как и POST) сохраняет результат анализа и пишет журнал ИБ — изменяющий GET. Оставить ли GET-вариант? — предсказуемость API и кэширование прокси — транспорт insights.
- [04-api/tenders-invite] `POST /invite/{token}/files` и `POST /invite/{token}/ack-corrections` не закрыты лимитом частоты; загрузка файла к КП не проверяет статус тендера, подачу КП и значение `doc_type` (удаление файла после подачи при этом запрещено). Нужны ли лимиты и проверки? — защита публичных ручек, целостность поданного КП — транспорт и сервис формы по ссылке.
