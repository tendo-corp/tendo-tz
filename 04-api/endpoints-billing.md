# API: биллинг ИИ — кабинет клиента и раздел владельца площадки (billing, owner)

Ручки учёта расходов на ИИ во внутренней валюте — токенах: кабинет клиента «Расходы» (баланс, история, график списаний, заявки на пополнение) и раздел владельца площадки (клиенты и их условия, ручные начисления, исполнение заявок, курс и реквизиты, себестоимость против списанного, журнал обращений к нейросети). Общие соглашения — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/billing.md](../02-business-logic/billing.md); экраны — [../03-screens/expenses.md](../03-screens/expenses.md) (кабинет «Расходы»), [../03-screens/owner-costs.md](../03-screens/owner-costs.md), [../03-screens/owner-calls.md](../03-screens/owner-calls.md), [../03-screens/owner-clients.md](../03-screens/owner-clients.md), [../03-screens/owner-requests.md](../03-screens/owner-requests.md), [../03-screens/owner-settings.md](../03-screens/owner-settings.md); ИИ — [../06-ai/](../06-ai/).

## Модель и правила

- **Клиент** (`billing_clients`) — организация-пользователь установки. Сейчас установка = один клиент: он заводится на старте приложения по `CLIENT_CODE` (имя — `CLIENT_NAME` или код) и тогда же, один раз, получает приветственный бонус `BILLING_WELCOME_BONUS` токенов. Все ручки кабинета работают с текущим клиентом установки.
- **Токен** — внутренняя единица: **100 токенов = 1 ₽** и себестоимости при множителе 1×, и цены покупки. Сумма заявки к оплате = токены / 100 ₽.
- **Баланс** = сумма всех записей баланса клиента (`billing_entries.tokens`, со знаком).
- **Записи баланса** (`kind`): `welcome` «Приветственный бонус» (+), `topup` «Пополнение по заявке» (+), `manual` «Начисление» (+, от владельца), `correction` «Корректировка» (−, от владельца), `charge` «Списание» (−, за ИИ-операцию).
- **ИИ-операция** (`ai_operations`) — одно действие пользователя с ИИ (`purpose`): `file_recognition` «Распознавание файла», `tender_analysis` «ИИ-анализ тендера», `pair_analysis` «Разбор пары», `supplier_letter` «Письмо поставщику», `table_question` «Вопрос по таблице», `position_matching` «Сопоставление позиций». Обращение к нейросети вне операции — `system` «Системное»: себестоимость владельца без списания.
- **Списание** — одно на **успешную** операцию с хотя бы одним обращением: `⌈себестоимость_₽ × 100 × множитель⌉` токенов; повторно не списывается. Неуспешная операция не списывается.
- **Журнал обращений** (`ai_calls`) — каждое обращение к нейросети: модель, токены промпта/ответа, стоимость в $ и ₽ по курсу владельца на момент обращения, длительность, успех/ошибка, тендер/раунд/подрядчик, кто запустил. Текст промпта и ответа хранится только при `AI_PROMPT_LOG_ENABLED=true` и стирается через `AI_PROMPT_LOG_DAYS` (30) сут периодической задачей раз в 6 ч (числа остаются).
- **Блокировка при нуле** (флаг клиента): при включённом биллинге и балансе ≤ 0 запуск новой ИИ-операции отклоняется **402** `{"code": "tokens_exhausted", "message": "Баланс токенов исчерпан — обратитесь к администратору"}`.
- **Порог низкого баланса**: при пересечении порога вниз владельцу уходит одно уведомление «Баланс клиента «<имя>» ниже порога» («Баланс: N токенов, порог: M.»); подъём выше порога снимает пометку.
- **Уведомления владельцу** — в Telegram-чат биллинга (`BILLING_TELEGRAM_ENABLED`, `BILLING_TELEGRAM_CHAT_ID`), иначе письмом на `BILLING_OWNER_EMAIL`, иначе только запись в лог; сбой уведомления не отменяет действие.
- **Флаг `BILLING_ENABLED`** (по умолчанию выключен): без него кабинет клиента отвечает 404, ИИ не блокируется и не списывается. Раздел владельца работает независимо от флага.
- **Владелец площадки** — учётка с признаком суперадмина (заводится служебной командой на сервере, не через API), ходит только в `/auth/*` и `/owner*`; MFA для неё обязательна.

### GET /billing/summary

**Назначение.** Шапка кабинета «Расходы»: баланс клиента, предупреждение о низком балансе и о блокировке, реквизиты для оплаты.

**Доступ.** Право `billing.view` (по умолчанию — только администратор). При `BILLING_ENABLED=false` — 404 «Раздел недоступен» (проверяется раньше сессии).

**Параметры.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `balance` | integer | баланс, токены |
| `low_balance` | boolean | баланс ниже порога клиента |
| `blocked` | boolean | блокировка при нуле включена и баланс ≤ 0 |
| `payment_details` | string | реквизиты для оплаты (задаёт владелец) |

**Ошибки.** 404 «Раздел недоступен»; 401/403.

**Пример.** → `{"balance": 10000, "low_balance": false, "blocked": false, "payment_details": ""}`.

**Побочные эффекты.** Нет.

### GET /billing/history

**Назначение.** История движения баланса клиента — без рублей и множителя.

**Доступ.** `billing.view`; 404 при выключенном биллинге.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `limit` | integer | 50 | 1–200 |
| `offset` | integer | 0 | ≥ 0 |

**Ответ `200`:** `{"items": BillingEntry[] (без cost_rub/multiplier), "total": integer}`, новые сверху.

**Ошибки.** 404; 403; 422.

**Пример.** → `{"items": [{"id": 1, "kind": "welcome", "tokens": 10000, "comment": "Приветственный бонус", "author": "Система", "purpose": null, "tender_id": null, "launched_by": null, "created_at": "2026-10-02T12:28:25+00:00"}], "total": 1}`.

**Побочные эффекты.** Нет.

### GET /billing/spending

**Назначение.** График списаний: сумма списанных токенов по неделям или месяцам.

**Доступ.** `billing.view`; 404 при выключенном биллинге.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `period` | string | `week` | `week` \| `month` |
| `count` | integer | 12 | 1–52 — число корзин, последняя — текущая неделя (с понедельника) / текущий месяц |

**Ответ `200`:** `{"period": "week", "buckets": [{"start": "YYYY-MM-DD", "tokens": integer}]}` — корзины по возрастанию, `tokens` — сумма списаний положительным числом (0, если не было); границы — по UTC.

**Ошибки.** 400 «Период — неделя или месяц»; 404; 403; 422.

**Пример.** `GET /api/billing/spending?period=month&count=3` → `{"period": "month", "buckets": [{"start": "2026-08-01", "tokens": 0}, {"start": "2026-09-01", "tokens": 1250}, {"start": "2026-10-01", "tokens": 310}]}`.

**Побочные эффекты.** Нет.

### GET /billing/topup-requests

**Назначение.** Заявки клиента на пополнение, новые сверху.

**Доступ.** `billing.view`; 404 при выключенном биллинге.

**Параметры.** Нет (без пагинации).

**Ответ `200`:** массив `TopupRequest` (без `client_id`, `requested_by`).

**Ошибки.** 404; 403.

**Пример.** → `[{"id": 4, "tokens": 50000, "amount_rub": 500.0, "comment": "на квартал", "status": "new", "reject_reason": null, "created_at": "2026-10-10T09:00:00+00:00", "decided_at": null}]`.

**Побочные эффекты.** Нет.

### POST /billing/topup-requests

**Назначение.** Попросить владельца площадки пополнить баланс.

**Доступ.** `billing.view`; 404 при выключенном биллинге.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `tokens` | integer | да | > 0 (схема) и ≤ 100 000 000 |
| `comment` | string | нет | по умолчанию пусто; пробелы по краям обрезаются |

**Ответ `201`:** `TopupRequest` (статус `new`).

**Ошибки.** 400 «Укажите количество токенов больше нуля» (больше 100 000 000); 422 (≤ 0, не число); 404; 403.

**Пример.** `{"tokens": 50000, "comment": "на квартал"}` → `201 {"id": 4, "tokens": 50000, "amount_rub": 500.0, "status": "new", …}`.

**Побочные эффекты.** Уведомление владельцу «Заявка на пополнение от «<клиент>»»: «50000 токенов на 500 ₽. <ФИО>: на квартал».

### GET /owner/clients

**Назначение.** Клиенты установки с текущим балансом и условиями.

**Доступ.** Владелец площадки; иначе 403 «Раздел доступен только владельцу площадки».

**Параметры.** Нет.

**Ответ `200`:** массив `{id, code, name, balance, multiplier, block_at_zero, low_balance_threshold}` по id; `multiplier` — число (по умолчанию 1.0), порог — токены.

**Ошибки.** 401/403.

**Пример.** → `[{"id": 1, "code": "demo", "name": "demo", "balance": 10000, "multiplier": 1.0, "block_at_zero": false, "low_balance_threshold": 1000}]`.

**Побочные эффекты.** Нет.

### PATCH /owner/clients/{client_id}

**Назначение.** Изменить условия клиента: множитель списаний, блокировку при нуле, порог предупреждения.

**Доступ.** Владелец площадки.

**Параметры пути:** `client_id` — integer.

**Тело запроса** (только присланные непустые поля):

| Поле | Тип | Ограничения |
|---|---|---|
| `multiplier` | number | > 0 и ≤ 1000 |
| `block_at_zero` | boolean | |
| `low_balance_threshold` | integer | ≥ 0 |

**Ответ `200`:** объект клиента (как в списке) с актуальным балансом.

**Ошибки.** 404 «Клиент не найден»; 422 (диапазоны); 403.

**Пример.** `{"multiplier": 1.5, "block_at_zero": true}` → `{"id": 1, …, "multiplier": 1.5, "block_at_zero": true}`.

**Побочные эффекты.** Журнал ИБ `billing_client_updated` (изменённые поля). Проверка порога (возможное уведомление владельцу). Новый множитель действует на следующие списания.

### POST /owner/clients/{client_id}/entries

**Назначение.** Ручное начисление (`manual`) или корректировка (`correction`, списывается) от владельца. Комментарий обязателен.

**Доступ.** Владелец площадки.

**Параметры пути:** `client_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `kind` | string | да | `manual` \| `correction` |
| `tokens` | integer | да | > 0 — вводится положительным, корректировка пишется со знаком «−» |
| `comment` | string | да | непустой |

**Ответ `201`:** `{id, kind, tokens, comment, author: "Владелец площадки", purpose: null, tender_id: null, launched_by: null, created_at, cost_rub: null, multiplier: null}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | `kind` не из списка | «Неизвестный тип начисления» |
| 400 | пустой комментарий | «Комментарий обязателен» |
| 404 | клиента нет | «Клиент не найден» |
| 422 | `tokens` ≤ 0, нет полей | |

**Пример.** `{"kind": "correction", "tokens": 500, "comment": "Возврат за сбойный разбор"}` → `201 {"id": 13, "kind": "correction", "tokens": -500, …}`.

**Побочные эффекты.** Журнал ИБ `billing_entry_created` (клиент, вид, токены). Проверка порога.

### GET /owner/topup-requests

**Назначение.** Заявки на пополнение всех клиентов, новые сверху.

**Доступ.** Владелец площадки.

**Параметры запроса:** `status` — string, необязательный: `new` \| `fulfilled` \| `rejected` (точное совпадение).

**Ответ `200`:** массив `TopupRequest` с `client_id` и `requested_by` (ФИО подавшего).

**Ошибки.** 403.

**Пример.** `GET /api/owner/topup-requests?status=new` → `[{"id": 4, "tokens": 50000, "amount_rub": 500.0, "status": "new", "client_id": 1, "requested_by": "Админова Елена", …}]`.

**Побочные эффекты.** Нет.

### POST /owner/topup-requests/{request_id}/fulfill

**Назначение.** Исполнить заявку: начислить токены (запрошенное число или иное — тогда с комментарием).

**Доступ.** Владелец площадки.

**Параметры пути:** `request_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `tokens` | integer \| null | нет | > 0; по умолчанию — запрошенное |
| `comment` | string \| null | если `tokens` отличается от запрошенного | |

**Ответ `200`:** `TopupRequest` (владельческий вид) со статусом `fulfilled`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | заявки нет | «Заявка не найдена» |
| 409 | статус не `new` | «Заявка уже рассмотрена» |
| 400 | сумма изменена без комментария | «Сумма изменена — укажите комментарий» |
| 422 | `tokens` ≤ 0 | |

**Пример.** `{"tokens": 40000, "comment": "Оплачено частично"}` → `{"id": 4, "status": "fulfilled", "decided_at": "…", …}`.

**Побочные эффекты.** Запись баланса `topup` (+токены, ссылка на заявку), фиксация решения (кто, когда) под блокировкой строки заявки. Журнал ИБ `billing_topup_fulfilled` (`tokens`, `requested`). Проверка порога.

### POST /owner/topup-requests/{request_id}/reject

**Назначение.** Отклонить заявку с причиной.

**Доступ.** Владелец площадки.

**Параметры пути:** `request_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `reason` | string | да | непустая после обрезки |

**Ответ `200`:** `TopupRequest` со статусом `rejected` и `reject_reason`.

**Ошибки.** 400 «Укажите причину отклонения»; 404 «Заявка не найдена»; 409 «Заявка уже рассмотрена»; 422.

**Пример.** `{"reason": "Нет оплаты"}` → `{"id": 4, "status": "rejected", "reject_reason": "Нет оплаты", …}`.

**Побочные эффекты.** Журнал ИБ `billing_topup_rejected`. Клиенту уведомление не отправляется (статус виден в кабинете).

### GET /owner/settings

**Назначение.** Настройки владельца: курс доллара для пересчёта стоимости обращений, реквизиты для оплаты; флаги установки (только чтение).

**Доступ.** Владелец площадки.

**Параметры.** Нет.

**Ответ `200`:** `{"usd_rate": number, "payment_details": string, "billing_enabled": boolean, "prompt_log_enabled": boolean}` — последние два из окружения (`BILLING_ENABLED`, `AI_PROMPT_LOG_ENABLED`).

**Ошибки.** 403.

**Пример.** → `{"usd_rate": 100.0, "payment_details": "", "billing_enabled": true, "prompt_log_enabled": false}`.

**Побочные эффекты.** Строка настроек создаётся при первом обращении, если её нет.

### PUT /owner/settings

**Назначение.** Сохранить курс доллара и реквизиты. Курс действует на новые обращения — у каждого записанного обращения остаётся свой курс.

**Доступ.** Владелец площадки.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `usd_rate` | number | да | > 0 и ≤ 10 000 |
| `payment_details` | string | нет | пробелы по краям обрезаются; по умолчанию пусто |

**Ответ `200`:** как у GET.

**Ошибки.** 422 (курс вне диапазона); 403.

**Пример.** `{"usd_rate": 95.5, "payment_details": "Р/с … в банке …"}` → `{"usd_rate": 95.5, …}`.

**Побочные эффекты.** Журнал ИБ `billing_owner_settings_updated` (`usd_rate`).

### GET /owner/costs

**Назначение.** Экономика ИИ за период: себестоимость обращений против списанного у клиента, с разбивкой.

**Доступ.** Владелец площадки.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `date_from` | date `YYYY-MM-DD` | сегодня − 30 дней | начало периода (UTC, включительно) |
| `date_to` | date | сегодня | конец периода (включительно) |
| `group_by` | string | `purpose` | `purpose` (вид операции) \| `tender` (id тендера) \| `client` (id клиента) |

**Ответ `200`:** `{"total": {...}, "rows": [...]}`; строки по ключу, ключ строкой (`""` — без ключа, например обращение вне тендера); суммы в ₽ округлены до копеек:

| Поле | Смысл |
|---|---|
| `key` | значение группировки; у итога — `total` |
| `cost_rub` | себестоимость всех обращений периода |
| `charged_tokens` | списано токенов (записи `charge` периода) |
| `charged_rub` | списано в ₽ (`charged_tokens / 100`) |
| `charged_cost_rub` | себестоимость списанных операций |
| `uncharged_rub` | не списано: `cost_rub − charged_cost_rub` (неуспешные, системные обращения) |
| `margin_rub` | маржа: `charged_rub − charged_cost_rub` |

**Ошибки.** 400 «Неизвестная группировка»; 422 (формат даты); 403.

**Пример.** → `{"total": {"key": "total", "cost_rub": 0.75, "charged_rub": 0.76, "charged_cost_rub": 0.75, "uncharged_rub": 0.0, "margin_rub": 0.01, "charged_tokens": 76}, "rows": [{"key": "tender_analysis", "cost_rub": 0.75, "charged_tokens": 76, "charged_rub": 0.76, "charged_cost_rub": 0.75, "uncharged_rub": 0.0, "margin_rub": 0.01}]}`.

**Побочные эффекты.** Нет.

### GET /owner/calls

**Назначение.** Журнал обращений к нейросети для разбора стоимости и сбоев.

**Доступ.** Владелец площадки.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `date_from`, `date_to` | date | последние 30 дней | как у `/owner/costs` |
| `purpose` | string | — | вид операции или `system` |
| `operation_id` | integer | — | обращения одной операции |
| `limit` | integer | 50 | 1–200 |
| `offset` | integer | 0 | ≥ 0 |

**Ответ `200`:** `{"items": [...], "total": integer}`, новые сверху:

| Поле | Тип | Смысл |
|---|---|---|
| `id`, `created_at` | integer, string | |
| `purpose` | string | вид операции или `system` |
| `operation_id` / `operation_status` | integer \| null / string \| null | операция и её статус: `running` \| `succeeded` \| `failed` |
| `kind` | string | тип вызова: `chat` (генерация) \| `embed` (эмбеддинги) |
| `model` | string | модель |
| `prompt_tokens`, `output_tokens` | integer \| null | |
| `cost_usd`, `usd_rate`, `cost_rub` | number \| null | стоимость, курс на момент обращения, стоимость в ₽ |
| `ok` / `error` | boolean / string \| null | успех; класс ошибки |
| `tender_id`, `round_no`, `supplier_code` | | контекст |
| `user` | string \| null | ФИО запустившего |
| `prompt_text`, `response_text` | string \| null | только при включённом журнале текстов и в пределах срока хранения |

**Ошибки.** 403; 422.

**Пример.** → `{"items": [{"id": 5, "created_at": "2026-10-02T16:47:05+00:00", "purpose": "tender_analysis", "operation_id": 2, "operation_status": "failed", "kind": "chat", "model": "…", "prompt_tokens": null, "output_tokens": null, "cost_usd": null, "usd_rate": 100.0, "cost_rub": null, "ok": false, "error": "ConnectError", "tender_id": 108, "supplier_code": null, "round_no": 1, "user": "…", "prompt_text": null, "response_text": null}], "total": 6}`.

**Побочные эффекты.** Нет. Тексты промптов содержат данные КП — доступ к ним только у владельца.
