# API: служебные проверки здоровья (без тега)

Три ручки проверки состояния для балансировщика, PaaS и мониторинга: жив ли процесс, отвечает ли хранилище файлов, доходит ли запрос до нейросети. Ручки не входят ни в один тег OpenAPI. Общие соглашения — в [overview.md](overview.md).

Связанные разделы: окружения и выкатка — [../08-deploy/environments.md](../08-deploy/environments.md) (проверка готовности после выкатки); архитектура — [../07-architecture/architecture.md](../07-architecture/architecture.md); хранилище — [endpoints-files.md](endpoints-files.md); ИИ — [../06-ai/](../06-ai/).

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/health` | Процесс жив | публично |
| GET | `/health/storage` | Хранилище файлов: доступность, занятость, счётчики | публично |
| GET | `/health/llm` | Путь до ИИ-шлюза: доступность, модель, пробный вызов | публично |

Сложность блока: **S**.

**Общее.** Ручки без аутентификации и без лимитов частоты; ответ всегда `200` (состояние — в теле, поле `ok`), кроме падения самого процесса. После выкатки демо-стенда конвейер ждёт `running:healthy` контейнера и успешный ответ `/health` ([../08-deploy/](../08-deploy/)). Наружу отдаются режим хранилища, базовый адрес ИИ-шлюза и имя модели — без ключей и внутренних адресов хранилища (см. открытые вопросы о публичности).

---

### GET /health

**Назначение.** Проверка живости процесса (liveness): приложение запущено и обрабатывает запросы. БД и внешние сервисы не проверяются.

**Доступ.** Публично.

**Параметры.** Нет.

**Ответ `200`:** `{"status": "ok"}`.

**Ошибки.** Нет (недоступный процесс не ответит вовсе; 504 — если обработчик завис дольше тайм-аута запроса).

**Пример.** `GET /api/health` → `{"status": "ok"}`.

**Побочные эффекты.** Нет.

---

### GET /health/storage

**Назначение.** Состояние хранилища файлов: отвечает ли оно, сколько занято вложениями, счётчики загрузок этого процесса. Проба — запрос размера несуществующего служебного ключа: проверяет сеть и ключи доступа (чужой ключ даёт 403, а не 404), ничего не записывая.

**Доступ.** Публично.

**Параметры.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `ok` | boolean | проба прошла |
| `error` | string \| null | класс ошибки пробы (например, `ClientError`, `EndpointConnectionError`) |
| `storage_backend` | string | `local` \| `s3` |
| `direct_upload` | boolean | доступна прямая загрузка в бакет |
| `storage_used_bytes` | integer | сумма размеров всех вложений по БД |
| `counters` | object | счётчики хранилища этого процесса с момента старта: ключ вида `storage_uploads_total{status="ok"}` (статусы `ok`, `virus`, `signature`, `size_mismatch`, `storage_error`) → число; пусто, если событий не было |

**Ошибки.** Нет (сбой пробы — `ok: false`). Недоступность БД при подсчёте занятости — 500.

**Пример.** `GET /api/health/storage` → `{"ok": true, "error": null, "storage_backend": "s3", "direct_upload": true, "storage_used_bytes": 8366854, "counters": {}}`.

**Побочные эффекты.** Нет записи в хранилище.

---

### GET /health/llm

**Назначение.** Проверка пути «бэкенд → ИИ-шлюз» стандартными методами OpenAI-совместимого API: шлюз отвечает, нужная модель есть в списке, пробный вызов генерации (1 токен) проходит — это проверяет и ключ. Используется при настройке стенда и диагностике деградации ИИ.

**Доступ.** Публично.

**Параметры.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `ai_enabled` | boolean | общий выключатель ИИ (`AI_ENABLED`) |
| `base_url` | string | базовый адрес шлюза (`AI_BASE_URL`) |
| `model` | string | модель роли `mechanical` (из `AI_MODELS`) |
| `proxy` | string \| null | задан ли HTTP-прокси для шлюза (значение `AI_HTTP_PROXY`) |
| `reachable` | boolean | `GET /models` у шлюза ответил успешно |
| `model_present` | boolean | модель есть в списке |
| `generate_ok` | boolean | пробный `POST /chat/completions` (`max_tokens: 1`) вернул ответ |
| `ok` | boolean | `ai_enabled AND reachable AND model_present` (`generate_ok` — отдельно) |

Без ключа `AI_API_KEY` обращений к шлюзу нет — все проверки `false`. Тайм-аут обращений к шлюзу — 30 с; любая ошибка даёт `false` в соответствующем поле без исключения.

**Ошибки.** Нет.

**Пример.** `GET /api/health/llm` (ИИ выключен) → `{"ai_enabled": false, "base_url": "https://<ии-шлюз>/api/v1", "model": "<модель>", "proxy": null, "reachable": false, "model_present": false, "generate_ok": false, "ok": false}`.

**Побочные эффекты.** При заданном ключе — платный пробный вызов модели на 1 токен у провайдера. В журнал обращений биллинга он не попадает (вызов идёт мимо учёта обращений) — см. открытые вопросы.
