# API: центр уведомлений и живой поток топбара (notifications)

Ручки колокольчика и страницы «Уведомления»: лента с условным GET, счётчик, отметка прочтения и живой поток SSE `/notifications/stream`, который одним соединением несёт состояние топбара — колокольчик, бейдж чатов, тонкие события чата и сигналы о смене статуса контрагента. Шина событий, ключи адресации, каталог событий и источники уведомлений — в [overview.md §16](overview.md#16-живой-поток-событий-sse); протокол синхронизации чата — в [endpoints-chat.md](endpoints-chat.md).

Связанные разделы: бизнес-логика — [../02-business-logic/notifications.md](../02-business-logic/notifications.md); экраны — [../03-screens/notifications.md](../03-screens/notifications.md) (страница и колокольчик в топбаре), [../03-screens/profile.md](../03-screens/profile.md) (галочки email — `GET/PUT /auth/me/notification-prefs` в [endpoints-identity.md](endpoints-identity.md#get-authmenotification-prefs)).

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/notifications` | Лента уведомлений зрителя (ETag, 304) | вошедший |
| GET | `/notifications/unread-count` | Только счётчик непрочитанных (устарела) | вошедший |
| GET | `/notifications/stream` | SSE-поток состояния топбара | вошедший |
| POST | `/notifications/{notification_id}/read` | Отметить одно уведомление прочитанным | адресат |
| POST | `/notifications/read-all` | Отметить прочитанным всё адресованное зрителю | вошедший |

Сложность блока: **M** — лента и прочтение (S), поток SSE со снимками и шиной `LISTEN/NOTIFY` (M; шина — общая для чата).

## Модель и адресация

- Уведомление — строка `app_notifications`: `audience` (`staff` | `supplier`), `user_id` (персональное) и/или `supplier_id` (вся организация контрагента), `kind`, `title` (≤ 500), `body`, `href` (относительная ссылка внутри приложения, ≤ 500), `is_read`, `created_at`.
- **Кому видно:**
  - сотруднику — `audience = staff` и (`user_id` пуст — широковещательное, **или** `user_id` = он);
  - пользователю контрагента — `audience = supplier` и (`supplier_id` = его организация **или** `user_id` = он); без действующей связки с контрагентом — ничего.
- **Прочитанность хранится на строке**, а не на паре «строка × зритель»: широковещательное staff-уведомление, прочитанное одним сотрудником, гаснет у всех; уведомление организации контрагента — у всех её пользователей.
- Виды (`kind`): `quote` (КП), `revision` (доработка, раунды, корректировки, версии ФКП), `tender` (тендер, анкеты, проверки), `message` (чат), `comment` (комментарии), `security` (инциденты ИБ), `system` (по умолчанию). Полный список событий — [overview.md §16.5](overview.md#165-источники-уведомлений-порождают-type-notification).
- Производные поля в ответе: `tender_id` — из `href` вида `/tenders/<id>…` или `?tender_id=<id>`; `supplier_id` — из поля строки или из `href` (`?supplier_id=<id>`).

### Объект `Notification`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | integer | |
| `audience` | string | `staff` \| `supplier` |
| `kind` | string | вид |
| `title`, `body` | string | заголовок и текст (`body` — пустая строка, если нет) |
| `href` | string \| null | куда ведёт клик: `/tenders/100`, `/chats?tender_id=100&supplier_id=201`, `/suppliers/201`, `/security-log`, `/cabinet?tab=tenders`, `/fill/<токен>` |
| `read` | boolean | прочитано |
| `created_at` | string | ISO 8601 |
| `supplier_id` | integer \| null | контрагент (строки или из ссылки) |
| `user_id` | integer \| null | персональный адресат |
| `tender_id` | integer \| null | тендер из ссылки |

### GET /notifications

**Назначение.** Лента уведомлений зрителя, новые сверху, постранично; колокольчик берёт 8 строк, страница «Все» — больше. Поддерживает условный GET: при неизменном состоянии — 304 без тела.

**Доступ.** Вошедший (сотрудник или пользователь контрагента; видит только адресованное ему).

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `limit` | integer | — (до 200) | 1–200 |
| `offset` | integer | 0 | ≥ 0 |

**Заголовки запроса:** `If-None-Match` — значение `ETag` предыдущего ответа.

**Ответ `200`:** `{items: Notification[], total, limit, offset, unread}`; `unread` — непрочитанные **по всей ленте**, а не по странице. Заголовок `ETag: W/"<id последнего>-<непрочитанных>"` (меняется, когда пришло новое или изменилось число непрочитанных).

**Ответ `304`:** без тела, с тем же `ETag`, если `If-None-Match` совпал.

Пользователю контрагента без связки с организацией — `{"items": [], "total": 0, "limit": …, "offset": 0, "unread": 0}` без `ETag`.

**Ошибки.** 401/403; 422 (`limit` вне диапазона).

**Пример.** `GET /api/notifications?limit=1` →

```json
{"items": [{"id": 1583, "audience": "staff", "kind": "quote", "title": "Новое КП от поставщика",
  "body": "ООО «Гамма Системы» подал КП по «Витражи — дворовой фасад».", "href": "/tenders/100", "read": false,
  "created_at": "2026-09-25T07:20:00+00:00", "supplier_id": 203, "user_id": 2, "tender_id": 100}],
 "total": 27, "limit": 1, "offset": 0, "unread": 9}
```

Повтор с `If-None-Match: W/"1586-9"` → `304`.

**Побочные эффекты.** Нет.

### GET /notifications/unread-count

**Назначение.** Только счётчик непрочитанных (`COUNT(*)` по всей ленте). **Устаревшая**: счётчик приходит в каждом кадре потока; ручка оставлена для кабинета контрагента и запасного пути фронта при недоступном потоке.

**Доступ.** Вошедший.

**Параметры.** Нет.

**Ответ `200`:** `{"count": integer}`; заголовок `Deprecation: true`.

**Ошибки.** 401/403.

**Пример.** → `{"count": 9}`.

**Побочные эффекты.** Нет.

### GET /notifications/stream

**Назначение.** Живой поток состояния топбара вместо опроса по таймеру: простаивающая вкладка не делает запросов к БД, событие доезжает за доли секунды. **Каждый кадр — полный снимок** колокольчика и бейджа чатов; события шины служат только поводом пересчитать состояние по БД (прочитанное в соседней вкладке не приедет «новым»).

**Доступ.** Вошедший (cookie проверяется при подключении; открытое соединение живёт и после истечения JWT). Набор ключей подписки фиксируется при подключении (см. [overview.md §16.3](overview.md#163-шина-событий)).

**Параметры.** Нет.

**Ответ `200`:** `text/event-stream; charset=utf-8`, заголовки `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`; не сжимается gzip.

Последовательность кадров:

1. `retry: 3000` — переподключаться через 3 с;
2. первый снимок сразу после подписки;
3. далее — снимок на каждую пачку событий шины (все накопившиеся события забираются разом, кадр один);
4. при 15 с без событий — комментарий `: ping`.

Кадр снимка: `id: <last_id>` (если есть уведомления) и `data: <JSON>`:

| Поле | Тип | Смысл |
|---|---|---|
| `type` | string | всегда `snapshot` |
| `unread` | integer | непрочитанных уведомлений |
| `items` | `Notification[]` | 8 последних уведомлений |
| `last_id` | integer | id последнего уведомления (0 — нет) |
| `chats_unread` | integer | непрочитанных реплик чата по видимым тредам |
| `chats_cursor` | integer | глобальный курсор событий чата; больше известного клиенту — дотянуть `GET /chats/updates?since=` |
| `events` | object[] | тонкие события чата этой пачки: `{type: "chat", kind: msg\|read\|typing, thread_id, tender_id, seq, cursor?, side, name?}` (в первом кадре поля нет) |
| `supplier_events` | integer[] | id контрагентов, у которых сменился статус проверки или дата аккредитации — перечитать карточку, если открыта (в первом кадре поля нет) |

Что пересчитывается по событию:

| Событие шины | Колокольчик | Бейдж чатов |
|---|---|---|
| `notification` | пересчитать | без изменений |
| `chat` / `msg` другой стороны, `read` своей стороны | без изменений | пересчитать |
| `chat` / своя `msg`, чужое `read`, `typing` | без изменений | только `chats_cursor = max(текущий, cursor события)` |
| `supplier` | без изменений | без изменений (id — в `supplier_events`) |
| `resync` | пересчитать | пересчитать |

Соединение с БД возвращается в пул после каждого пересчёта (поток живёт часами). Ошибка внутри потока закрывает его без технического оповещения; клиент переподключается.

**Ошибки.** До начала потока — 401/403 по [overview.md §2.2](overview.md#22-jwt-доступа).

**Пример.**

```text
retry: 3000

id: 1586
data: {"type": "snapshot", "unread": 9, "items": [{"id": 1586, "audience": "staff", "kind": "quote", …}], "last_id": 1586, "chats_unread": 8, "chats_cursor": 71}

: ping

id: 1587
data: {"type": "snapshot", "unread": 10, "items": [...], "last_id": 1587, "chats_unread": 9, "chats_cursor": 72, "events": [{"type": "chat", "kind": "msg", "thread_id": 64, "tender_id": 100, "seq": 72, "cursor": 72, "side": "supplier"}], "supplier_events": []}
```

**Побочные эффекты.** Нет (только чтение). Клиент держит один поток на браузер (лидер среди вкладок), переподключение — 3 с, при неудачах до 30 с; при первой неудаче — разовый `GET /notifications?limit=8`.

### POST /notifications/{notification_id}/read

**Назначение.** Отметить одно уведомление прочитанным (клик по строке колокольчика).

**Доступ.** Адресат: сотруднику — staff-уведомление, широковещательное или своё персональное; пользователю контрагента — supplier-уведомление своей организации или своё персональное.

**Параметры пути:** `notification_id` — integer.

**Тело.** Нет.

**Ответ `200`:** `{"ok": true, "item": Notification}` (с `read: true`). Повторная отметка допустима.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | уведомления нет | «Уведомление не найдено» |
| 403 | не адресовано зрителю (чужая аудитория, чужая организация, чужое персональное) | «Нет доступа» |
| 401/403 | сессия, `Origin` | |

**Пример.** `POST /api/notifications/1583/read` → `{"ok": true, "item": {"id": 1583, …, "read": true}}`.

**Побочные эффекты.** Событие шины `notification` для других вкладок: сотруднику — на `staff:<id>` (или на `staff`, если уведомление широковещательное — оно гаснет у всех); контрагенту — на ключи его организации и личный.

---

### POST /notifications/read-all

**Назначение.** Отметить прочитанным всё адресованное зрителю — всю ленту одним обновлением, а не только загруженную страницу.

**Доступ.** Вошедший.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:** `{"ok": true, "marked": integer}` — сколько строк изменилось (0 — уже всё прочитано или ничего не адресовано).

**Ошибки.** 401/403.

**Пример.** → `{"ok": true, "marked": 9}`.

**Побочные эффекты.** Если что-то изменилось — событие шины `notification`: сотруднику на `staff` (могли погаснуть общие уведомления у всех сотрудников), контрагенту — на ключи организации и личный.
