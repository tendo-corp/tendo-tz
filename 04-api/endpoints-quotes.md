# API: коммерческие предложения (quotes)

Ручки раздела «Входящие КП» и карточки КП для сотрудника: реестр входящих по всем доступным тендерам с фильтрами и бейджем «новых», карточка КП (позиции, условия, версии с диффом, цена в контексте), пользовательский статус-пометка, отклонение КП целиком, снятие флага «новое», ИИ-сопоставление строк КП, поданных как новые позиции, с позициями ведомости. Решения по корректировкам, версии КП и запрос доработки под `/tenders/{id}/…` относятся к тегу `tenders` (файл API-2). Общие соглашения — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/tenders-quotes.md](../02-business-logic/tenders-quotes.md); экраны — [../03-screens/quotes-inbox.md](../03-screens/quotes-inbox.md), [../03-screens/quote-card.md](../03-screens/quote-card.md); ИИ-пайплайн сопоставления — [../06-ai/](../06-ai/).

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/quotes` | Входящие КП: реестр с фильтрами, `total`, `new_count` | право `quotes.manage` |
| GET | `/quotes/new-count` | Счётчик новых КП для бейджа | `quotes.manage` |
| GET | `/quotes/{quote_id}` | Карточка КП (любая версия) | `quotes.manage` + доступ к объекту тендера |
| PATCH | `/quotes/{quote_id}/custom-status` | Поставить/снять пользовательский статус КП | то же |
| POST | `/quotes/{quote_id}/reject` | Отклонить КП целиком с причиной | то же |
| POST | `/quotes/{quote_id}/mark-viewed` | Снять флаг «новое» | то же |
| GET | `/quotes/{quote_id}/matching` | ИИ: предложить пары «строка КП → позиция ведомости» | то же |
| POST | `/quotes/{quote_id}/matching/apply` | Применить подтверждённые пары | то же |

**Доступ — общее.** Право `quotes.manage` (по умолчанию — тендерный специалист и администратор). Отказ — `403` «Недостаточно прав для этого действия — обратитесь к администратору системы» + `permission_denied` в журнале ИБ. Для ручек с `{quote_id}` дополнительно:

| Код | Когда | `detail` |
|---|---|---|
| 403 | роль — поставщик | «Доступно только сотрудникам компании» |
| 404 | КП нет | «КП не найдено» |
| 404 | нет приглашения/тендера КП | «Приглашение не найдено» / «Тендер не найден» |
| 403 | объект тендера не входит в доступные пользователю | «Нет доступа к проекту этого тендера» |

Сложность блока: **M** (карточка КП — L вместе с экраном).

### Статусы КП

| Код | Смысл |
|---|---|
| `draft` | черновик подачи (контрагент заполняет форму) |
| `submitted` | подано |
| `revision_requested` | возвращено на доработку |
| `accepted` | принято |
| `withdrawn` | отозвано |
| `rejected` | отклонено специалистом |

«Новое» КП: статус `submitted` и (специалист ещё не открывал его **или** текущая версия подана позже последнего просмотра).

### GET /quotes

**Назначение.** «Почтовый ящик» входящих КП по всем тендерам доступных объектов: по строке на КП (текущая версия), свежие подачи сверху.

**Доступ.** `quotes.manage`; срез — объекты, доступные пользователю (администратор — все).

**Параметры запроса:**

| Параметр | Тип | Смысл / ограничения |
|---|---|---|
| `custom_status_code` | string | фильтр по пользовательскому статусу; `none` — только КП без статуса |
| `project_id` | integer | объект тендера |
| `work_type_id` | integer | вид работ тендера (тендер может иметь несколько видов работ) |
| `responsible_user_id` | integer | ответственный за тендер |
| `date_from` / `date_to` | string `ГГГГ-ММ-ДД` | день подачи текущей версии, включительно |
| `limit` | integer | 1–500; **без него — весь срез** (экран реестра читает срез целиком) |
| `offset` | integer | ≥ 0 |

Сортировка: время подачи текущей версии по убыванию (без подачи — в конце), затем id.

**Ответ `200`:** `{"items": [...], "new_count": integer, "total": integer}` — `total` и `new_count` считаются по тому же срезу фильтров, независимо от страницы. Элемент:

| Поле | Тип | Смысл |
|---|---|---|
| `id` / `display_id` | integer / string | id и `Q-<id>` |
| `tender_id`, `tender_number`, `tender_title` | | тендер |
| `supplier_id`, `supplier`, `inn` | | контрагент (юр. название, ИНН) |
| `project_id`, `project_name` | | объект |
| `work_type_ids` / `work_type` | integer[] / string | виды работ (названия через запятую) |
| `responsible_user_id` / `responsible` | integer \| null / string | ответственный |
| `file_names` / `has_attachments` | string[] / boolean | файлы, приложенные контрагентом к форме (лежат на приглашении) |
| `status` | string | статус КП |
| `amount` | number | итог текущей версии (0, если позиций нет) |
| `current_version` / `versions_total` | integer | номер текущей версии / сколько версий |
| `submitted_at` | string \| null | ISO UTC подачи текущей версии (`null` у черновика) |
| `custom_status_code` | string \| null | пользовательский статус |
| `is_new` | boolean | «новое» (см. выше) |
| `has_pending_new_position` | boolean | есть предложенная новая позиция без решения |
| `has_declined_items` | boolean | есть позиции с отказом контрагента |

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | дата не в формате | «date_from: ожидается дата ГГГГ-ММ-ДД» (или `date_to`) |
| 401 / 403 | см. общее | |
| 422 | `limit` вне 1–500 | |

**Пример.**

```json
{"items": [{"id": 114, "display_id": "Q-114", "tender_id": 100, "tender_number": "T-2026-100",
  "tender_title": "Витражи, дворовой фасад", "supplier_id": 203, "supplier": "ООО «Гамма Системы»",
  "inn": "7700000000", "project_id": 24, "project_name": "МКД-1", "work_type_ids": [17],
  "work_type": "Витражи и оконные блоки", "responsible_user_id": 2, "responsible": "Петров Пётр Петрович",
  "file_names": [], "has_attachments": false, "status": "submitted", "amount": 321568972.22,
  "current_version": 2, "versions_total": 2, "submitted_at": "2026-09-25T07:20:00Z",
  "custom_status_code": "clarification", "is_new": false, "has_pending_new_position": false,
  "has_declined_items": false}],
 "new_count": 3, "total": 12}
```

**Побочные эффекты.** Нет.

### GET /quotes/new-count

**Назначение.** Лёгкий счётчик новых КП для бейджа в боковом меню (без сборки реестра).

**Доступ.** `quotes.manage`; по доступным объектам.

**Параметры.** Нет.

**Ответ `200`:** `{"count": integer}` — то же число, что `new_count` реестра без фильтров.

**Ошибки.** 401 / 403.

**Пример.** → `{"count": 3}`

**Побочные эффекты.** Нет.

### GET /quotes/{quote_id}

**Назначение.** Карточка КП: шапка (тендер, контрагент), другие КП тендера с навигацией «предыдущее/следующее», другие КП контрагента, цена в контексте, версии с диффом, позиции ведомости с ценами выбранной версии, новые позиции, условия, итоги, бейдж версии ФКП.

**Доступ.** См. общее.

**Параметры:**

| Параметр | Где | Тип | Смысл |
|---|---|---|---|
| `quote_id` | путь | integer | КП |
| `version` | запрос | integer | номер версии; по умолчанию текущая |

**Ответ `200`:** `{"item": {...}}`:

| Поле | Тип | Смысл |
|---|---|---|
| `id`, `display_id`, `status`, `custom_status_code` | | реквизиты КП |
| `revision_comment` | string \| null | последний запрос доработки |
| `tender` | object | `{id, number, title, project_id, status, winner_supplier_id, responsible: {id, name} \| null}` |
| `supplier` | object | `{id, name, inn, kpp, ogrn, accreditation: {status, label, accredited}, pool: {code, label}, contact: {full_name, job_title, phone, email} \| null}`; блок `finance: {status, label, limit_amount}` — **только** при праве видеть финансы |
| `tender_quotes` | object | поданные КП тендера в порядке «Обзора» (полные — от дешёвого, затем неполные по имени): `items[{id, supplier_id, supplier_name, status, custom_status_code, version_number, submitted_at, amount, complete, missing_count, deviation_pct (к лучшей полной цене, %), is_best}]`, `total`, `best_amount`, `prev_id`, `next_id` |
| `supplier_quotes` | array | до 10 других поданных КП этого контрагента по доступным объектам: `{id, tender_id, tender_number, tender_title, status, amount, submitted_at}` |
| `price_context` | object | `{vs_best_pct, is_best, incomplete: {missing_count} \| null, vs_previous_pct}` — к лучшей цене и неполнота только для текущей версии; к прошлой версии — для версии > 1 |
| `versions` | array | все версии: `{version_number, is_current, submitted_at, author, author_id, supplier_name, status, diff, files}`; `diff` — `{is_first, counts: {added, changed, removed}, total, items[{kind, name, fields[{field, label, from, to}]}]}`; сравниваемые поля: цена материалов, цена работ, объём, отказ от позиции, комментарий |
| `version` | object | выбранная версия: `{version_number, is_current, submitted_at, created_by, items: {<id позиции ведомости>: Line}, new_items: [...], condition_values: {<id поля>: string}, totals: {materials, works, total}}` |
| `fkp` | object | `{version_number (по какой версии ФКП подано; null — по исходной), current (актуальная версия), outdated (подано по устаревшей ФКП)}` |
| `tender_items` | array | действующие позиции ведомости: `{id, section_name, name, unit, quantity, quote: Line \| null}` |
| `new_items` | array | позиции, предложенные контрагентом сверх ведомости: `{id, name, materials, works, total, materials_unit, works_unit, unit_total, quantity, comment, review_status, review_comment}` |
| `condition_fields` | array | условия тендера и ответы: `{id, field_name, value}` |
| `totals` | object | `{materials, works, total}` выбранной версии (без отказанных позиций; новые позиции — только принятые; округление до копеек) |

`Line` (цена контрагента по позиции): `quote_item_id`, `materials`, `works`, `total`, `materials_unit`, `works_unit`, `unit_total`, `quantity`, `declined` (отказ от позиции), `comment`, `quantity_override` (предложенный объём), `review_status` (`accepted`/`rejected`/`null`), `review_comment`, `awaiting_supplier_volume` (объём отклонён — ждём контрагента), `refill_required` (после решения по корректировке строка ждёт новую цену), `negotiation_potential` (отметка потенциала торга из СТ), `awaiting_reply` (по ячейке ждём ответа контрагента).

Цены в карточке не маскируются правом на финансы (доступ уже закрыт `quotes.manage`), маскируется только финансовый блок контрагента — см. открытые вопросы.

**Ошибки.** См. общее; 404 «КП или версия не найдены» — нет такой версии.

**Пример (сокращён).**

  "tender": {"id": 100, "number": "T-2026-100", "title": "Витражи, дворовой фасад", "project_id": 24, "status": "open",

### PATCH /quotes/{quote_id}/custom-status

**Назначение.** Назначить КП пользовательский статус — рабочую пометку специалиста поверх жизненного цикла подачи (например, «на уточнении»), или снять её.

**Доступ.** См. общее.

**Тело запроса** (`application/json`):

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `custom_status_code` | string \| null | да (ключ) | код активного статуса из справочника статусов КП (`entity_type = quote`); `null` или пустая строка — снять |

**Ответ `200`:** `{"item": {"id": integer, "custom_status_code": string | null}}`. Тот же статус повторно — ответ без побочных эффектов.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | кода нет в справочнике или он неактивен | «Неизвестный статус КП» |
| 401 / 403 / 404 | см. общее | |

**Пример.** `{"custom_status_code": "clarification"}` → `{"item": {"id": 114, "custom_status_code": "clarification"}}`

**Побочные эффекты.** Запись в ленте активности тендера `quote_status_changed` (с какого на какой, подпись) — только для сотрудников, контрагенту не показывается; событие журнала ИБ `quote_status_changed` (`from_status`, `to_status`, `tender_id`).

### POST /quotes/{quote_id}/reject

**Назначение.** Отклонить КП целиком. Отклонённое КП выпадает из «Обзора» и сравнения, но остаётся во входящих и в ленте тендера. Письмо контрагенту **не** отправляется — что и когда ему сообщить, решает специалист.

**Доступ.** См. общее.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `comment` | string | да | причина; не пустая после обрезки; в ленту пишется до 500 символов |

**Ответ `200`:** `{"item": {"id": integer, "status": "rejected"}}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | тендер `closed` или `cancelled` | «Тендер завершён — КП уже не отклонить» |
| 400 | статус КП не `submitted` / `revision_requested` | «Отклонить можно только поданное КП» |
| 400 | нет причины | «Укажите причину отклонения» |
| 401 / 403 / 404 | см. общее | |

**Пример.** `{"comment": "Не выполнены требования к составу КП: нет графика работ"}` → `{"item": {"id": 116, "status": "rejected"}}`

**Побочные эффекты.** Лента активности тендера: `quote_status_changed` (`from_status` → `rejected`, подпись «Отклонено», причина) — только для сотрудников.

### POST /quotes/{quote_id}/mark-viewed

**Назначение.** Снять флаг «новое» после открытия КП специалистом.

**Доступ.** См. общее. **Тело.** Нет.

**Ответ `200`:** `{"ok": true, "inbox_viewed_at": "<ISO 8601>"}`.

**Ошибки.** См. общее.

**Пример.** → `{"ok": true, "inbox_viewed_at": "2026-10-15T08:12:40.120000+00:00"}`

**Побочные эффекты.** Время просмотра КП (одно на КП, общее для всех сотрудников); бейдж и `new_count` уменьшаются, пока контрагент не подаст новую версию.

### GET /quotes/{quote_id}/matching

**Назначение.** Предложить пары для строк **текущей** версии КП, которые контрагент подал как новые позиции (без привязки к ведомости). Ничего не записывает: решает человек, применяет отдельная ручка. Уже привязанные строки не трогаются никогда.

**Доступ.** См. общее.

**Механика (кратко; подробно — в разделе ИИ).** Нормализация названий → векторные представления → косинусная близость → пороги: «уверенно» ≥ `AI_MATCHING_CONFIDENT` (0,90), «требует подтверждения» ≥ `AI_MATCHING_REVIEW` (0,70), иначе «не сопоставлено»; для спорных пар модель пишет объяснение. Пайплайн включается настройкой (`ai_pipelines.position_matching`, по умолчанию **выключен**) и при доступном ИИ. Операция учитывается в биллинге ИИ.

**Ответ `200`:**
- пайплайн выключен: `{"enabled": false, "summary": "Сопоставление позиций выключено в этом окружении", "pairs": [], "matched": 0, "review": 0, "unmatched": 0}`;
- нечего сопоставлять: `{"enabled": true, "summary": "В этом КП нет строк без пары" | "В ведомости тендера нет позиций", "pairs": [], …}`;
- результат:

| Поле | Тип | Смысл |
|---|---|---|
| `enabled` | boolean | `true` |
| `matched` / `review` / `unmatched` | integer | счётчики вердиктов |
| `summary` | string | «N строк сопоставлены уверенно, M требуют подтверждения» |
| `thresholds` | string | описание порогов |
| `pairs` | array | все пары, включая несопоставленные: `{fkp_index, fkp_name, fkp_ref (id позиции ведомости), quote_index, quote_name, quote_ref (id строки КП), score (строкой), verdict: matched\|review\|unmatched, label («сопоставлено уверенно» / «требует подтверждения» / «не сопоставлено»), why, differs}` |
| `degraded` | boolean | ИИ недоступен или упал — результат детерминированной части |
| `notices` | string[] | сообщения о деградации |
| `trace` | object \| null | трасса прогона (служебно) |

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | у КП нет версий | «У КП нет ни одной версии» |
| 402 | биллинг включён, у клиента блокировка при нуле и баланс исчерпан | `{"code": "tokens_exhausted", "message": "Баланс токенов исчерпан — обратитесь к администратору"}` |
| 401 / 403 / 404 | см. общее | |

**Пример.** `GET /api/quotes/112/matching` → `{"enabled": true, "matched": 2, "review": 1, "unmatched": 0, "summary": "2 строк сопоставлены уверенно, 1 требуют подтверждения", "pairs": [{"fkp_index": 14, "fkp_name": "монтаж кронштейнов", "fkp_ref": 2517, "quote_index": 1, "quote_name": "Монтаж кронштейнов фасадной системы", "quote_ref": 31560, "score": "0.93", "verdict": "matched", "label": "сопоставлено уверенно", "why": "", "differs": ""}], "degraded": false, "notices": [], "trace": null, …}`

**Побочные эффекты.** Запросы к ИИ-шлюзу и учёт операции `position_matching` в биллинге (списание токенов по факту обращений).

### POST /quotes/{quote_id}/matching/apply

**Назначение.** Применить пары, подтверждённые человеком. Сервер **заново** выполняет сопоставление и применяет только те пары, которые предложил этот прогон (между показом и подтверждением могли измениться КП и ведомость).

**Доступ.** См. общее.

**Тело запроса:**

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `pairs` | `[{quote_item_id, tender_item_id}]` | да, непустой | подтверждённые пары (из `quote_ref` / `fkp_ref`) |

Строка применяется, только если она принадлежит текущей версии КП и ещё не привязана.

**Ответ `200`:** `{"applied": integer, "requested": integer}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | пары не переданы | «Не переданы пары для применения» |
| 409 | сопоставлять нечего | «В этом КП нет строк без пары» / «В ведомости тендера нет позиций» |
| 402 | баланс токенов исчерпан | как выше |
| 401 / 403 / 404 | см. общее | |

**Пример.** `{"pairs": [{"quote_item_id": 31560, "tender_item_id": 2517}]}` → `{"applied": 1, "requested": 1}`

**Побочные эффекты.** Строка КП получает позицию ведомости и перестаёт быть «новой позицией» — в сравнении встаёт на место этой позиции. Повторный прогон ИИ учитывается в биллинге. При выключенном пайплайне прогон выполняется без шагов модели (см. открытые вопросы).
