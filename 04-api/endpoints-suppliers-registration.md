# API: регистрация контрагента по приглашению и кабинет поставщика

Ссылки-приглашения на анкету (выдача, журнал, перевыпуск, отзыв), публичная анкета саморегистрации с загрузкой документов и финализацией, а также личный кабинет контрагента (`/me/*`: профиль организации, мои тендеры, мои КП, моя лента). Остальные ручки контрагентов — в [endpoints-suppliers.md](endpoints-suppliers.md) (там же объект `SupplierItem` и справочники статусов). Общие соглашения — [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/suppliers.md](../02-business-logic/suppliers.md), [../02-business-logic/tenders-invitations.md](../02-business-logic/tenders-invitations.md), [../02-business-logic/end-to-end-scenarios.md](../02-business-logic/end-to-end-scenarios.md); экраны — [../03-screens/register.md](../03-screens/register.md) (анкета), [../03-screens/cabinet.md](../03-screens/cabinet.md) (кабинет), [../03-screens/fill.md](../03-screens/fill.md) (форма КП по ссылке), [../03-screens/suppliers.md](../03-screens/suppliers.md) (журнал ссылок); прямая загрузка файлов — [endpoints-files.md](endpoints-files.md#прямая-загрузка-в-бакет-s3); вход в ЛК — [endpoints-identity.md](endpoints-identity.md).

Сложность блока: **M** — токены приглашений одно-/многоразовые (S), анкета на 5 шагов с серверной валидацией всех полей разом (M), загрузка документов по токену с прямой загрузкой в бакет (M), кабинет (S).

## Доступ и токены — общее

- **Ссылка-приглашение** — случайный токен (32 байта, URL-safe base64); в БД хранится его SHA-256 и, пока ссылка живая, сам токен (чтобы сотрудник мог скопировать её повторно). Адрес анкеты в SPA: `/register?token=<токен>`.
- **Режимы:** `single` (по умолчанию) — одна регистрация, после неё статус `used`; `multi` — многоразовая: остаётся `pending`, растёт `use_count`, пока ссылку не отзовут. Статусы приглашения: `pending`, `used`, `revoked`.
- **Публичные ручки анкеты** работают без сессии и без проверки `Origin` (overview §2.6, §4). Ручки `POST /suppliers/register` и `/suppliers/register/{supplier_id}/…` (кроме `GET work-types`) ограничены **20 запросами за 60 с** с одного клиента (ключ — IP): превышение — 429 «Слишком много запросов — попробуйте немного позже»; недоступность счётчика — 503 «Сервис временно недоступен — попробуйте позже».
- **Ручки файлов анкеты** принимают токен приглашения и пускают, только если приглашение найдено и **последней** регистрацией по нему создан именно этот `supplier_id` (иначе 403 «Ссылка недействительна для этой анкеты»). Статус приглашения (`used`) здесь не мешает — файлы догружаются после регистрации.
- **Кабинет `/me/*`** — гейт «вошедший» + действующая связка пользователя с контрагентом (роль `supplier`); иначе 403 «Доступно только контрагенту с привязанным ЛК». Контрагент видит только свою организацию.

## Последовательность: регистрация по приглашению и вход в кабинет

```mermaid
sequenceDiagram
    autonumber
    actor S as Сотрудник
    actor C as Контрагент (браузер)
    participant API as API
    participant DB as PostgreSQL
    participant Q as Фоновые задания
    S->>API: POST /suppliers/invitations {mode:"single"}
    API->>DB: приглашение (хеш токена, pending)
    API-->>S: 201 {token, id, mode}
    S-->>C: ссылка /register?token=… (вне системы: почта, мессенджер)
    C->>API: GET /suppliers/invitations/{token}/check
    API-->>C: {valid:true, mode} | {valid:false, reason}
    C->>API: GET /suppliers/register/work-types?invite_token=…
    API-->>C: {items, require_work_experience}
    Note over C: 5 шагов мастера: организация и выручка → виды работ и опыт → контакты → документы (файлы держит браузер) → согласие на ПДн и пароль ЛК
    C->>API: POST /suppliers/register {invite_token, org, workTypes, contacts, docSlots, revenues, workExperience, pdnConsent, password?}
    API->>API: honeypot; токен; все поля разом (400 fieldErrors)
    API->>DB: supplier (status new), контакты (согласие ПДн + редакция), виды работ, опыт, выручка
    API->>DB: пользователь role=supplier + связка ЛК
    API->>DB: приглашение used (single) / use_count+1 (multi); журнал supplier_registered; уведомление «Новая анкета контрагента»
    API->>Q: задание supplier_notification (письмо держателям suppliers.manage)
    API-->>C: 201 {item, cabinet:{created, email, password?}}
    loop по каждому выбранному файлу
        C->>API: POST /suppliers/register/{id}/attachments/presign-upload {invite_token, doc_type, filename, content_type, file_size}
        alt хранилище S3
            API-->>C: {upload_id, url, method:PUT, headers}
            C->>C: PUT в бакет
            C->>API: POST …/attachments/confirm {invite_token, upload_id}
            API-->>C: 201 {item}
        else локальное хранилище (409)
            C->>API: POST /suppliers/register/{id}/attachments (multipart)
            API-->>C: 201 {item}
        end
    end
    C->>API: POST /suppliers/register/{id}/complete {invite_token}
    API->>API: обязательные слоты с реальными файлами (иначе 400 missing_required_docs)
    API->>DB: questionnaire_submitted_at, оси pending, status review, событие questionnaire_submitted
    API->>DB: уведомления СБ, юристу, тендерному специалисту
    API-->>C: 200 {item}
    C->>API: POST /auth/login (e-mail и пароль ЛК)
    C->>API: GET /me/supplier, GET /me/tenders, GET /me/quotes, GET /me/activity
    API-->>C: данные своей организации
```

Пояснения к шагам:

1–3. Сотрудник выдаёт ссылку (режим `single` или `multi`) и передаёт её контрагенту сам — система писем с приглашением на анкету не шлёт.
4–6. Анкета при открытии проверяет ссылку и показывает «ссылка недействительна» до заполнения (`not_found`, `revoked`, `used`).
7–8. Список видов работ берётся по токену — справочник для сотрудников закрыт сессией. Флаг `require_work_experience` (настройка системы) делает опыт по каждому выбранному виду работ обязательным.
9–14. Анкета отправляется одним запросом без файлов: в `docSlots` — только имена файлов обязательных слотов. Ошибки всех шагов возвращаются разом (`fieldErrors` с ключами полей, `contacts.<i>.<поле>`, `workExperience.<i>.<поле>`, `revenues.<год>`). Ссылка гасится только при успехе — анкету с ошибками можно отправить повторно. Одновременно создаётся учётная запись ЛК: с паролем из анкеты или сгенерированным (тогда он возвращается в ответе один раз и уходит письмом на e-mail организации).
15–21. Документы догружаются после создания карточки тем же токеном: сначала прямая загрузка в бакет, при выключенной прямой загрузке (409) — multipart. Механика presign/confirm и проверки файла — как у [POST /files/presign-upload](endpoints-files.md#post-filespresign-upload).
22–25. Финализация проверяет, что у трёх обязательных слотов есть реальные файлы, и отправляет анкету на аккредитацию: параллельно стартуют проверки СБ, юриста и финансов, сотрудникам приходят уведомления.
26–28. Контрагент входит в систему обычным входом и попадает в кабинет: профиль, приглашения в тендеры с прогрессом заполнения, свои КП и лента.

### POST /suppliers/invitations

**Назначение.** Создать ссылку-приглашение на анкету саморегистрации.

**Доступ.** Сотрудник.

**Тело запроса (необязательно, пустое тело допустимо):**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `mode` | string | нет | `single` (по умолчанию) или `multi`, регистр не важен |

**Ответ `201`:** `{"token": string, "id": integer, "mode": "single"|"multi"}` — токен показывается сотруднику для копирования ссылки.

**Ошибки.** 400 «mode должен быть single или multi».

**Пример.** `{"mode": "multi"}` → `201 {"token": "<токен>", "id": 9, "mode": "multi"}`

**Побочные эффекты.** Строка приглашения (`pending`, автор). Журнал ИБ не пишется.

---

### GET /suppliers/invitations/list

**Назначение.** Журнал выданных ссылок (последние 200, новые сверху). Токен отдаётся только у живых (`pending`) ссылок — чтобы скопировать повторно.

**Доступ.** Сотрудник.

**Параметры.** Нет.

**Ответ `200`:** `{"items": [...]}`, элемент:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | integer | |
| `status` | string | `pending` / `used` / `revoked` |
| `mode` | string | `single` / `multi` |
| `use_count` | integer | сколько регистраций прошло по ссылке |
| `token` | string \| null | только у `pending` |
| `created_by_name` | string | кто выдал («—», если неизвестно) |
| `created_at` | ISO | |
| `used_at` | ISO \| null | последняя регистрация (у `revoked` — `null`) |
| `supplier_id`, `supplier_name`, `supplier_inn` | | кто зарегистрировался последним |

**Ошибки.** 401/403.

**Пример.** → `{"items": [{"id": 7, "status": "used", "mode": "single", "use_count": 1, "token": null, "created_by_name": "Кузнецов Андрей Павлович", "created_at": "2026-09-05T11:15:00+00:00", "used_at": "2026-09-08T12:55:00+00:00", "supplier_id": 209, "supplier_name": "ООО «Йота Металл»", "supplier_inn": "7700000000"}]}`

**Побочные эффекты.** Нет.

### POST /suppliers/invitations/{invitation_id}/regenerate

**Назначение.** Перевыпуск: старая ссылка гасится (`revoked`), создаётся новое приглашение с новым токеном и тем же режимом (ссылку слили или потеряли до регистрации). Карточки, зарегистрированные по старой ссылке, помечаются `registeredViaStaleLink`.

**Доступ.** Сотрудник.

**Параметры пути:** `invitation_id` — integer.

**Ответ `200`:** `{"token", "id", "mode"}` — нового приглашения.

**Ошибки.** 404 «Приглашение не найдено»; 409 «Это приглашение уже использовано или отозвано — создайте новое» (статус не `pending`).

**Пример.** `POST /suppliers/invitations/8/regenerate` → `{"token": "<новый токен>", "id": 10, "mode": "single"}`

**Побочные эффекты.** Старое приглашение `revoked`, новое — `pending` с автором-текущим пользователем.

---

### POST /suppliers/invitations/{invitation_id}/revoke

**Назначение.** Отозвать ссылку без замены (утечка, отказ контрагента).

**Доступ.** Сотрудник.

**Ответ `200`:** `{"ok": true, "id": integer, "status": "revoked"}`.

**Ошибки.** 404 «Приглашение не найдено»; 409 «Это приглашение уже использовано или отозвано».

**Пример.** `POST /suppliers/invitations/5/revoke` → `{"ok": true, "id": 5, "status": "revoked"}`

**Побочные эффекты.** Статус `revoked`; многоразовая ссылка перестаёт принимать анкеты.

---

### GET /suppliers/invitations/{token}/check

**Назначение.** Публичная проверка ссылки при открытии `/register`, чтобы сразу показать «ссылка недействительна».

**Доступ.** Публично (без сессии, без лимита частоты).

**Параметры пути:** `token` — string.

**Ответ `200`:** `{"valid": true, "mode": "single"|"multi"}` или `{"valid": false, "reason": "not_found"|"revoked"|"used"}` (`used` — одноразовая ссылка уже использована). Ошибкой (4xx) недействительная ссылка не считается.

**Ошибки.** Нет (кроме общих 5xx).

**Пример.** `GET /suppliers/invitations/<токен>/check` → `{"valid": false, "reason": "used"}`

**Побочные эффекты.** Нет.

---

### GET /suppliers/register/work-types

**Назначение.** Справочник активных видов работ (по алфавиту) для шага «Виды работ» анкеты и флаг обязательности опыта.

**Доступ.** Публично по токену: приглашение с таким токеном должно существовать (статус не проверяется).

**Параметры запроса:** `invite_token` — string, обязателен.

**Ответ `200`:** `{"items": [{"id", "name", "parent_id", "is_active": true}], "require_work_experience": boolean}`.

**Ошибки.** 403 «Ссылка недействительна или устарела» (токен не найден); 422 — нет параметра.

**Пример.** → `{"items": [{"id": 17, "name": "Витражи и оконные блоки", "parent_id": null, "is_active": true}], "require_work_experience": true}`

**Побочные эффекты.** Нет.

### POST /suppliers/register

**Назначение.** Отправка анкеты саморегистрации: создаёт карточку контрагента (`status = new`), контакты, виды работ, опыт, выручку и учётную запись ЛК. Документы — следующими запросами, финализация — `…/complete`.

**Доступ.** Публично по токену приглашения; лимит 20 запросов / 60 с.

**Тело запроса (JSON):**

| Поле | Тип | Обяз. | Правила и тексты ошибок (`fieldErrors`) |
|---|---|---|---|
| `invite_token` | string | да | действующее приглашение (см. «Ошибки») |
| `hp_website` | string | — | ловушка для ботов: поле скрыто в форме; непустое — 400 «Не удалось обработать форму» |
| `org.legal_name` | string | да | «Укажите полное наименование организации» |
| `org.short_name` | string | нет | по умолчанию = полное |
| `org.inn` | string | да | ИНН 10/12 цифр, контрольная сумма; уникален в реестре |
| `org.ogrn` | string | нет | ОГРН/ОГРНИП с контрольной цифрой, согласован с ИНН |
| `org.kpp` | string | нет | формат КПП |
| `org.director_full_name` | string | да | «Укажите ФИО руководителя» |
| `org.legal_address` | string | да | адрес: город, улица, дом (≥ разумной длины, не только цифры) |
| `org.actual_address` | string | нет | то же; по умолчанию = юридический |
| `org.email` | string | да | e-mail организации (на него уходят письма по тендерам и логин ЛК) |
| `org.phone` | string | нет | телефон, E.164 |
| `org.founded_at` | string | да | `ДД.ММ.ГГГГ`, не в будущем, год ≥ 1900 |
| `workTypes` | (integer\|string)[] | да | ≥ 1 («Отметьте хотя бы одну категорию»); id или названия из справочника |
| `contacts[]` | `{full_name, job_title, phone, email, is_primary}` | да | учитываются строки с ФИО; у каждой — e-mail обязателен, телефон по формату; ключи ошибок `contacts.<индекс>.<поле>`; ни одной — «Заполните ФИО и email хотя бы одного контактного лица» |
| `docSlots` | `{charter, inn_extract, authority}` → имя файла | да | все три слота с именами; иначе ответ 400 `missing_required_docs` (раньше проверки полей) |
| `documentNames` | string[] | нет | имена прочих файлов (информативно) |
| `revenues` | `{год: сумма}` или `[{year, amount}]` | если передан — да | три последних завершённых года; число ≥ 0, не более двух знаков после запятой, пробелы и запятая допустимы; ошибки `revenues.<год>` (и дубль `revenue_<год>`): «Укажите выручку за <год> год», «Укажите числовое значение», «Выручка не может быть отрицательной», «Не более двух знаков после запятой»; если пришёл новый год, а прошлогодней суммы нет — «Наступил новый год — внесите выручку за <год>» |
| `workExperience[]` | строки опыта | по настройке | правила — [endpoints-suppliers.md, «Опыт работ»](endpoints-suppliers.md#опыт-работ), вид работ должен быть среди выбранных; ключи `workExperience.<i>.<поле>`; при `require_work_experience` — по каждому выбранному виду хотя бы один договор: «Укажите опыт работы хотя бы по одному договору для каждого заявленного вида деятельности: <виды>» |
| `pdnConsent` | boolean | да (`true`) | «Без согласия на обработку ПДн анкету принять нельзя» |
| `password` | string | нет | пароль ЛК по политике паролей (overview §7); пусто — генерируется |

**Ответ `201`:**

| Поле | Тип | Смысл |
|---|---|---|
| `item` | `SupplierItem` | созданная карточка (`status: new`, `overall_status: draft`) |
| `cabinet.created` | boolean | создана ли учётная запись ЛК |
| `cabinet.email` | string | логин ЛК (= e-mail организации) |
| `cabinet.password` | string \| null | сгенерированный пароль (показывается один раз) или `null`, если пароль задан в анкете |
| `cabinet.hint` | string | «Сгенерированный пароль показывается один раз — сохраните его.» |
| `cabinet.error` | string | при `created: false`: «Email уже занят другой учётной записью» — анкета при этом **принята** |

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | нет токена | «Ссылка недействительна — не найден токен приглашения» |
| 400 | ловушка | «Не удалось обработать форму» |
| 400 | не хватает имён обязательных документов | `{"error": "Не хватает обязательных документов", "missing_required_docs": [{"key": "authority", "label": "Документ, подтверждающий полномочия подписанта"}]}` |
| 400 | ошибки полей | `{"error": "Проверьте заполнение формы", "fieldErrors": {"inn": "…", "contacts.0.email": "Укажите корректный email", "revenues.2025": "Укажите выручку за 2025 год"}}` |
| 404 | токен не найден | «Ссылка недействительна или устарела» |
| 409 | ссылка отозвана / многоразовая отозвана | «Эта ссылка отозвана» |
| 409 | одноразовая уже использована | «Эта ссылка уже была использована для регистрации» |
| 409 | ИНН уже в реестре | «Контрагент с таким ИНН уже есть в реестре» |
| 429 / 503 | лимит частоты | см. «Доступ» |

**Пример.**

```json

   "legal_address": "г. Энск, ул. Ленина, д. 1", "email": "user@example.com", "founded_at": "14.04.2009"},

 "docSlots": {"charter": "Устав.pdf", "inn_extract": "Выписка.pdf", "authority": "Приказ.pdf"},

```

→ `201 {"item": {"id": 216, "status": "new", "overall_status": "draft", …}, "cabinet": {"created": true, "email": "user@example.com", "password": "<сгенерирован>", "hint": "Сгенерированный пароль показывается один раз — сохраните его."}}`

**Побочные эффекты.** Контакты с согласием на ПДн (время и редакция текста согласия); пустые строки выручки досоздаются; пользователь `supplier` + связка ЛК; при сгенерированном пароле — письмо на e-mail организации «Доступ в личный кабинет <название>» со ссылкой на вход, логином и паролем (синхронно); приглашение: `single` → `used`, `use_count + 1`, `used_at`, `supplier_id`; карточка запоминает приглашение (для пометки «по старой ссылке»); журнал ИБ `supplier_registered`; запись центра уведомлений всем сотрудникам «Новая анкета контрагента» (`kind: tender`, «<название> (ИНН …) — подал анкету через форму»); фоновое задание `supplier_notification` — письмо держателям `suppliers.manage` «Новый контрагент: <название>» (повторы при сбое SMTP).

### POST /suppliers/register/{supplier_id}/attachments

**Назначение.** Загрузить документ анкеты через API (локальное хранилище или запасной путь после неудачной прямой загрузки).

**Доступ.** Публично по токену приглашения этой анкеты; лимит 20 / 60 с.

**Параметры пути:** `supplier_id` — integer.

**Тело запроса (`multipart/form-data`):**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `invite_token` | string | да | токен приглашения, по которому создана карточка |
| `doc_type` | string | нет, `other` | `charter`, `inn_extract`, `authority`, `sro`, `license_mchs`, `license_minculture`, `iso`, `other`, старые `rd_url`, `tz_file`, `smr_contract_file`, `surety_file` |
| `file` | файл | да | ≤ 25 МБ (`MAX_UPLOAD_MB`); типы вложений overview §13; проверка сигнатуры и антивирус |

**Ответ `201`:** `{"item": {"id", "name", "doc_type", "size"}}`.

**Ошибки.** 403 «Ссылка недействительна для этой анкеты»; 400 «Неизвестный тип документа»; 400 тип/сигнатура/вирус и 413 «Файл больше 25 МБ» — как у [POST /files/upload](endpoints-files.md#post-filesupload); 503 хранилище недоступно; 429.

**Пример.** `invite_token=<токен>, doc_type=charter, file=Устав.pdf` → `201 {"item": {"id": 250, "name": "Устав.pdf", "doc_type": "charter", "size": 482113}}`

**Побочные эффекты.** Файл в хранилище, вложение `entity_type=supplier` (автор — пусто); журнал ИБ загрузки файла (как у `/files/upload`).
