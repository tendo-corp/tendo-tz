# API: настройки системы (settings)

Ручки экрана «Настройки»: состояние и выключатель почты, тестовое письмо, редактор шаблонов писем, SMTP-сервер из интерфейса (если разрешено при развёртывании) и системные параметры (требование к анкете контрагента, пороги аномалий сравнения). Общие соглашения (аутентификация, `Origin`, формат ошибок, 422) — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/settings.md](../02-business-logic/settings.md); экран — [../03-screens/settings.md](../03-screens/settings.md); пороги аномалий используются в сравнительной таблице — [../02-business-logic/tenders-comparison.md](../02-business-logic/tenders-comparison.md#9-пороги-системные-настройки).

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/settings/mail` | Работает ли почта и почему нет | право `settings.manage` |
| PUT | `/settings/mail` | Выключатель «Почта включена» (пауза) | `settings.manage` |
| POST | `/settings/mail/test` | Тестовое письмо себе | `settings.manage` |
| GET | `/settings/mail/templates` | Список шаблонов писем | `settings.manage` |
| PUT | `/settings/mail/templates/{code}` | Сохранить свой текст письма | `settings.manage` |
| DELETE | `/settings/mail/templates/{code}` | Вернуть стандартный текст | `settings.manage` |
| POST | `/settings/mail/templates/{code}/preview` | Предпросмотр черновика на примерных данных | `settings.manage` |
| GET | `/settings/smtp` | SMTP-сервер (без пароля) | `settings.manage`; только при `SMTP_SETTINGS_IN_UI=true` |
| PUT | `/settings/smtp` | Сохранить SMTP-сервер | то же |
| POST | `/settings/smtp/test` | Проверить соединение и вход | то же |
| GET | `/settings/system` | Системные настройки и пороги аномалий | `settings.manage` |
| PATCH | `/settings/system` | Изменить системные настройки | `settings.manage` |

**Доступ — общее для раздела.** Все ручки закрыты правом `settings.manage` матрицы «роль × действие» (по умолчанию — только у администратора; администратор матрицу обходит). Отказ: `403` «Недостаточно прав для этого действия — обратитесь к администратору системы», событие `permission_denied` пишется в журнал ИБ. Поставщику и лиду — тот же `403`. Нет сессии — `401` «Не авторизован».

Сложность блока: **M**.

### Как система решает, уходят ли письма

Порядок проверки (первое сработавшее — причина в `reason`):

| Условие | `reason` |
|---|---|
| почта выключена при развёртывании (`MAIL_ENABLED=false`) | «Почта выключена» |
| выключатель в настройках на паузе | «Почта выключена в настройках» |
| SMTP-сервер не задан (из окружения или, при `SMTP_SETTINGS_IN_UI=true`, из интерфейса) | «Почтовый сервер не настроен» |
| иначе | `null` — почта работает |

Окружение главнее выключателя: выключенную при развёртывании почту из интерфейса включить нельзя.

### Шаблоны писем

Реестр шаблонов задан в коде; администратор может переопределить тему и текст. Переменные пишутся в фигурных скобках по-русски: `{номер}`.

| `code` | Название | Когда уходит | Переменные | Обязательные |
|---|---|---|---|---|
| `invitation` | Приглашение к тендеру | контрагент приглашён в тендер | `номер`, `название`, `объект`, `вид_работ`, `срок`, `ндс`, `приглашающий`, `ссылка`, `бренд` | `ссылка` |
| `round` | Новый раунд | открыт раунд, контрагентам уходит запрос уточнённого КП | `номер`, `название`, `раунд`, `срок`, `сообщение`, `ссылка`, `бренд` | `ссылка` |
| `fkp_notice` | Новая версия ФКП | изменилась структура ФКП, участникам уходит уведомление | `номер`, `название`, `версия`, `изменения`, `ссылка`, `бренд` | `ссылка` |

Правила подстановки: неизвестная переменная при отправке остаётся как есть (проверка — до сохранения); строка шаблона, в которой все переменные оказались пустыми, выпадает целиком, подряд идущие пустые строки схлопываются.

### GET /settings/mail

**Назначение.** Показать честное состояние почты системы.

**Доступ.** `settings.manage`.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `working` | boolean | письма сейчас уходят |
| `reason` | string \| null | почему не уходят (см. таблицу выше); `null`, если работают |
| `env_enabled` | boolean | почта включена при развёртывании (`MAIL_ENABLED`) |
| `paused` | boolean | выключатель в настройках на паузе |

**Ошибки.** 401, 403 (см. общее).

**Пример.**

```json
{"working": false, "reason": "Почтовый сервер не настроен", "env_enabled": true, "paused": false}
```

**Побочные эффекты.** Нет.

### PUT /settings/mail

**Назначение.** Включить/выключить отправку писем выключателем в настройках (пауза поверх `MAIL_ENABLED`).

**Доступ.** `settings.manage`.

**Тело запроса:**

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `paused` | boolean | да | `true` — письма не отправляются |

**Ответ `200`.** Тот же объект, что у `GET /settings/mail`, уже с новым состоянием.

**Ошибки.** 401, 403, 422 (нет `paused`).

**Пример.** `{"paused": true}` → `{"working": false, "reason": "Почта выключена в настройках", "env_enabled": true, "paused": true}`.

**Побочные эффекты.** Строка настроек почты создаётся при первом обращении (единственная запись, порт 587, TLS включён). Если значение изменилось — событие журнала ИБ `mail_switch_changed` с `{"paused": …}`, сущность `settings`, IP. Пока пауза — все письма системы (приглашения, раунды, уведомления) не отправляются и помечаются причиной «Почта выключена в настройках».

### POST /settings/mail/test

**Назначение.** Отправить тестовое письмо на адрес самого администратора — проверка цепочки «сервер → ящик».

**Доступ.** `settings.manage`.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `sent` | boolean | письмо принято SMTP-сервером |
| `to` | string | адрес получателя (e-mail текущего пользователя) |
| `error` | string \| null | причина неудачи («Почта выключена», «Почта выключена в настройках», «Почтовый сервер не настроен», ошибка SMTP и т. п.) |

Неудача отправки — это `200` с `sent=false`, а не ошибка HTTP.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | у учётной записи нет e-mail | «У вашей учётной записи нет адреса почты» |
| 401 / 403 | см. общее | |

**Пример.**

```json
{"sent": false, "to": "user@example.com", "error": "Почтовый сервер не настроен"}
```

**Побочные эффекты.** Письмо с темой «<название системы>: проверка почты» и текстом «Это тестовое письмо из настроек системы. Если вы его читаете, письма системы доходят до адресатов.» Название системы — из настройки `BRAND_NAME`.

### GET /settings/mail/templates

**Назначение.** Список всех редактируемых писем с переменными, стандартным и действующим текстом.

**Доступ.** `settings.manage`.

**Параметры.** Нет.

**Ответ `200`:** массив `MailTemplate` в порядке реестра (`invitation`, `round`, `fkp_notice`):

| Поле | Тип | Смысл |
|---|---|---|
| `code` | string | код письма |
| `title` | string | название |
| `when` | string | когда уходит (одна фраза) |
| `variables` | `[{name, description}]` | доступные переменные и что в них подставляется |
| `required` | string[] | переменные, без которых письмо теряет смысл (сортировка по алфавиту) |
| `default_subject` / `default_body` | string | стандартный текст |
| `subject` / `body` | string | действующий текст: свой, если сохранён, иначе стандартный |
| `customized` | boolean | есть свой текст |

**Ошибки.** 401, 403.

**Пример (фрагмент).**

```json
[{"code": "round", "title": "Новый раунд",
  "when": "Открыт раунд: контрагентам уходит запрос уточнённого КП",
  "variables": [{"name": "номер", "description": "Номер тендера"}, {"name": "ссылка", "description": "Ссылка на форму подачи КП"}],
  "required": ["ссылка"], "default_subject": "Раунд №{раунд} — {номер}", "default_body": "Здравствуйте!\n\n…",
  "subject": "Раунд №{раунд} — {номер}", "body": "Здравствуйте!\n\n…", "customized": false}]
```

**Побочные эффекты.** Нет.

### PUT /settings/mail/templates/{code}

**Назначение.** Сохранить свой текст письма вместо стандартного.

**Доступ.** `settings.manage`.

**Параметры пути:**

| Параметр | Тип | Смысл |
|---|---|---|
| `code` | string | `invitation` \| `round` \| `fkp_notice` |

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `subject` | string | да | ≤ 300 символов; не пустая; только известные переменные |
| `body` | string | да | ≤ 20 000 символов; не пустой; только известные переменные; обязаны присутствовать все переменные из `required` |

Перед сохранением тема обрезается по краям, у текста убираются ведущие/хвостовые переводы строк и добавляется один завершающий.

**Ответ `200`.** Объект `MailTemplate` (как в списке) с `customized=true`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | неизвестный `code` (проверяется раньше разбора текста) | «Такого письма нет» |
| 422 | превышена длина поля | стандартная ошибка валидации |
| 422 | ошибки текста — по полям, в формате ошибки валидации: `[{"loc": ["body", "subject"\|"body"], "msg": "…", "type": "value_error"}]` | `msg`: «Укажите тему письма», «Напишите текст письма», «Неизвестные переменные: {x}, {y}», «В тексте должно быть {ссылка}» |
| 401 / 403 | см. общее | |

**Пример.**

```json
{"subject": "Раунд №{раунд} по тендеру {номер}", "body": "Добрый день!\n\nОткрыт раунд №{раунд}.\nФорма: {ссылка}\n"}
```

**Побочные эффекты.** Запись в таблицу своих шаблонов (кто изменил — `updated_by`). Событие журнала ИБ `mail_template_changed` с `{"code": "<code>", "action": "saved"}`. Все последующие письма этого типа собираются по новому тексту.

### DELETE /settings/mail/templates/{code}

**Назначение.** Удалить свой текст и вернуть стандартный.

**Доступ.** `settings.manage`.

**Параметры пути.** `code` — как выше.

**Ответ `200`.** Объект `MailTemplate` со стандартным текстом и `customized=false`. Повторный вызов без своего текста — тоже `200`.

**Ошибки.** 404 «Такого письма нет»; 401 / 403.

**Пример.** `DELETE /api/settings/mail/templates/round` → `{"code": "round", …, "customized": false}`.

**Побочные эффекты.** Если свой текст был — удаляется, событие журнала ИБ `mail_template_changed` с `{"code": …, "action": "reset"}`.

### POST /settings/mail/templates/{code}/preview

**Назначение.** Показать, как будет выглядеть письмо из несохранённого черновика редактора, на примерных данных (номер «Т-2026-014», дата, имя приглашающего и т. п. — набор фиксирован для каждого шаблона).

**Доступ.** `settings.manage`.

**Параметры пути.** `code` — как выше.

**Тело запроса.** Как у `PUT …/{code}`: `subject` (≤ 300), `body` (≤ 20 000). Проверка переменных не выполняется — неизвестные `{…}` остаются в тексте как есть.

**Ответ `200`:** `{"subject": string, "body": string}` — результат подстановки.

**Ошибки.** 404 «Такого письма нет»; 422 — длина; 401 / 403.

**Пример.**

```json
{"subject": "Раунд №{раунд} — {номер}", "body": "Срок ответа: {срок}.\nФорма: {ссылка}\n"}
```

```json
{"subject": "Раунд №2 — Т-2026-014", "body": "Срок ответа: 20.10.2026 18:00.\nФорма: https://example.ru/fill/…\n"}
```

**Побочные эффекты.** Нет (ничего не сохраняется).

### GET /settings/smtp

**Назначение.** Параметры SMTP-сервера, заданного из интерфейса. Пароль не возвращается никогда.

**Доступ.** `settings.manage`. Ручка существует только при `SMTP_SETTINGS_IN_UI=true`; иначе — `404 {"detail": "Not Found"}` раньше проверки прав (как у несуществующего пути). Включён ли экран SMTP, фронт узнаёт из `GET /settings/system` → `smtp_settings_in_ui`.

**Параметры.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `host` | string | адрес сервера (пустая строка — не задан) |
| `port` | integer | порт (по умолчанию 587) |
| `username` | string \| null | логин |
| `use_tls` | boolean | STARTTLS/SSL (по умолчанию `true`) |
| `from_email` | string \| null | адрес отправителя |
| `password_set` | boolean | пароль сохранён |
| `configured` | boolean | заданы и `host`, и `from_email` |

**Ошибки.** 404 (флаг выключен); 401 / 403.

**Пример.**

```json
{"host": "smtp.example.com", "port": 587, "username": "user@example.com", "use_tls": true,
 "from_email": "user@example.com", "password_set": true, "configured": true}
```

**Побочные эффекты.** При первом обращении создаётся пустая строка настроек.

### PUT /settings/smtp

**Назначение.** Сохранить SMTP-сервер.

**Доступ.** Как у `GET /settings/smtp`.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `host` | string | нет (по умолч. `""`) | ≤ 255; обрезается по краям |
| `port` | integer | нет (587) | 1–65535 |
| `username` | string \| null | нет | ≤ 255; пустое → `null` |
| `password` | string \| null | нет | пустая строка или `null` — «не менять пароль»; хранится зашифрованным на уровне поля |
| `use_tls` | boolean | нет (`true`) | |
| `from_email` | string \| null | нет | ≤ 255; пустое → `null` |

**Ответ `200`.** Как у `GET /settings/smtp`.

**Ошибки.** 404 (флаг выключен); 422 (длина, порт вне диапазона); 401 / 403.

**Пример.**

```json
{"host": "smtp.example.com", "port": 465, "username": "user@example.com", "password": "…", "use_tls": true, "from_email": "user@example.com"}
```

**Побочные эффекты.** Все последующие письма уходят через новый сервер. Записи в журнал ИБ нет (см. открытые вопросы).

### POST /settings/smtp/test

**Назначение.** Проверить соединение и вход с сохранёнными настройками. Письмо не отправляется.

**Доступ.** Как у `GET /settings/smtp`.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:** `{"ok": true, "steps": [...]}`, где `steps` — пройденные шаги по порядку: `connected`, `tls` (если порт 465 или `use_tls=true`), `auth` (если задан логин). Тайм-аут соединения — 8 с.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | `host` не сохранён | «Сначала укажите и сохраните адрес SMTP-сервера» |
| 400 | сервер отверг логин/пароль | «Ошибка авторизации: <текст сервера>» |
| 400 | не удалось подключиться (сеть, TLS, тайм-аут, иная ошибка SMTP) | «Не удалось подключиться: <причина>» |
| 404 | флаг выключен | «Not Found» |
| 401 / 403 | см. общее | |

**Пример.** `{"ok": true, "steps": ["connected", "tls", "auth"]}`.

**Побочные эффекты.** Нет.

### GET /settings/system

**Назначение.** Системные настройки для экрана «Настройки».

**Доступ.** `settings.manage`.

**Параметры.** Нет.

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `require_questionnaire_work_experience` | boolean | требовать от контрагента заполнить в анкете опыт работ (раздел «Опыт») при регистрации/подаче анкеты |
| `smtp_settings_in_ui` | boolean | только чтение, из окружения `SMTP_SETTINGS_IN_UI`: показывать ли экран SMTP |
| `anomaly` | `AnomalyThresholds` | действующие пороги аномалий сравнения |
| `anomaly_defaults` | `AnomalyThresholds` | системные значения по умолчанию (для кнопки «Вернуть системные значения») |

`AnomalyThresholds`:

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `spread_notice` | number | 15 | порог разброса цен «внимание», % |
| `spread_high` | number | 40 | порог разброса «высокий», % |
| `anomaly_k` | number | 3 | коэффициент аномальной цены: цена участника по позиции аномальна, если её отклонение от медианы в k раз больше медианного отклонения остальных участников (и не меньше порога «внимание»; нужно ≥ 3 сопоставимых цен) |
| `key_share` | number | 80 | доля ключевых работ, %: позиции, которые нарастающим итогом дают эту долю разницы/стоимости |

Точная семантика порогов — в [../02-business-logic/tenders-comparison.md §9](../02-business-logic/tenders-comparison.md#9-пороги-системные-настройки) (формулы разброса, аномалии и ключевых позиций — §5 того же файла).

**Ошибки.** 401 / 403.

**Пример.**

```json
{"require_questionnaire_work_experience": true, "smtp_settings_in_ui": false,
 "anomaly": {"spread_notice": 15.0, "spread_high": 40.0, "anomaly_k": 3.0, "key_share": 80.0},
 "anomaly_defaults": {"spread_notice": 15.0, "spread_high": 40.0, "anomaly_k": 3.0, "key_share": 80.0}}
```

**Побочные эффекты.** При первом обращении создаётся единственная строка настроек со значениями по умолчанию (`require_questionnaire_work_experience=false`).

### PATCH /settings/system

**Назначение.** Частично изменить системные настройки; переданные поля меняются, отсутствующие — нет.

**Доступ.** `settings.manage`.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `require_questionnaire_work_experience` | boolean \| null | нет | |
| `anomaly` | object \| null | нет | частичный набор порогов |
| `anomaly.spread_notice` | number \| null | нет | > 0, ≤ 10 000 |
| `anomaly.spread_high` | number \| null | нет | > 0, ≤ 10 000 |
| `anomaly.anomaly_k` | number \| null | нет | > 0, ≤ 100 |
| `anomaly.key_share` | number \| null | нет | > 0, ≤ 100 |

Согласованность проверяется по итоговому набору (сохранённые значения + переданные).

**Ответ `200`.** Как у `GET /settings/system`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | `spread_notice` ≤ 0 | «Порог разброса должен быть больше нуля» |
| 400 | `spread_high` ≤ `spread_notice` | «Высокий порог разброса должен быть больше порога внимания» |
| 400 | `anomaly_k` ≤ 0 | «Коэффициент аномалии должен быть больше нуля» |
| 400 | `key_share` вне (0; 100] | «Доля ключевых работ — от 0 до 100 %» |
| 422 | значение вне диапазона схемы | стандартная ошибка валидации |
| 401 / 403 | см. общее | |

**Пример.** `{"anomaly": {"spread_high": 50}}` → полный объект настроек с `anomaly.spread_high = 50.0`.

**Побочные эффекты.** Если изменился хотя бы один порог — событие журнала ИБ `anomaly_thresholds_changed` с деталями `{"anomaly_spread_high": {"from": 40.0, "to": 50.0}, …}`. Новые пороги сразу меняют подсветку аномалий в сравнительных таблицах у всех пользователей. Изменение `require_questionnaire_work_experience` в журнал не пишется.
