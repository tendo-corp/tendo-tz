# API: комментарии (comments)

Ручки внутреннего обсуждения сущностей: тендера, КП, позиции тендера (в том числе ячейки «подрядчик × позиция» сравнительной таблицы) и карточки контрагента. Один уровень вложенности (комментарий → ответы), один файл на комментарий, адресное «+ Уведомить», отметки «прочитано» — свои у каждого пользователя. Общие соглашения (аутентификация, формат ошибок, конверт постраничных списков `{items, total, limit, offset}`) — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/comments.md](../02-business-logic/comments.md); экраны — [../03-screens/tender-card.md](../03-screens/tender-card.md) (обсуждение тендера, комментарии ячеек СТ), [../03-screens/quote-card.md](../03-screens/quote-card.md). Загрузка файла к комментарию — через общие ручки файлов (`endpoints-files.md`, раздел API-1): файл грузится на саму обсуждаемую сущность.

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/comments` | Обсуждение сущности: корневые комментарии страницей + все ответы к ним | вошедший пользователь с доступом к сущности |
| POST | `/comments` | Новый комментарий или ответ | то же |
| POST | `/comments/read` | Отметить записи прочитанными (для себя) | то же |

Сложность блока: **S–M**.

### Правила доступа (общие для трёх ручек)

`entity_type` — один из: `tender`, `quote`, `tender_item`, `supplier`.

| Кто | `tender` / `tender_item` | `quote` | `supplier` |
|---|---|---|---|
| Администратор | да | да | да |
| Сотрудник (тендерный специалист, СБ, юрист) | только если проект тендера входит в его доступные проекты (гранты на портфель/проект, с подпроектами) | то же, по тендеру КП | да (любой сотрудник) |
| Поставщик (пользователь контрагента) | нет — 403 | только КП своего контрагента | нет — 403 |

Тексты отказов:

| Код | Когда | `detail` |
|---|---|---|
| 400 | `entity_type` не из списка | «Недопустимый тип сущности» (GET) / «Недопустимый тип или id сущности» (POST) |
| 403 | поставщик обращается не к КП | «Комментарии по этой сущности доступны только сотрудникам компании» |
| 403 | поставщик — к чужому КП | «Нет доступа к КП» |
| 403 | сотрудник без доступа к проекту тендера | «Нет доступа к проекту этого тендера» |
| 403 | не сотрудник — к карточке контрагента | «Доступно только сотрудникам компании» |
| 404 | сущности нет | «Тендер не найден» / «КП не найдено» / «Приглашение не найдено» / «Позиция не найдена» |

### Объект `Comment`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | integer | id комментария |
| `parent_comment_id` | integer \| null | корень треда для ответа; `null` у корневого |
| `supplier_id` | integer \| null | «якорь» треда ячейки СТ (подрядчик колонки); только у `tender_item`, иначе `null` |
| `author_name` | string | ФИО автора; «Удалённый пользователь», если автора нет |
| `comment_text` | string | текст; для комментария только с файлом — «📎 <имя файла>» |
| `created_at` | string | время по Москве, формат `ДД.ММ.ГГГГ ЧЧ:ММ` |
| `notify_user_id` | integer \| null | кого позвали через «+ Уведомить» |
| `notify_name` | string \| null | ФИО адресата |
| `attachment` | object \| null | файл: `{id, name, size, content_type, is_image}` (`is_image` — `content_type` начинается с `image/`) |
| `replies` | Comment[] | ответы (только у корневых; у ответов — пустой массив) |

---

### GET /comments

**Назначение.** Лента обсуждения сущности. Страница считается по **корневым** комментариям (чтобы тред не разрывался границей страницы); ответы к попавшим на страницу корням приходят целиком. Порядок — по времени создания, старые сверху (и корни, и ответы).

**Доступ.** См. «Правила доступа».

**Параметры запроса:**

| Параметр | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `entity_type` | string | да | `tender` \| `quote` \| `tender_item` \| `supplier` |
| `entity_id` | integer | да | id сущности |
| `limit` | integer | нет | 1–200; без него — все корни, но не больше 200 |
| `offset` | integer | нет | ≥ 0, по умолчанию 0 |

Фильтра по `supplier_id` нет: для треда ячейки СТ клиент запрашивает обсуждение позиции (`tender_item`) и сам группирует записи по `supplier_id`.

**Ответ `200`:** `{"items": Comment[], "total": <число корней>, "limit": <фактический лимит>, "offset": …}`.

**Ошибки.** См. «Правила доступа»; 401 — нет сессии; 422 — нет обязательного параметра.

**Пример.**

```http
GET /api/comments?entity_type=tender&entity_id=109
```

```json
{"items": [{"id": 9265, "parent_comment_id": null, "supplier_id": null, "author_name": "Петров Пётр Петрович",
  "comment_text": "Итоги: 2 раунда, 3 КП. Рекомендую к заключению договора.", "created_at": "22.09.2026 14:40",
  "notify_user_id": 1, "notify_name": "Сидорова Анна", "attachment": null,
  "replies": [{"id": 9266, "parent_comment_id": 9265, "supplier_id": null, "author_name": "Сидорова Анна",
    "comment_text": "Согласовано, закрывайте тендер.", "created_at": "22.09.2026 14:55",
    "notify_user_id": null, "notify_name": null, "attachment": null, "replies": []}]}],
 "total": 1, "limit": 200, "offset": 0}
```

**Побочные эффекты.** Нет (отметки «прочитано» ставит только `POST /comments/read`).

### POST /comments

**Назначение.** Добавить комментарий или ответ, при необходимости с файлом и адресным упоминанием.

**Доступ.** См. «Правила доступа» (поставщик может писать только в обсуждение своего КП).

**Тело запроса** (`application/json`, без строгой схемы — поля читаются сервером):

| Поле | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `entity_type` | string | да | `tender` \| `quote` \| `tender_item` \| `supplier` |
| `entity_id` | integer | да | ненулевой |
| `comment_text` | string | да, если нет `attachment_id` | обрезается по краям; длина не ограничена |
| `parent_comment_id` | integer \| null | нет | id корневого комментария, на который отвечают |
| `supplier_id` | integer \| null | нет | якорь треда ячейки СТ; допустим только при `entity_type=tender_item`; контрагент должен существовать. Ответ без `supplier_id` наследует якорь родителя |
| `attachment_id` | integer \| null | нет | ранее загруженный файл, привязанный к **этой же** сущности (`entity_type`/`entity_id` файла совпадают) |
| `notify_user_id` | integer \| null | нет | адресат «+ Уведомить»: активный пользователь-сотрудник (не поставщик) |

**Ответ `201`:** `{"item": Comment}` (поле `replies` в ответе отсутствует).

**Ошибки:**

| Код | Когда | `detail` |
|---|---|---|
| 400 | неверный `entity_type` или нет `entity_id` | «Недопустимый тип или id сущности» |
| 400 | нет ни текста, ни файла | «Комментарий не может быть пустым» |
| 400 | файл не найден или привязан к другой сущности | «Файл не привязан к этому обсуждению» |
| 400 | адресат не найден или отключён | «Недопустимый адресат уведомления» |
| 400 | адресат — поставщик | «Адресат уведомления должен быть сотрудником» |
| 400 | `supplier_id` не существует | «Недопустимый поставщик» |
| 400 | `supplier_id` при типе, отличном от `tender_item` | «Поставщик-якорь имеет смысл только у комментария позиции» |
| 401 / 403 / 404 | см. «Правила доступа» | |

**Пример.**

```json
{"entity_type": "tender_item", "entity_id": 2504, "supplier_id": 203,
 "comment_text": "Цена профиля выше медианы на 40 % — уточнить комплектацию.", "notify_user_id": 12}
```

```json
{"item": {"id": 9270, "parent_comment_id": null, "supplier_id": 203, "author_name": "Петров Пётр Петрович",
  "comment_text": "Цена профиля выше медианы на 40 % — уточнить комплектацию.", "created_at": "15.10.2026 11:02",
  "notify_user_id": 12, "notify_name": "Сидорова Анна", "attachment": null}}
```

**Побочные эффекты.**
- Для `tender`, `quote`, `tender_item` увеличивается ревизия тендера (комментарий меняет входной контекст ИИ-анализа; кэш анализа/сравнения считается устаревшим).
- Автору комментарий сразу помечается прочитанным.
- In-app уведомление (вид `comment`, аудитория — сотрудники, ссылка на карточку тендера) получают: адресат «+ Уведомить» (заголовок «Вас упомянули в комментарии») и ответственный за тендер (заголовок «Новый комментарий»); автор себе не пишет, дубли схлопываются. Текст: «<автор> · «<название тендера>»: <первые 160 символов>». Для `supplier` ответственного нет — только адресат. Уведомление публикуется в живой поток адресата (SSE ленты уведомлений).
- Адресату «+ Уведомить» дополнительно уходит письмо «Вас упомянули в комментарии» с тем же текстом и ссылкой на тендер (если почта работает и у адресата есть e-mail).
- Событие журнала ИБ `comment_created` (сущность, `comment_id`, `supplier_id`, IP).

### POST /comments/read

**Назначение.** Отметить записи обсуждения прочитанными для текущего пользователя (бейджи непрочитанного). С `ids` — отмечаются именно показанные записи; без `ids` — весь тред (кнопка «Отметить всё просмотренным»), для ячейки СТ — тред пары «позиция × подрядчик».

**Доступ.** См. «Правила доступа».

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `entity_type` | string | да | как выше |
| `entity_id` | integer | да | ненулевой |
| `supplier_id` | integer \| null | нет | только для `tender_item` — ограничить тредом ячейки |
| `ids` | integer[] \| null | нет | конкретные id комментариев этой сущности; чужие id игнорируются |

**Ответ `200`:** `{"marked": <сколько записей отмечено>}` (повторная отметка идемпотентна и тоже считается).

**Ошибки:**

| Код | Когда | `detail` |
|---|---|---|
| 400 | неверный `entity_type` или нет `entity_id` | «Недопустимый тип или id сущности» |
| 400 | `supplier_id` при типе, отличном от `tender_item` | «Поставщик-якорь имеет смысл только у комментария позиции» |
| 400 | `ids` содержит не числа | «Недопустимый перечень записей» |
| 401 / 403 / 404 | см. «Правила доступа» | |

**Пример.** `{"entity_type": "tender_item", "entity_id": 2504, "supplier_id": 203}` → `{"marked": 3}`.

**Побочные эффекты.** Запись отметок «пользователь × комментарий» (upsert с временем прочтения). Другим пользователям не видно.
