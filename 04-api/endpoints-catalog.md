# API: справочники — виды работ, бюджетные позиции, единицы, статусы, дефолты вида работ в объекте (catalog, statuses, project-work-type-configs)

Ручки справочников: дерево видов работ, дерево бюджетных позиций (статей бюджета) с суммами по годам и переносом суммы на подпозицию, единицы измерения с запоминанием написаний из Excel, пользовательские статусы тендеров и КП, а также даты сбора КП и шаблон по умолчанию для вида работ внутри объекта. Общие соглашения — в [overview.md](overview.md). Счётчик использования статусов `GET /statuses/usage` (первый тег `tenders`) описан в [endpoints-tenders.md](endpoints-tenders.md).

Связанные разделы: бизнес-логика — [../02-business-logic/catalog.md](../02-business-logic/catalog.md), бюджет — [../02-business-logic/budget.md](../02-business-logic/budget.md); экраны — [../03-screens/catalog-work-types.md](../03-screens/catalog-work-types.md), [../03-screens/catalog-budget-positions.md](../03-screens/catalog-budget-positions.md), [../03-screens/catalog-units.md](../03-screens/catalog-units.md), [../03-screens/catalog-statuses.md](../03-screens/catalog-statuses.md), [../03-screens/portfolios.md](../03-screens/portfolios.md) (панель дефолтов вида работ); сводка и распределение бюджета — [endpoints-budget.md](endpoints-budget.md); мастер тендера — [endpoints-tenders.md](endpoints-tenders.md).

| PATCH | `/statuses/{status_id}` | Переименовать, перекрасить, вернуть из архива | `catalogs.manage` |

| PUT | `/projects/{project_id}/work-type-configs/{work_type_id}` | Задать даты сбора КП и шаблон для вида работ | доступ к объекту |

Сложность блока: **L** — бюджетные позиции с переносами, историей и метриками (L), виды работ и статусы (S+S), единицы с синонимами (S), дефолты вида работ (S).

**Общее.** «Сотрудник» — роли `admin`, `tender_specialist`, `security`, `lawyer`; контрагенту — 403 «Доступно только сотрудникам компании». Отказ по праву — 403 «Недостаточно прав для этого действия — обратитесь к администратору системы» и событие `permission_denied`. По умолчанию `catalogs.manage` и `budget.manage` есть только у администратора. Удаления во всех справочниках **мягкие** (флаг `is_active = false`): на записи ссылаются тендеры, КП, контрагенты, и архивная запись остаётся в старых данных, но пропадает из выбора в новых формах.

## Виды работ

Неограниченное дерево: `parent_id = null` — корневая категория, иначе подкатегория любого уровня. Название уникально без учёта регистра. Вид работ задаётся тендеру (несколько), контрагенту и дефолтам объекта. С бюджетными позициями виды работ не связаны.

Объект `WorkType`: `{id: integer, name: string, is_active: boolean, parent_id: integer | null}`.

### GET /work-types

**Назначение.** Все виды работ (включая архивные) плоским списком по id — дерево собирает клиент по `parent_id`.

**Доступ.** Сотрудник.

**Параметры.** Нет.

**Ответ `200`:** массив `WorkType`.

**Ошибки.** 401/403.

**Пример.** → `[{"id": 13, "name": "Устройство фасадов", "is_active": true, "parent_id": null}, {"id": 17, "name": "Витражи и оконные блоки", "is_active": true, "parent_id": null}]`.

**Побочные эффекты.** Нет.

### POST /work-types

**Назначение.** Завести вид работ (корневой или подкатегорию).

**Доступ.** `catalogs.manage`.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `name` | string | да | непустое после обрезки, ≤ 255, уникально без учёта регистра |
| `parent_id` | integer \| null | нет | существующий вид работ |

**Ответ `201`:** `WorkType`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | пустое имя | «Введите название вида работ» |
| 409 | имя занято | «Такой вид работ уже есть в справочнике» |
| 404 | родителя нет | «Родительская категория не найдена» |
| 422 | нет `name` | |

**Пример.** `{"name": "Кровельные работы", "parent_id": null}` → `201 {"id": 18, "name": "Кровельные работы", "is_active": true, "parent_id": null}`.

**Побочные эффекты.** Журнал ИБ `work_type_created` (имя, родитель).

### PATCH /work-types/{item_id}

**Назначение.** Переименовать, перенести в другую ветку (или сделать корневым), включить/выключить.

**Доступ.** `catalogs.manage`.

**Параметры пути:** `item_id` — integer.

**Тело запроса** (применяются только присланные поля):

| Поле | Тип | Правило |
|---|---|---|
| `name` | string | уникальность без учёта регистра; смена регистра своего имени допустима; пустое — игнорируется |
| `is_active` | boolean | |
| `parent_id` | integer \| null | явный `null` — сделать корневым; нельзя сам себя и потомка (цикл) |

**Ответ `200`:** `WorkType`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | вида работ нет | «Вид работ не найден» |
| 409 | имя занято другим | «Такой вид работ уже есть в справочнике» |
| 400 | родитель = сам | «Категория не может быть родителем самой себя» |
| 404 | родителя нет | «Родительская категория не найдена» |
| 400 | перенос в своего потомка | «Так нельзя — получится цикл в дереве» |

**Пример.** `PATCH /api/work-types/17` `{"parent_id": 13}` → `{"id": 17, …, "parent_id": 13}`.

**Побочные эффекты.** Журнал ИБ `work_type_changed` (`before`, `after`).

### DELETE /work-types/{item_id}

**Назначение.** «Удалить» вид работ — снять флаг активности. Повторный вызов идемпотентен.

**Доступ.** `catalogs.manage`.

**Параметры пути:** `item_id` — integer.

**Ответ `200`:** `{"ok": true, "id": integer}`.

**Ошибки.** 404 «Вид работ не найден».

**Пример.** `DELETE /api/work-types/18` → `{"ok": true, "id": 18}`.

**Побочные эффекты.** Журнал ИБ `work_type_changed` (`via: delete`, `was_active`, имя). Подкатегории не архивируются автоматически.

## Бюджетные позиции

Дерево статей бюджета (не глубже **5** уровней). Код позиции (необязательный) уникален среди **активных** позиций; имя уникально в пределах родителя. Хранится только «выделено» на пару «позиция × год» (`budget_period_allocations`, статус периода `open`/`closed`, история изменений сумм); «в работе», «израсходовано», «свободно» вычисляются из тендеров (правила — [endpoints-budget.md](endpoints-budget.md)). Закрытый период не меняется. Тендер ссылается на позицию полем `budget_position_id`.

Объект `BudgetPositionMetrics` (строка списка):

| Поле | Тип | Смысл |
|---|---|---|
| `id`, `name`, `code`, `parent_id`, `is_active` | | |
| `path` | string | путь «Корень › … › Позиция» |
| `depth` | integer | уровень (0 — корень) |
| `period_year` | integer | год метрик |
| `allocation_id` / `allocation_status` / `allocation_comment` | integer \| null / `open` \| `closed` \| null / string \| null | бюджет позиции на год |
| `allocated`, `in_work`, `spent`, `free` | number | выделено / в работе / израсходовано / свободно (`free = allocated − in_work − spent`) |
| `has_funds` | boolean | `free > 0` |
| `branch_allocated`, `branch_in_work`, `branch_spent`, `branch_free` | number | то же по ветке (позиция + потомки) |
| `tenders_total`, `tenders_open`, `tenders_closed` | integer | тендеры позиции за год: все / `draft`+`open` / `closed` |
| `branch_tenders_total` | integer | тендеры ветки |

### GET /budget-positions

**Назначение.** Справочник статей бюджета с метриками выбранного года (экран справочника и выбор позиции в тендере).

**Доступ.** Сотрудник (отдельное право `budget.view` здесь не требуется).

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `year` | integer | текущий год | год метрик |
| `include_inactive` | boolean | `false` | включать архивные |
| `limit`, `offset` | integer | — / 0 | пагинация (страница режется после расчёта метрик по всему дереву) |

**Ответ `200`:** `{items: BudgetPositionMetrics[], total, limit, offset}`, порядок — дерево (родитель перед потомками).

**Ошибки.** 401/403; 422.

**Пример.** `GET /api/budget-positions?limit=1` →

```json
{"items": [{"id": 16, "name": "Жилые корпуса 1 и 3", "code": "OBJ-MKD", "parent_id": 36, "is_active": true,
  "path": "ЖК «Северный парк» › Жилые корпуса 1 и 3", "depth": 1, "period_year": 2026, "allocation_id": 37,
  "allocation_status": "open", "allocation_comment": null, "allocated": 23000000.0, "in_work": 0.0, "spent": 0.0,
  "free": 23000000.0, "has_funds": true, "branch_allocated": 788000000.0, "branch_in_work": 512400000.0,
  "branch_spent": 150031118.06, "branch_free": 125568881.94, "tenders_total": 0, "tenders_open": 0,
  "tenders_closed": 0, "branch_tenders_total": 3}], "total": 15, "limit": 1, "offset": 0}
```

**Побочные эффекты.** Нет.

### POST /budget-positions

**Назначение.** Завести статью бюджета; для подпозиции — сразу перенести на неё часть выделенной суммы родителя за год (с возможностью отменить перенос).

**Доступ.** `budget.manage`.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `name` | string | да | непустое после обрезки; уникально в пределах родителя |
| `code` | string \| null | нет | уникален среди активных позиций |
| `parent_id` | integer \| null | нет | существующая позиция; глубина родителя < 5 |
| `transfer_amount` | number \| null | нет | ≥ 0; > 0 только с `parent_id`; не больше выделенного родителю на год |
| `period_year` | integer \| null | нет | год переноса; по умолчанию текущий |

**Ответ `201`:** `BudgetPositionMetrics` новой позиции за год + `undo_transfer`: `{child_id, parent_id, period_year, amount}` при переносе, иначе `null` (передаётся в `POST /budget-positions/undo-transfer`).

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | пустое имя | «Введите название бюджетной позиции» |
| 400 | родителя нет | «Родительская позиция не найдена» |
| 400 | глубже 5 уровней | «Дерево не глубже 5 уровней» |
| 409 | имя занято у родителя | «Имя уже занято в пределах этого родителя» |
| 409 | код занят | «Код уже используется активной позицией» |
| 400 | отрицательный перенос | «Сумма переноса не может быть отрицательной» |
| 400 | перенос без родителя | «Перенос суммы возможен только при создании подпозиции» |
| 400 | период родителя закрыт | «Закрытый период родителя нельзя менять» |
| 400 | перенос больше остатка | «Сумма превышает нераспределённый остаток родителя (<сумма>)» |

**Пример.** `{"name": "Устройство фасадов", "code": "OBJ-MKD.06", "parent_id": 16, "transfer_amount": 15000000, "period_year": 2026}` → `201 {…, "allocated": 15000000.0, "undo_transfer": {"child_id": 40, "parent_id": 16, "period_year": 2026, "amount": 15000000.0}}`.

**Побочные эффекты.** При переносе: «выделено» родителя уменьшается, подпозиции — назначается; две записи истории («Перенос на подпозицию «…» (−…)», «Перенос с родителя id=… (+…)»). Журнал ИБ `budget_position_created`.

### GET /budget-positions/{item_id}

**Назначение.** Карточка статьи: метрики за год, путь, подпозиции, тендеры года, история изменений суммы.

**Доступ.** Сотрудник.

**Параметры:**

| Параметр | Где | Тип | По умолчанию |
|---|---|---|---|
| `item_id` | путь | integer | |
| `year` | запрос | integer | текущий год |

**Ответ `200`:** `BudgetPositionMetrics` (в т.ч. для архивной) плюс:

| Поле | Тип | Смысл |
|---|---|---|
| `children` | `BudgetPositionMetrics[]` | прямые подпозиции (включая архивные) |
| `tenders` | `[{id, number, title, status, project_id, project_name, plan_amount}]` | тендеры позиции за год; `plan_amount` — плановый бюджет или `null` |
| `history` | `[{id, old_amount, new_amount, comment, changed_by, created_at}]` | история суммы позиции за год |

**Ошибки.** 404 «Бюджетная позиция не найдена».

**Пример.** `GET /api/budget-positions/16?year=2026` → `{"id": 16, …, "children": [{"id": 22, "name": "Устройство фасадов", …}], "tenders": [], "history": [{"id": 83, "old_amount": 38000000.0, "new_amount": 23000000.0, "comment": "Перенос на подпозицию «Витражи и оконные блоки» (−15000000.00)", "changed_by": 1, "created_at": "2026-09-21T07:30:00+00:00"}]}`.

**Побочные эффекты.** Нет.

### PATCH /budget-positions/{item_id}

**Назначение.** Переименовать, сменить код, перенести в другую ветку, архивировать/вернуть. При архивации подпозиции остаток «выделено» текущего года возвращается родителю.

**Доступ.** `budget.manage`.

**Параметры пути:** `item_id` — integer.

**Тело запроса** (только присланные поля):

| Поле | Тип | Правило |
|---|---|---|
| `name` | string | уникально у (нового) родителя; пустое — без изменений |
| `code` | string | уникален среди активных; пустая строка — очистить |
| `parent_id` | integer \| null | не в себя и не в свою ветку; итоговая глубина ветки ≤ 5 |
| `is_active` | boolean | `false` — архив с возвратом остатка (если период позиции и родителя не закрыт) |

**Ответ `200`:** `{id, name, code, parent_id, is_active, returned_to_parent}` — `returned_to_parent`: возвращённая родителю сумма или `null`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | нет позиции | «Бюджетная позиция не найдена» |
| 409 | имя занято | «Имя уже занято в пределах этого родителя» |
| 400 | родителя нет | «Родительская позиция не найдена» |
| 400 | перенос в себя/ветку | «Нельзя перенести позицию в саму себя или в свою подветку» |
| 400 | глубина | «Дерево не глубже 5 уровней» |
| 409 | код занят | «Код уже используется активной позицией» |

**Пример.** `{"is_active": false}` → `{"id": 40, "name": "…", "code": "…", "parent_id": 16, "is_active": false, "returned_to_parent": 15000000.0}`.

**Побочные эффекты.** История сумм при возврате («Возврат при архивации подпозиции», «Возврат с архивированной подпозиции «…»»). Журнал ИБ `budget_position_changed` (поля, возврат).

### DELETE /budget-positions/{item_id}

**Назначение.** «Удалить» позицию — архивировать с возвратом остатка текущего года родителю. Повторный вызов идемпотентен.

**Доступ.** `budget.manage`.

**Параметры пути:** `item_id` — integer.

**Ответ `200`:** `{"ok": true, "id": integer, "returned_to_parent": number | null}`.

**Ошибки.** 404 «Бюджетная позиция не найдена».

**Пример.** → `{"ok": true, "id": 40, "returned_to_parent": null}`.

**Побочные эффекты.** История сумм («Возврат при удалении подпозиции» / «Возврат с удалённой подпозиции «…»»). Журнал ИБ `budget_position_changed` (`via: delete`). Подпозиции не архивируются автоматически.

### POST /budget-positions/undo-transfer

**Назначение.** Отменить перенос суммы, сделанный при создании подпозиции (кнопка «Отменить» в уведомлении после создания).

**Доступ.** `budget.manage`.

**Параметры.** Нет.

**Тело запроса** (значения из `undo_transfer` ответа создания):

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `child_id` | integer | да | |
| `parent_id` | integer | да | |
| `period_year` | integer | нет | по умолчанию текущий год |
| `amount` | number | да | > 0; возвращается не больше текущего «выделено» подпозиции |

**Ответ `200`:** `{"ok": true, "returned": number}`.

**Ошибки.** 400 «Некорректные параметры отмены»; 404 «Позиция не найдена»; 400 «Закрытый период нельзя менять».

**Пример.** `{"child_id": 40, "parent_id": 16, "period_year": 2026, "amount": 15000000}` → `{"ok": true, "returned": 15000000.0}`.

**Побочные эффекты.** Две записи истории «Отмена переноса». Журнал ИБ `budget_transfer_undone`.

### POST /budget-positions/{item_id}/allocations

**Назначение.** Назначить или изменить бюджет позиции на год, закрыть/открыть период.

**Доступ.** `budget.manage`.

**Параметры пути:** `item_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `period_year` | integer | нет | по умолчанию текущий год |
| `allocated_amount` | number | нет | ≥ 0; по умолчанию 0 |
| `status` | string | нет | `open` (по умолчанию) \| `closed` |
| `comment` | string | нет | комментарий к изменению |

Правила: периода нет — создаётся; период закрыт и остаётся закрытым — сумму менять нельзя (только комментарий); закрытый переоткрывается (`status: open`) — можно сразу с новой суммой; открытый — меняется сумма и статус. Каждое изменение суммы пишется в историю (комментарий или «Назначение бюджета» / «Изменение суммы»).

**Ответ `200`:** `{"item": {id, budget_position_id, period_year, allocated_amount, status, comment}}`.

**Ошибки.** 404 «Бюджетная позиция не найдена»; 400 «Сумма не может быть отрицательной»; 400 «Статус: open или closed»; 400 «Закрытый период нельзя менять».

**Пример.** `{"period_year": 2026, "allocated_amount": 25000000, "comment": "Корректировка по смете"}` → `{"item": {"id": 37, "budget_position_id": 16, "period_year": 2026, "allocated_amount": 25000000.0, "status": "open", "comment": "Корректировка по смете"}}`.

**Побочные эффекты.** История суммы. Журнал ИБ `budget_allocation_changed` (год, сумма, статус).

## Единицы измерения

Справочник единиц (`шт.`, `м²`, `м³`, `компл.` …) для сверки строк Excel в мастере тендера. Название ≤ 50 символов, уникально. **Синонимы**: написание из файла приводится к ключу сопоставления (нижний регистр, без хвостовых точек, пробелов, скобок, `^`, `²`→`2`, `³`→`3`; «квм»/«мкв» → «м2», «кубм»/«мкуб» → «м3»; «м» и «м.п.» остаются разными) и запоминается за единицей — следующие загрузки подставят её сами.

Объект `Unit`: `{id: integer, name: string, is_active: boolean}`.

### GET /units

**Назначение.** Все единицы (включая выключенные) по названию.

**Доступ.** Сотрудник.

**Параметры.** Нет.

**Ответ `200`:** массив `Unit`.

**Ошибки.** 401/403.

**Пример.** → `[{"id": 24, "name": "компл.", "is_active": true}, {"id": 21, "name": "м²", "is_active": true}, {"id": 22, "name": "шт.", "is_active": true}]`.

**Побочные эффекты.** Нет.

### POST /units

**Назначение.** Завести единицу — в том числе оператором прямо на шаге проверки структуры в мастере тендера (поэтому без права справочников). Идемпотентно: единица с таким именем без учёта регистра уже есть — возвращается она.

**Доступ.** Сотрудник.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `name` | string | да | непустое после обрезки, ≤ 50 |

**Ответ `201`:** `Unit` (новая или существующая).

**Ошибки.** 400 «Введите название единицы измерения»; 422.

**Пример.** `{"name": "м.п."}` → `201 {"id": 23, "name": "м.п.", "is_active": true}`.

**Побочные эффекты.** Нет записи в журнал ИБ.

### POST /units/{item_id}/aliases

**Назначение.** Запомнить написание единицы из файла за единицей справочника (выбор оператора перезаписывает прежнюю привязку, в том числе догадку ИИ).

**Доступ.** Сотрудник.

**Параметры пути:** `item_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `alias` | string | да | непустой ключ после нормализации |

**Ответ `201`:** `{"alias_key": string, "unit_id": integer}`. Если ключ совпал с ключом самого имени единицы — синоним не записывается, ответ тот же.

**Ошибки.** 404 «Единица измерения не найдена»; 400 «Введите написание единицы».

**Пример.** `POST /api/units/24/aliases` `{"alias": "Комплект"}` → `201 {"alias_key": "комплект", "unit_id": 24}`. Для единицы «м³» написание «куб.м» даёт ключ «м3» — он совпадает с ключом имени, синоним не нужен и не записывается.

**Побочные эффекты.** Upsert в `unit_aliases` (ключ — одно значение на весь справочник).

### PATCH /units/{item_id}

**Назначение.** Переименовать или выключить единицу.

**Доступ.** `catalogs.manage`.

**Параметры пути:** `item_id` — integer.

**Тело запроса:**

| Поле | Тип | Правило |
|---|---|---|
| `name` | string \| null | пустое после обрезки — без изменений |
| `is_active` | boolean \| null | |

**Ответ `200`:** `Unit`.

**Ошибки.** 404 «Единица измерения не найдена»; 403.

**Пример.** `{"is_active": false}` → `{"id": 25, "name": "м", "is_active": false}`.

**Побочные эффекты.** Нет записи в журнал ИБ.

## Статусы тендеров и КП

Пользовательские статусы — дополнительная пометка поверх системного статуса тендера (`tenders.custom_status_code`) или КП (`quotes.custom_status_code`). Сущность — `tender` или `quote`. **Код** (латиница, цифры, `_`, ≤ 50) не меняется никогда: он записан в данных строкой; переименование — это `label`. Цвет — один из смысловых тонов интерфейса: `info`, `success`, `warning`, `danger`, `neutral` (прежние произвольные значения в данных показываются нейтральным тоном). Порядок — `order_index` шагом 10. Системные статусы (`is_system`) можно переименовать, нельзя удалить.

Объект `Status`: `{id, entity_type, code, label, color, is_system, is_active, order_index}`.

### GET /statuses

**Назначение.** Действующие статусы (по сущности и порядку); с `include_archived=true` — и снятые (для подписей уже размеченных записей и раздела «Архив»).

**Доступ.** Сотрудник.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `entity_type` | string | — (обе) | `tender` \| `quote`; иное значение даёт пустой список |
| `include_archived` | boolean | `false` | включать снятые |

**Ответ `200`:** `{"items": Status[]}`, порядок — сущность, `order_index`, id.

**Ошибки.** 401/403.

**Пример.** → `{"items": [{"id": 2, "entity_type": "quote", "code": "clarification", "label": "Уточнение у подрядчика", "color": "info", "is_system": false, "is_active": true, "order_index": 110}, {"id": 1, "entity_type": "tender", "code": "budget_check", "label": "Проверка бюджета", "color": "warning", "is_system": false, "is_active": true, "order_index": 110}]}`.

**Побочные эффекты.** Нет.

### POST /statuses

**Назначение.** Завести статус в конец списка своей сущности. Код необязателен — выводится транслитом из названия («Ждём документы» → `zhdem_dokumenty`), при совпадении (в том числе со снятым статусом) получает суффикс `_2`, `_3`…

**Доступ.** `catalogs.manage`.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `entity_type` | string | да | `tender` \| `quote` |
| `label` | string | да | непустое, ≤ 60; уникально среди действующих статусов сущности |
| `color` | string \| null | нет | тон из списка или пусто |
| `code` | string | нет | приводится к коду; явно заданный занятый код — ошибка |

**Ответ `201`:** `{"item": Status}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | неверная сущность | «Статус бывает у тендера или у КП» |
| 400 | пустое название | «Введите название статуса» |
| 400 | длиннее 60 | «Название статуса — не длиннее 60 символов» |
| 400 | неизвестный цвет | «Неизвестный цвет статуса» |
| 409 | название занято | «Статус с таким названием уже есть» |
| 409 | явный код занят | «Такой код уже есть» |

**Пример.** `{"entity_type": "tender", "label": "Ждём документы", "color": "warning"}` → `201 {"item": {"id": 3, "entity_type": "tender", "code": "zhdem_dokumenty", "label": "Ждём документы", "color": "warning", "is_system": false, "is_active": true, "order_index": 120}}`.

**Побочные эффекты.** Нет записи в журнал ИБ.

### PUT /statuses/order

**Назначение.** Задать порядок действующих статусов одной сущности **целиком** (защита от перемешивания при правке из двух вкладок).

**Доступ.** `catalogs.manage`.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `entity_type` | string | да | `tender` \| `quote` |
| `ids` | integer[] | да | ровно множество id действующих статусов сущности, без повторов |

**Ответ `200`:** `{"items": Status[]}` — действующие статусы сущности в новом порядке (`order_index` = 10, 20, 30…).

**Ошибки.** 400 «Статус бывает у тендера или у КП»; 400 «Передайте ids — список статусов в нужном порядке»; 400 «ids — числа»; 409 «Список статусов изменился — обновите страницу».

**Пример.** `{"entity_type": "tender", "ids": [3, 1]}` → `{"items": [{"id": 3, …, "order_index": 10}, {"id": 1, …, "order_index": 20}]}`.

**Побочные эффекты.** Нет.

### PATCH /statuses/{status_id}

**Назначение.** Переименовать, перекрасить, переставить или вернуть снятый статус (возвращённый встаёт в конец списка).

**Доступ.** `catalogs.manage`.

**Параметры пути:** `status_id` — integer.

**Тело запроса** (только присланные поля; `code` не принимается):

| Поле | Тип | Правило |
|---|---|---|
| `label` | string | как при создании, уникально среди действующих (кроме себя) |
| `color` | string \| null | тон или пусто |
| `order_index` | integer | число |
| `is_active` | boolean | `true` для снятого — вернуть (если название не занято действующим) |

**Ответ `200`:** `{"item": Status}`.

**Ошибки.** 404 «Статус не найден»; 400 (тексты названия/цвета); 400 «order_index должен быть числом»; 409 «Статус с таким названием уже есть»; 409 «Действующий статус с таким названием уже есть — переименуйте один из них».

**Пример.** `PATCH /api/statuses/1` `{"label": "Согласование бюджета"}` → `{"item": {"id": 1, …, "label": "Согласование бюджета"}}`.

**Побочные эффекты.** Нет.

### DELETE /statuses/{status_id}

**Назначение.** Снять статус (архив): пропадает из выбора, но подписывает уже размеченные записи. Повторный вызов допустим.

**Доступ.** `catalogs.manage`.

**Параметры пути:** `status_id` — integer.

**Ответ `200`:** `{"ok": true}`.

**Ошибки.** 404 «Статус не найден»; 400 «Системный статус нельзя удалить».

**Пример.** `DELETE /api/statuses/3` → `{"ok": true}`.

**Побочные эффекты.** Нет. Записи, помеченные статусом, не меняются (сколько их — `GET /statuses/usage`).

## Дефолты вида работ в объекте

Для пары «объект × вид работ» хранятся даты сбора КП по умолчанию и привязанный шаблон тендера; мастер создания тендера подставляет их как подсказку при выборе объекта и вида работ (не навязывает). Одна запись на пару.

Объект `WorkTypeConfig`: `{project_id, work_type_id, collect_from: "YYYY-MM-DD" | null, collect_to: "YYYY-MM-DD" | null, template_id: integer | null}`.

### GET /projects/{project_id}/work-type-configs

**Назначение.** Все дефолты видов работ объекта.

**Доступ.** Вошедший с доступом к объекту (администратор — любой; остальные — по грантам). Контрагенту и пользователю без грантов — 403.

**Параметры пути:** `project_id` — integer.

**Ответ `200`:** `{"items": WorkTypeConfig[]}`.

**Ошибки.** 403 «Нет доступа к этому проекту»; 401.

**Пример.** → `{"items": [{"project_id": 21, "work_type_id": 16, "collect_from": "2026-09-08", "collect_to": "2026-10-02", "template_id": 1}]}`.

**Побочные эффекты.** Нет.

### PUT /projects/{project_id}/work-type-configs/{work_type_id}

**Назначение.** Создать или изменить дефолты пары «объект × вид работ».

**Доступ.** Вошедший с доступом к объекту (отдельное право не проверяется).

**Параметры пути:** `project_id`, `work_type_id` — integer.

**Тело запроса** (применяются только присланные ключи):

| Поле | Тип | Правило |
|---|---|---|
| `collect_from` | string \| null | дата `YYYY-MM-DD`; пусто или неразборчиво — сбрасывается в `null` |
| `collect_to` | string \| null | то же |
| `template_id` | integer \| null | существующий шаблон тендера; `null` — отвязать |

**Ответ `200`:** `{"item": WorkTypeConfig}`.

**Ошибки.** 404 «Проект не найден»; 403 «Нет доступа к этому проекту»; 404 «Шаблон не найден».

**Пример.** `PUT /api/projects/21/work-type-configs/8` `{"collect_from": "2026-10-01", "collect_to": "2026-10-22", "template_id": null}` → `{"item": {"project_id": 21, "work_type_id": 8, "collect_from": "2026-10-01", "collect_to": "2026-10-22", "template_id": null}}`.

**Побочные эффекты.** Нет записи в журнал ИБ.
