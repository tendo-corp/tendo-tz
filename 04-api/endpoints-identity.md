# API: вход, пользователи, права, лиды (auth, users, permissions, leads)

Ручки входа и сессии (пароль, второй фактор TOTP, refresh, выход, восстановление и первичная установка пароля), профиль текущего пользователя и его галочки уведомлений, реестр пользователей для администратора с доступом к портфелям и объектам, матрица «роль × действие» и публичная заявка с лендинга. Общие правила (cookie, CSRF, формат ошибок, лимиты частоты) — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/identity.md](../02-business-logic/identity.md), уведомления — [../02-business-logic/notifications.md](../02-business-logic/notifications.md); экраны — [../03-screens/login.md](../03-screens/login.md), [../03-screens/reset-password.md](../03-screens/reset-password.md), [../03-screens/welcome.md](../03-screens/welcome.md), [../03-screens/profile.md](../03-screens/profile.md), [../03-screens/users.md](../03-screens/users.md), [../03-screens/settings.md](../03-screens/settings.md) (матрица прав); журнал ИБ — [endpoints-security.md](endpoints-security.md); гранты портфелей — [endpoints-portfolios.md](endpoints-portfolios.md).

### Пароли и одноразовые ссылки

- Политика пароля — [overview.md §7](overview.md#7-валидация); тексты отказов: «Пароль не должен начинаться или заканчиваться пробелом», «Пароль должен быть не короче 8 символов», «Пароль должен быть не длиннее 64 символов», «Пароль слишком длинный: кириллица считается за два символа, сократите его», «Пароль должен содержать символы минимум трёх категорий: строчные, прописные, цифры, спецсимволы», «Этот пароль слишком распространён — придумайте другой», «Пароль состоит из повторяющихся символов — придумайте другой», «Пароль не должен повторять email», «Пароль не должен повторять имя пользователя».
- Хеш пароля — bcrypt; история — 5 последних хешей; новый пароль не может совпадать с текущим или историей: «Нельзя повторно использовать недавний пароль».
- Ссылки активации (72 ч) и восстановления (2 ч) — одна таблица одноразовых токенов (в БД — SHA-256 токена), токен 32 байта в base64url. Ссылка активации: `<PUBLIC_APP_URL>/login?activation_token=<токен>&email=<email>`; восстановления: `<PUBLIC_APP_URL>/reset-password?token=<токен>`.

### POST /auth/login

**Назначение.** Вход по email и паролю. Открывает сессию (cookie `tendo_at` + `tendo_rt`) либо, если у пользователя включена MFA, выдаёт cookie шага второго фактора и просит код.

**Доступ.** Публично. Лимит 20 запросов / 60 с на IP (fail-closed), проверка `Origin`.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `email` | string | да | мягкая нормализация входа: обрезка, нижний регистр, `@` и точка в домене, без пробелов; иначе 422 «Укажите email» / «Укажите корректный email» |
| `password` | string | да | без ограничений длины на входе |

**Ответ `200`:** `{"mfa_required": boolean}`; токенов в теле нет.
- `false` — сессия открыта: `Set-Cookie: tendo_at`, `tendo_rt`; cookie `tendo_mfa` снимается.
- `true` — нужен код: `Set-Cookie: tendo_mfa` (5 мин), следующий шаг — `POST /auth/login/mfa`.

Алгоритм: проверка паузы по паре «email + IP» → поиск учётки → сверка bcrypt (при отсутствии учётки сверяется с заглушкой, чтобы время ответа не выдавало наличие адреса) → при неудаче регистрация неудачи и 401 → отключённая учётка (403) → приостановленная организация контрагента (403) → сброс паузы, `last_login_at` → MFA включена и `MFA_ENFORCED` → челлендж; иначе сессия.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 401 | неверный email или пароль (одинаково для несуществующего адреса) | «Неверный email или пароль» |
| 403 | верный пароль, учётка отключена | «Учётная запись отключена. Обратитесь к администратору системы.» |
| 403 | организация контрагента приостановлена | «Доступ организации приостановлен. Обратитесь к администратору системы.» |
| 429 | пауза по паре «email + IP» (с 5-й неудачи подряд: 1, 2, 4 … ≤ 60 мин) | «Слишком много неудачных попыток входа. Повторите через N мин.», заголовок `Retry-After` |
| 429 | лимит по IP | «Слишком много запросов — попробуйте немного позже» |
| 503 | БД счётчиков недоступна | «Сервис временно недоступен — попробуйте позже» |
| 403 | чужой `Origin` | «Запрос с чужого источника отклонён» |
| 422 | нет полей / форма email | массив ошибок |

**Пример.** `POST /api/auth/login` `{"email": "user@example.com", "password": "********"}` → `200 {"mfa_required": false}` + cookie.

**Побочные эффекты.** Журнал ИБ: `login_failed` (с `details.email` или `details.reason`: `account_disabled`, `org_suspended`), `login_success`. Запись паузы входа; строка `auth_sessions` или `login_challenges`; `users.last_login_at`.

### POST /auth/login/check-email

**Назначение.** Первый шаг двухшагового входа (сначала email, потом пароль). Ответ одинаков для любого адреса, чтобы нельзя было перебором выяснить, есть ли учётка; первый вход приглашённого идёт только по ссылке активации.

**Доступ.** Публично. Лимит 30 / 60 с на IP. `Origin` не проверяется.

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `email` | string | да | мягкая нормализация (как у входа) |

**Ответ `200`:** `{"next_step": "enter_password"}` — всегда.

**Ошибки.** 422 — форма email («Value error, Укажите корректный email»); 429.

**Пример.** `{"email": "user@example.com"}` → `{"next_step": "enter_password"}`.

**Побочные эффекты.** Нет.

### POST /auth/login/set-initial-password

**Назначение.** Установка первого пароля приглашённым пользователем по токену из письма активации (тот же механизм одноразовых токенов, что у восстановления). Сессию не открывает — после успеха пользователь входит обычным способом.

**Доступ.** Публично, по токену. Лимит 20 / 3600 с на IP (общий с `password-reset/confirm`, fail-closed).

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `email` | string | да | мягкая нормализация; для поиска учётки **не используется** (решает токен) |
| `token` | string | да | токен из ссылки (`activation_token`), пробелы по краям обрезаются |
| `new_password` | string | да | ≥ 1 символа по схеме; полная политика пароля проверяется с учётом email и ФИО учётки |

**Ответ `200`:** `{"ok": true}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | токена нет, он использован или истёк | «Ссылка недействительна или истекла. Запросите новую ссылку активации от администратора.» |
| 403 | учётка удалена или отключена | «Учётная запись отключена. Обратитесь к администратору системы.» |
| 400 | пароль не прошёл политику | текст политики |
| 429 / 503 | лимит / БД счётчиков недоступна | |
| 422 | нет полей | |

**Пример.** `{"email": "user@example.com", "token": "Xy…", "new_password": "********"}` → `{"ok": true}`.

**Побочные эффекты.** Хеш пароля, история = [новый хеш], сброс счётчика неудач и `locked_until`, токен помечен использованным, **все сессии пользователя закрываются** (причина `password_changed`). Журнал ИБ `initial_password_set`.

### POST /auth/login/mfa

**Назначение.** Второй шаг входа: обмен кода TOTP на сессию.

**Доступ.** Cookie `tendo_mfa` (выдаёт `POST /auth/login`). Лимит 10 / 60 с на IP (fail-closed), проверка `Origin`.

**Параметры.** Нет (челлендж — из cookie).

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `code` | string | да | 6 цифр; иное считается неверным кодом |

**Ответ `200`:** `{"mfa_required": false}` + `Set-Cookie: tendo_at`, `tendo_rt`; `tendo_mfa` снимается.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 401 | нет cookie, челлендж не найден, использован или старше 5 мин; пользователь удалён | «Время на ввод кода вышло — войдите заново» |
| 403 | учётка отключена (челлендж гасится) | «Учётная запись отключена. Обратитесь к администратору системы.» |
| 400 | неверный код, попытки остались | «Неверный код подтверждения. Осталось попыток: N» |
| 401 | исчерпаны 5 попыток (челлендж гасится) | «Слишком много неверных кодов — войдите заново» |
| 429 / 503 / 403 Origin / 422 | | |

**Пример.** `{"code": "123456"}` → `{"mfa_required": false}`.

**Побочные эффекты.** Челлендж погашен; `users.mfa_last_counter` = номер шага принятого кода; новая сессия. Журнал ИБ: `login_failed` (`reason: mfa_invalid`), `login_success` (`mfa: true`).

### POST /auth/refresh

**Назначение.** Новый JWT доступа по refresh-cookie с ротацией самого refresh; продлевает скользящий срок простоя сессии. Правила окна гонки 30 с и обнаружения повторного использования — [overview.md §2.3](overview.md#23-refresh-токен-и-серверная-сессия).

**Доступ.** Cookie `tendo_rt`. Лимит 120 / 60 с на IP (не fail-closed), проверка `Origin`.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:** `{"ok": true}` + новые `tendo_at` и (кроме случая окна гонки) `tendo_rt`.

**Ошибки.** При 401/403 ответ **снимает все cookie сессии**.

| Код | Когда | `detail` |
|---|---|---|
| 401 | нет cookie | «Не авторизован» |
| 401 | refresh неизвестен, сессия отозвана, или старый refresh позже окна гонки (сессия закрывается) | «Сессия завершена. Войдите заново.» |
| 401 | истёк срок простоя или потолок сессии | «Сессия завершена из-за неактивности. Войдите снова.» |
| 403 | пользователь отключён (сессия закрывается) | «Учётная запись отключена. Обратитесь к администратору системы.» |
| 429 / 403 Origin | | |

**Пример.** `POST /api/auth/refresh` → `200 {"ok": true}`.

**Побочные эффекты.** Ротация хеша refresh, `rotated_at`, `last_used_at`, IP. Журнал ИБ: `session_reuse_detected`, `session_idle_timeout`.

### POST /auth/logout

**Назначение.** Закрыть сессию текущего устройства и снять cookie. Идемпотентно: без cookie тоже 200.

**Доступ.** Публично (сессия не требуется), проверка `Origin`.

**Параметры.** Нет. **Тело.** Нет.

**Ответ `200`:** `{"ok": true}`; cookie `tendo_at`, `tendo_rt`, `tendo_mfa` снимаются всегда, даже если закрыть сессию не удалось.

**Ошибки.** 403 — чужой `Origin`.

**Пример.** → `{"ok": true}`.

**Побочные эффекты.** Сессия по refresh (текущему или предыдущему) и по `sid` из JWT отзывается (причина `logout`). Журнал ИБ `logout`.

### POST /auth/logout-all

**Назначение.** «Выйти на всех устройствах»: закрыть все сессии пользователя, включая текущую.

**Доступ.** Вошедший.

**Параметры.** Нет. **Тело.** Нет.

### POST /auth/password-reset/request

**Назначение.** Запрос письма со ссылкой восстановления. Ответ всегда одинаков — не раскрывает, есть ли учётка.

**Доступ.** Публично. Лимит 5 / 3600 с на IP (fail-closed) и не более 3 писем на один адрес в час (сверх — тот же ответ без письма).

**Параметры.** Нет.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `email` | string | да | мягкая нормализация |

**Ответ `200`:** `{"ok": true, "message": "Если учётная запись существует, мы отправили письмо со ссылкой."}`.

**Ошибки.** 422 (форма email); 429; 503.

**Пример.** `{"email": "user@example.com"}` → ответ выше.

**Побочные эффекты.** Журнал ИБ `password_reset_requested` (с адресом) — всегда. Если учётка есть, активна и лимит на адрес не исчерпан: токен на 2 ч и письмо «Восстановление пароля — тендерная площадка» (текст и HTML) со ссылкой `<PUBLIC_APP_URL>/reset-password?token=…`, пометкой «действует 2 ч., одноразовая» и фразой «Если вы не запрашивали сброс — просто проигнорируйте это письмо.». Отключённой учётке письмо не уходит.

### POST /users/{user_id}/activation

**Назначение.** Выдать ссылку активации заново (потерялось письмо или ответ `POST /users`). Прежние неиспользованные ссылки гасятся — действует одна.

**Доступ.** `users.manage`.

**Параметры пути:** `user_id` — integer. **Тело.** Нет.

**Ответ `200`:** `{"activation_link": "<PUBLIC_APP_URL>/login?activation_token=…&email=…"}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | нет пользователя | «Пользователь не найден» |
| 400 | пароль уже задан | «Пользователь уже активирован — пароль меняется восстановлением, а не ссылкой активации» |
| 400 | учётка отключена | «Учётная запись отключена — сначала включите её» |

**Пример.** → `{"activation_link": "https://<домен>/login?activation_token=…&email=user@example.com"}`.

**Побочные эффекты.** Новый токен (72 ч); письмо «Активация учётной записи — <BRAND_NAME>» с текстом «Ссылка активации выдана заново (действует 72 ч.)… Прежние ссылки больше не работают.». Журнал ИБ `user_activation_reissued`.

### POST /users/{user_id}/mfa/reset

**Назначение.** Сброс второго фактора другого пользователя (потерян телефон). Самому себе — нельзя (иначе обходится запрет отключать MFA администратору).

**Доступ.** `users.manage` + заголовок `X-Reauth-Password` с паролем действующего администратора.

**Параметры пути:** `user_id` — integer. **Тело.** Нет.

**Ответ `200`:** `{"mfa_enabled": false}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 403 | нет заголовка | «Подтвердите действие паролем» |
| 403 | неверный пароль | «Пароль не подошёл — действие не выполнено» |
| 400 | сброс своей MFA | «Сбросить свою MFA нельзя — попросите другого администратора» |
| 404 | нет пользователя | «Пользователь не найден» |
| 400 | у пользователя нет ни включённой MFA, ни секрета | «У пользователя не настроена MFA» |

**Пример.** `POST /api/users/2/mfa/reset` с `X-Reauth-Password: ********` → `{"mfa_enabled": false}`.

**Побочные эффекты.** `mfa_enabled = false`, секрет удалён (администратор при следующем запросе будет направлен на настройку). Журнал ИБ `mfa_reset` (с email цели).

### POST /users/{user_id}/unlock

**Назначение.** Снять блокировку учётной записи (поля `locked_until` и счётчик неудачных попыток) без ожидания таймера.

**Доступ.** `users.manage`.

**Параметры пути:** `user_id` — integer. **Тело.** Нет.

**Ответ `200`:** `{"item": UserView}`.

**Ошибки.** 404 «Пользователь не найден»; 400 «Учётная запись не заблокирована» — `locked_until` не в будущем и счётчик неудач = 0.

**Пример.** → `{"item": {…, "status": "active", "failed_login_attempts": 0}}`.

**Побочные эффекты.** Журнал ИБ `account_unlocked` (`failed_attempts`, `was_locked`). Паузу входа по паре «email + IP» ручка не снимает — в текущей системе учётка при неудачных входах не блокируется, и статус `locked` практически не возникает (см. открытые вопросы).

### PUT /users/{user_id}/access

**Назначение.** Переписать гранты пользователя целиком. Доступный пользователю набор объектов = объекты из грантов на портфели + объекты из грантов на объект + все их подобъекты + путь до корня (чтобы узел не оказался «осиротевшим» в дереве). Администратор видит всё без грантов.

**Доступ.** `users.manage`.

**Параметры пути:** `user_id` — integer.

**Тело запроса:**

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `portfolio_ids` | integer[] | нет (пусто — снять все) | гранты на портфели |
| `project_ids` | integer[] | нет | гранты на объекты |

**Ответ `200`:** `{"portfolio_ids": [...], "project_ids": [...]}` — как сохранено (без дублей).

**Ошибки.** 404 «Пользователь не найден»; 403.

**Пример.** `{"portfolio_ids": [13], "project_ids": [24]}` → то же.

**Побочные эффекты.** Журнал ИБ `project_access_changed` (оба списка). Доступ меняется со следующего запроса; открытый поток SSE пользователя подхватит новые объекты при переподключении.

### PUT /permissions/matrix

**Назначение.** Сохранить изменённые строки матрицы одной транзакцией: всё или ничего.

**Доступ.** `users.manage`.

**Параметры.** Нет.

**Тело запроса:** `{"roles": {"<код роли>": ["<действие>", …], …}}`. Незнакомые коды действий молча отбрасываются.

**Ответ `200`:** матрица целиком (как `GET /permissions/matrix`).

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | `roles` не словарь списков | «Ожидается словарь «роль → список действий» в поле roles» |
| 400 | в теле заблокированная роль | текст блокировки роли |
| 404 | роли нет | «Роль '<код>' не найдена» |

**Пример.** `{"roles": {"lawyer": ["suppliers.contacts.view", "reports.view"]}}` → матрица.

**Побочные эффекты.** Событие журнала ИБ `role_permissions_changed` на каждую изменённую роль (`role`, `added`, `removed`). Права действуют со следующего запроса всех носителей роли.

### POST /leads

**Назначение.** Заявка на демо с маркетингового лендинга. Лид сразу становится пользователем с ролью `lead` (прав нет) и получает письмо со ссылкой активации; после входа он видит экран ожидания `/welcome`, пока администратор не назначит настоящую роль. Команде (носителям `users.manage`) уходит письмо.

**Доступ.** Публично. Ручка есть только при `LEADS_ENABLED=true`: иначе — 404 «Not Found» до лимита частоты, и в схеме OpenAPI её нет. Лимит 20 / 3600 с на IP. Защита от ботов — скрытое поле-ловушка.

**Параметры.** Нет.

**Тело запроса** (произвольный JSON; невалидный JSON трактуется как пустой объект):

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `name` | string | да | имя и должность; обрезается до 255 |
| `email` | string | да | строгая проверка email |
| `company` | string | нет | до 255 |
| `volume` | string | нет | объём закупок в год, до 64 |
| `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` | string | нет | до 255 каждый |
| `hp_website` | string | нет | поле-ловушка: заполнено — заявка молча игнорируется |

**Ответ `200`:** `{"ok": true, "created": boolean}` — всегда успех, в том числе для уже существующего адреса и для ловушки (`created: false`), чтобы форма не позволяла проверять наличие адресов.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | нет имени / неверный email | `{"error": "Проверьте заполнение формы", "fieldErrors": {"name": "Укажите, как к вам обращаться", "email": "Укажите email"}}` |
| 400 | роль `lead` не заведена в БД | «Роль лида не заведена — обратитесь к администратору системы» |
| 404 | `LEADS_ENABLED=false` | «Not Found» |
| 429 | лимит | |

**Пример.** `{"name": "Петрова Анна, руководитель закупок", "email": "user@example.com", "company": "ООО «Пример»", "volume": "до 100 млн", "utm_source": "ads"}` → `{"ok": true, "created": true}`.

**Побочные эффекты.** Пользователь (`role = lead`, `source = landing`, без пароля); журнал ИБ `lead_submitted` (`duplicate`, компания, объём, utm) — и для дубля; письмо лиду «Активация учётной записи — <BRAND_NAME>» с текстом «Вы оставили заявку на демо <BRAND_NAME> — мы уже получили её. Учётная запись создана. Продуктом можно будет пользоваться, когда мы подтвердим заявку и откроем доступ…»; письмо держателям `users.manage` «Заявка с лендинга — <имя>» с полями заявки и ссылкой `<PUBLIC_APP_URL>/users?user=<id>`. Для дубля и ловушки писем нет.
