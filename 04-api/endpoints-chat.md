# API: переписка (chats)

Ручки чата «тендер × контрагент»: тред на пару «тендер × контрагент», протокол синхронизации из трёх операций (снапшот списка, история вверх по курсору, дельта по глобальному курсору событий), отправка с идемпотентностью и вложениями, правка/удаление в окне 15 минут, «печатает…», прочитанность по курсору, поиск и выгрузка в Markdown, мост «комментарий ячейки СТ → чат». Отдельный публичный контур `/chats/invite/{token}/*` — переписка контрагента по ссылке-приглашению без учётной записи, включая собственный SSE-поток. Общие соглашения (аутентификация, `Origin`, формат ошибок, общий SSE-поток `GET /notifications/stream`) — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/chat.md](../02-business-logic/chat.md); экран — [../03-screens/chats.md](../03-screens/chats.md); комментарии ячеек СТ — [endpoints-comments.md](endpoints-comments.md); загрузка/скачивание файлов в ЛК — `endpoints-files.md` (API-1).

## Модель и ключевые правила

- **Тред** — один на пару «тендер × контрагент» (уникальность в БД). При создании в тред пишется системная реплика «Диалог открыт.».
- **Стороны:** `specialist` (любой сотрудник), `supplier` (пользователь ЛК контрагента или контрагент по ссылке), `system`.
- **Номер события `event_seq`** — из одной глобальной последовательности на все треды. Правка и удаление реплики получают новый номер `edited_seq` из той же последовательности. **Курсор** клиента — максимальный выданный номер (создания или правки); одно число описывает состояние всех переписок зрителя.
- **Видимость тредов** (одни и те же предикаты для списка, дельты, поиска, выгрузки):
  - администратор — все треды;
  - другой сотрудник — треды тендеров его доступных объектов (гранты на портфель/объект с подобъектами); без грантов — ничего;
  - поставщик — треды своей организации **по тендерам с действующим (не отозванным) приглашением**.
  - роль, организация и доступные объекты зрителя кэшируются в памяти процесса на 30 с: выданный/отозванный доступ применяется с этой задержкой.
- **Сотруднику приглашение контрагента не нужно**: можно написать любому контрагенту из справочника по доступному тендеру. Контрагент пишет только по своим приглашениям.
- **Прочитанность** — на человека (для контрагента по ссылке — на приглашение), курсором «прочитано до события N»; отметка только растёт. Для пометки «прочитано» (✓✓) у отправителя хранится агрегат стороны: сторона-собеседник дочитала до N.
- **Непрочитанное** = число реплик другой стороны (без системных) после своей отметки; удаление реплики счётчик не уменьшает.
- **Лимиты:** реплика ≤ 4000 символов; вложение ≤ 25 МБ, разрешённые типы — PNG, JPEG, GIF, WEBP, PDF, DOC, DOCX, XLS, XLSX, ZIP, TXT, CSV, тип обязан совпадать с сигнатурой содержимого (кроме TXT, CSV, WEBP); имя файла санируется, ≤ 200 символов. Частота под сессией: отправка/правка/удаление/мост — 30 в минуту на пользователя, открытие треда — 10 в минуту.

### Объект `Message`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | id реплики (строкой) |
| `event_seq` | integer | номер события создания; порядок ленты |
| `author` | string | `specialist` \| `supplier` \| `system` |
| `author_name` | string | ФИО автора; без имени — «Система», «Поставщик» или «Специалист» |
| `author_user_id` | integer \| null | пользователь-автор (`null` у системы и у контрагента по ссылке) — для меню «Изменить/Удалить» |
| `edited` | boolean | реплика правилась |
| `deleted` | boolean | удалена (текст и вложение тогда пустые) |
| `text` | string | текст; для реплики только с файлом — «📎 <имя>» |
| `created_at` | string | ISO 8601 UTC (`…Z`) |
| `attachment` | object \| null | `{id, name, size, content_type, is_image}` |
| `kind` | string | `message` \| `system` |
| `client_msg_id` | string \| null | ключ идемпотентности клиента (UUID) |
| `reply_to` | object \| null | цитата: `{id, event_seq, author, text}` (текст ≤ 200 символов; у удалённой — «Сообщение удалено») |
| `cell` | object \| null | мост ячейки СТ: `{kind: cell_thread\|cell_quote\|review, quote_item_id, comment_id}` |
| `read` | boolean | сторона-собеседник дочитала до этой реплики |

### Объект `Thread`

| Поле | Тип | Смысл |
|---|---|---|
| `id` | string | id треда (строкой; пустая строка у ещё не созданного треда в контуре по ссылке) |
| `tender_id` / `tender_title` | integer / string | тендер |
| `supplier_id` / `supplier_name` | integer / string | контрагент (короткое или юридическое название) |
| `messages` | Message[] | лента (последние 50) — только когда она запрошена; иначе `[]` |
| `updated_at` | string \| null | ISO UTC последней активности |
| `unread` | integer | непрочитанное зрителя |
| `last_preview` | string | превью последней реплики (≤ 120 символов; «Сообщение удалено») |
| `last_seq` | integer | `event_seq` последней реплики |
| `has_more` | boolean | в ленте есть более ранние реплики |

### Realtime: от отправки до экрана собеседника

Чат не имеет своего постоянного канала у вошедших пользователей: события едут в общем SSE-потоке топбара `GET /notifications/stream` (описан в [overview.md](overview.md), раздел API-1). У контрагента по ссылке — свой поток `GET /chats/invite/{token}/stream`. События **тонкие**: вид, тред, номер — без текста (лимит `NOTIFY` 8000 байт, текст не должен попадать в логи прокси). Текст клиент забирает дельтой.

Адресация событий шины:

| Ключ | Кто слушает |
|---|---|
| `chat:p<id объекта>` | сотрудники с доступом к объекту тендера |
| `chat:all` | администраторы |
| `supplier:<id контрагента>` | все пользователи ЛК контрагента и потоки по его ссылкам |
| `staff:<user_id>` | конкретный сотрудник (его отметка «прочитано» для других вкладок) |

Виды событий чата (`type: "chat"`): `msg` (новая/изменённая/удалённая реплика; поля `thread_id`, `seq`, `cursor`, `side`), `read` (сторона `side` дочитала до `seq`), `typing` (сторона `side` набирает, `name` ≤ 80 символов; только противоположной стороне). При переподключении слушателя Postgres всем подписчикам рассылается `resync`.

```mermaid
sequenceDiagram
    autonumber
    participant A as Клиент автора
    participant API as API (любой процесс)
    participant DB as PostgreSQL
    participant L as LISTEN-слушатель (в каждом процессе)
    participant S as SSE-поток адресата
    participant B as Клиент адресата
    A->>API: POST /chats/{id}/messages {text, client_msg_id}
    API->>DB: BEGIN; повтор client_msg_id? → вернуть существующую
    API->>DB: INSERT chat_messages (event_seq = nextval(chat_event_seq))
    API->>DB: курсор прочтения автора = seq; уведомление/письмо (задание)
    API->>DB: SELECT pg_notify('app_realtime', {keys, type:chat, kind:msg, thread_id, seq, cursor, side})
    API->>DB: COMMIT (NOTIFY доставляется только при коммите)
    API-->>A: 201 {item, thread_id, created, cursor}
    DB-->>L: NOTIFY payload
    L->>S: положить событие в очереди подписчиков с этими ключами
    S-->>B: data: {..., chats_cursor / events:[{kind:msg, seq}]}
    B->>API: GET /chats/updates?since=<свой курсор>
    API->>DB: реплики видимых тредов с event_seq или edited_seq > since−20
    API-->>B: {reset:false, cursor, messages[], threads[]}
    Note over B: дедупликация по id, замена изменённых
    B->>API: POST /chats/{id}/read {up_to_seq}
    API->>DB: GREATEST(last_read_seq, up_to_seq) + pg_notify(kind:read)
    Note over S,B: обрыв соединения
    B->>S: переподключение через retry: 3000 мс
    S-->>B: первый кадр: снимок / {type:chat, cursor:N}
    B->>API: GET /chats/updates?since=<последний известный курсор>
    alt отставание > 300 событий
        API-->>B: {reset:true, cursor} → клиент перечитывает GET /chats
    else
        API-->>B: пропущенные реплики и состояния тредов
    end
```

Правила догона:
- дельта считается из БД, «окна» нет: курсор любой давности валиден;
- сервер отдаёт события начиная с `since − 20` (нахлёст): номер выдаётся при вставке, а виден становится при коммите, и параллельные отправки могут закоммититься не по порядку номеров; повторы клиент отсеивает по `id`;
- больше 300 событий — `reset: true`, клиент перечитывает снапшот;
- потеря отдельного кадра SSE ничего не ломает: каждый кадр — повод перечитать, а не источник данных.

### GET /chats

**Назначение.** Снапшот списка диалогов зрителя: превью, непрочитанное, курсор для последующей дельты. Страница по ключу `(updated_at, id)`, свежие сверху.

**Доступ.** Любой вошедший; состав — по правилам видимости.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения / смысл |
|---|---|---|---|
| `tender_id` | integer | — | только треды тендера (фильтр на сервере) |
| `limit` | integer | 50 | 1–200 |
| `before` | string | — | ≤ 80 символов; непрозрачный ключ страницы из `next` предыдущего ответа |
| `with_messages` | integer | 0 | 0 \| 1; 1 — вложить ленты (последние 50 реплик каждого треда); оставлено для совместимости |

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `items` | Thread[] | треды страницы |
| `next` | string \| null | ключ следующей страницы (`before`) или `null` |
| `unread_total` | integer | сумма непрочитанного **по странице** |
| `cursor` | integer | текущий глобальный курсор событий |
| `side` | string | сторона зрителя: `specialist` \| `supplier` |

**Ошибки.** 400 «Некорректный ключ страницы»; 401; 422.

**Пример.**

```json
{"items": [{"id": "70", "tender_id": 103, "tender_title": "Витражи и окна, корпус 3", "supplier_id": 204,
  "supplier_name": "Дельта Стекло", "messages": [], "updated_at": "2026-09-24T09:10:00Z", "unread": 1,
  "last_preview": "Добрый день! Возможно ли посещение площадки 30.09?", "last_seq": 68, "has_more": false}],
 "next": "2026-09-24T09:10:00+00:00|70", "unread_total": 1, "cursor": 71, "side": "specialist"}
```

**Побочные эффекты.** Нет.

### GET /chats/updates

**Назначение.** Всё новое во **всех** видимых тредах после курсора одним запросом: новые, изменённые и удалённые реплики + состояние затронутых тредов.

**Доступ.** Любой вошедший; по правилам видимости.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `since` | integer | 0 | ≥ 0; курсор клиента |
| `limit` | integer | 300 | 1–300; больше — `reset` |

**Ответ `200`:**

| Поле | Тип | Смысл |
|---|---|---|
| `reset` | boolean | отставание больше `limit` — перечитать снапшот |
| `cursor` | integer | новый курсор |
| `messages` | `(Message + thread_id)[]` | реплики с `event_seq` или `edited_seq` > `since − 20`, по возрастанию |
| `threads` | `[{id, unread, updated_at, peer_read_seq}]` | состояние затронутых тредов; `peer_read_seq` — докуда дочитала другая сторона |

Если зрителю не видно ни одного треда — `{"reset": false, "cursor": 0, "messages": [], "threads": []}`.

**Ошибки.** 401; 422.

**Пример.** `GET /api/chats/updates?since=65` →

```json
{"reset": false, "cursor": 71,
 "messages": [{"thread_id": "64", "id": "647", "event_seq": 47, "author": "supplier", "author_name": "Сергеев С. С.",
   "author_user_id": 163, "edited": false, "deleted": false, "text": "КП направлено, прошу подтвердить получение.",
   "created_at": "2026-09-19T10:00:00Z", "attachment": null, "kind": "message", "client_msg_id": null,
   "reply_to": null, "cell": null, "read": true}],
 "threads": [{"id": "64", "unread": 0, "updated_at": "2026-09-19T10:00:00Z", "peer_read_seq": 47}]}
```

**Побочные эффекты.** Нет.

### GET /chats/search

**Назначение.** Поиск по тексту переписки в пределах видимых тредов — полнотекстовый с русской морфологией («сроки монтажа» находит «срок монтажа»), удалённые реплики не ищутся.

**Доступ.** Любой вошедший; по правилам видимости.

**Параметры запроса:**

| Параметр | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `q` | string | да | 2–200 символов |
| `tender_id` | integer | нет | |
| `supplier_id` | integer | нет | |
| `thread_id` | integer | нет | |
| `limit` | integer | нет (50) | 1–100 |

**Ответ `200`:** `{"items": [...], "query": "<q>"}`; элемент — `Message` плюс `thread_id`, `tender_id`, `tender_title`, `supplier_id`, `supplier_name` (для перехода в ленту на нужное место по `event_seq`). Порядок — новые сверху. Поле `read` в результатах поиска всегда `false` (не вычисляется).

**Ошибки.** 401; 422 (длина `q`).

**Пример.** `GET /api/chats/search?q=срок&limit=1` → `{"items": [{"thread_id": "65", "tender_id": 100, "tender_title": "…", "supplier_id": 206, "supplier_name": "Зета Фасад", "id": "653", "event_seq": 62, "author": "supplier", "text": "Цены действительны 30 календарных дней…", …}], "query": "срок"}`

**Побочные эффекты.** Нет.

### GET /chats/{thread_id}/export

**Назначение.** Выгрузить весь диалог документом Markdown — для приложения к делу/спору.

**Доступ.** Доступ к треду (см. «Модель»).

**Параметры пути.** `thread_id` — integer > 0.

**Ответ `200`.** `text/markdown; charset=utf-8`, `Content-Disposition: attachment; filename="chat-<id>.md"`. Структура: заголовок «# Переписка по тендеру «…»»; контрагент, тендер, период (первая — последняя реплика, ISO UTC), число реплик; примечание, что порядок — по номеру события; затем каждая реплика: `### <автор> · <время> · #<event_seq>` (у системной — «(системная запись)»), вложение (имя, тип, размер), текст (символы разметки экранируются), пометки «(изменено …)» / «(удалено автором …)» и **все прежние версии** («Прежняя версия (до правки/до удаления, время)»); в конце — раздел «Вложения».

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | id не число / ≤ 0 | «Некорректный id чата» |
| 404 | треда нет | «Чат не найден» |
| 403 | нет доступа | «Нет доступа к чату» / «Нет приглашения в этот тендер» |
| 401 | нет сессии | |

**Пример.** `GET /api/chats/65/export` → файл `chat-65.md`.

**Побочные эффекты.** Событие журнала ИБ `chat_thread_exported` (`tender_id`, `supplier_id`).

### POST /chats/open

**Назначение.** Открыть тред «тендер × контрагент», создав его при отсутствии (идемпотентно, устойчиво к гонке).

**Доступ.**
- сотрудник — доступ к тендеру (объект в доступных; администратор — любой); приглашение контрагента **не требуется**;
- поставщик — только своя организация и только по тендеру, куда она приглашена и не отозвана.

**Лимит.** 10 в минуту на пользователя → `429` «Слишком много запросов — попробуйте немного позже».

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `tender_id` | integer | да | > 0 |
| `supplier_id` | integer | да | > 0 |

**Ответ `201`:** `{"item": Thread (с лентой), "created": boolean, "cursor": integer}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 403 | поставщик открывает чужой тред | «Нельзя открыть чужой чат» |
| 403 | поставщик не приглашён / отозван | «Нет приглашения в этот тендер» |
| 403 | сотрудник без доступа к объекту | «Нет доступа к проекту этого тендера» |
| 404 | тендера нет | «Тендер не найден» |
| 404 | тендер или контрагент не найден | «Тендер или контрагент не найден» |
| 422 | id ≤ 0 / не число | |
| 429 | лимит | |

**Пример.** `{"tender_id": 100, "supplier_id": 202}` → `{"item": {"id": "61", …, "messages": [{"text": "Диалог открыт.", "kind": "system", …}]}, "created": true, "cursor": 72}`

**Побочные эффекты.** При создании — тред и системная реплика «Диалог открыт.» (получает `event_seq`, но событие шины не публикуется).

### GET /chats/{thread_id}/messages

**Назначение.** Страница истории **вверх**: `limit` реплик строго до `before_seq`, по возрастанию `event_seq`.

**Доступ.** Доступ к треду.

**Параметры:**

| Параметр | Где | Тип | По умолчанию | Ограничения |
|---|---|---|---|---|
| `thread_id` | путь | integer | | > 0 |
| `before_seq` | запрос | integer | 0 | ≥ 0; 0 — последние реплики |
| `limit` | запрос | integer | 50 | 1–200 |

**Ответ `200`:** `{"items": Message[], "has_more": boolean, "cursor": integer}`; `has_more` = страница заполнена целиком.

**Ошибки.** 400 «Некорректный id чата»; 403 «Нет доступа к чату» / «Нет приглашения в этот тендер»; 404 «Чат не найден»; 401; 422.

**Пример.** `GET /api/chats/65/messages?limit=2` → `{"items": [{"id": "652", "event_seq": 61, "author": "supplier", "text": "Позиция «Сборная сэндвич-панель»: объём по файлу КП 9.5175 (в тендере 4.7588)", "cell": {"kind": "cell_quote", "quote_item_id": 17084, "comment_id": null}, …}, {"id": "653", "event_seq": 62, …}], "has_more": true, "cursor": 71}`

**Побочные эффекты.** Нет (прочитанность не меняется).

### POST /chats/{thread_id}/messages

**Назначение.** Отправить реплику текстом и/или с уже загруженным вложением. Ответ — созданная реплика и курсор, а не весь тред.

**Доступ.** Доступ к треду (запись = чтение: отозванный контрагент писать не может).

**Лимит.** 30 в минуту на пользователя.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `text` | string | нет (`""`) | обрезается по краям; ≤ 4000 символов |
| `attachment_id` | integer \| null | нет | вложение, загруженное ранее на этот тред (`entity_type = chat_message`, `entity_id = id треда`) |
| `client_msg_id` | UUID \| null | нет | ключ идемпотентности: повтор возвращает ту же реплику с `created: false` |
| `reply_to_id` | integer \| null | нет | цитируемая реплика |

Нужен текст или файл.

**Ответ `201`:** `{"item": Message, "thread_id": string, "created": boolean, "cursor": integer}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | нет ни текста, ни файла | «Нужен текст или файл» |
| 400 | файл не привязан к этому треду | «Файл не привязан к этому чату» |
| 400 | id треда некорректен | «Некорректный id чата» |
| 403 / 404 | доступ / нет треда | как выше |
| 422 | текст > 4000 | «Сообщение длиннее 4000 символов — отправьте длинный текст файлом» |
| 422 | `client_msg_id` не UUID | стандартная ошибка валидации |
| 429 | лимит частоты | «Слишком много запросов — попробуйте немного позже» |

**Пример.**

```json
{"text": "Подтверждаем получение КП, вопросы направим до пятницы.", "client_msg_id": "5b0c3e8e-2f7a-4c1b-9b0e-0d6c1a2f3e4d"}
```

```json
{"item": {"id": "720", "event_seq": 72, "author": "specialist", "author_name": "Петров Пётр Петрович", "author_user_id": 2,
  "edited": false, "deleted": false, "text": "Подтверждаем получение КП, вопросы направим до пятницы.",
  "created_at": "2026-10-15T08:00:00Z", "attachment": null, "kind": "message",
  "client_msg_id": "5b0c3e8e-2f7a-4c1b-9b0e-0d6c1a2f3e4d", "reply_to": null, "cell": null, "read": false},
 "thread_id": "65", "created": true, "cursor": 72}
```

**Побочные эффекты** (только при `created: true`):
- курсор прочтения автора и агрегат его стороны сдвигаются на номер реплики; `updated_at` треда, счётчик реплик стороны;
- уведомление адресату:
  - сотрудник → контрагент: in-app «Новое сообщение по тендеру» организации контрагента (если тип не отключён в настройках ЛК) и письмо на e-mail контрагента;
  - контрагент → ответственный за тендер: in-app «Сообщение от контрагента» и письмо;
  - письмо ставится фоновой задачей и уходит не чаще одного на разговор за 15 минут (считается от предыдущей реплики треда любой стороны); in-app создаётся всегда;
- запись в ленту активности тендера (`chat_message`);
- событие шины `msg` обеим сторонам (см. «Realtime»);
- событие журнала ИБ `chat_message_created` (`author_role`, `has_attachment`).

### POST /chats/{thread_id}/read

**Назначение.** Отметить тред прочитанным до события `up_to_seq` (курсор, а не «сейчас»): фоновая вкладка не гасит непрочитанное, которого человек не видел.

**Доступ.** Доступ к треду.

**Тело запроса** (необязательное):

| Поле | Тип | Смысл |
|---|---|---|
| `up_to_seq` | integer \| null | прочитано до этого события; `0`/`null`/нет тела — до последней реплики треда |

**Ответ `200`:** `{"ok": true, "item": Thread (без ленты), "last_read_seq": integer}` — фактическая отметка (не меньше прежней).

**Ошибки.** 400 / 403 / 404 — как у истории; 401.

**Пример.** `{"up_to_seq": 68}` → `{"ok": true, "item": {"id": "70", "unread": 0, …}, "last_read_seq": 68}`

**Побочные эффекты.** Отметка `GREATEST(старая, новая)` на человека; агрегат стороны; событие шины `read`: от сотрудника — в его личный ключ и стороне контрагента; от контрагента — его организации и сотрудникам объекта.

### POST /chats/{thread_id}/messages/file

**Назначение.** Отправить реплику с файлом **одной транзакцией** (нет реплики — нет файла; не остаётся файлов-сирот).

**Доступ.** Доступ к треду. Файл читается только после проверки доступа.

**Лимит.** 30 в минуту на пользователя.

**Тело запроса** (`multipart/form-data`):

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `file` | файл | да | ≤ 25 МБ, не пустой, разрешённый тип с совпадающей сигнатурой |
| `text` | string | нет | ≤ 4000 символов |
| `client_msg_id` | string | нет | UUID; некорректное значение молча игнорируется |
| `reply_to_id` | integer | нет | |

**Ответ `201`:** как у `POST /chats/{thread_id}/messages` (`attachment` заполнен; текст пустой → «📎 <имя>»).

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | файл > 25 МБ (чтение прерывается на лимите) | «Файл больше 25 МБ» |
| 400 | пустой файл | «Пустой файл» |
| 400 | тип не из списка | «Такой тип файла в переписку не принимается» |
| 400 | сигнатура не совпадает с типом | «Содержимое файла не совпадает с его типом» |
| 400 | текст > 4000 | «Сообщение длиннее 4000 символов. Отправьте длинный текст файлом — так его и прочитают, и сохранят.» |
| 403 / 404 / 429 | как выше | |
| 422 | нет `file` | |

**Пример.** `multipart: file=@schema.pdf; text="Схема узла крепления"` → `201 {"item": {"id": "721", "text": "Схема узла крепления", "attachment": {"id": 950, "name": "schema.pdf", "size": 182044, "content_type": "application/pdf", "is_image": false}, …}, "created": true, …}`

**Побочные эффекты.** Файл в хранилище (локальный диск или S3) + запись вложения (`entity_type = chat_message`, `entity_id = id треда`, тип документа `chat`); далее — как у обычной отправки; `chat_message_created` с `has_attachment: true`.

### PATCH /chats/{thread_id}/messages/{message_id}

**Назначение.** Исправить свою реплику в течение 15 минут после отправки. Прежний текст сохраняется в истории реплики и попадает в выгрузку; у собеседника — пометка «изменено».

**Доступ.** Доступ к треду + автор: та же сторона и тот же пользователь. Нельзя править системные реплики и дубли из сравнения (`cell_quote`, `review`, `cell_thread` сотрудника); ответ контрагента на вопрос по ячейке (`cell_thread` стороны `supplier`) править можно — правка уходит и в зеркальную запись треда ячейки.

**Лимит.** 30 в минуту.

**Параметры пути.** `thread_id`, `message_id` — integer > 0.

**Тело запроса:**

| Поле | Тип | Обяз. | Ограничения |
|---|---|---|---|
| `text` | string | да | обрезается; ≤ 4000; пустой допустим только у реплики с файлом |

**Ответ `200`:** `{"item": Message, "cursor": integer}`. Текст без изменений — ответ без новой ревизии и события.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | реплики нет в этом треде | «Сообщение не найдено» |
| 403 | чужая реплика | «Изменить можно только своё сообщение» |
| 403 | реплика из сравнения | «Эта реплика пришла из сравнения — изменить её можно только там» |
| 403 | прошло > 15 минут | «Изменить или удалить сообщение можно в течение 15 минут после отправки» |
| 400 | уже удалена | «Сообщение уже удалено» |
| 400 | пустой текст у реплики без файла | «Нужен текст» |
| 400 | некорректный id | «Некорректный id сообщения» / «Некорректный id чата» |
| 422 | текст > 4000 | |
| 429 | лимит | |

**Пример.** `{"text": "Подтверждаем получение КП, вопросы направим до четверга."}`

**Побочные эффекты.** Ревизия (`action = edit`, прежний текст и вложение, кто правил), новый `edited_seq`, `edited_at`; событие шины `msg` (реплика приезжает дельтой заново); событие журнала `chat_message_edited` (`message_id`).

### DELETE /chats/{thread_id}/messages/{message_id}

**Назначение.** Мягко удалить свою реплику в течение 15 минут: место в ленте остаётся («Сообщение удалено»), текст и вложение уходят в историю реплики.

**Ответ `200`:** `{"item": Message (deleted: true, text: "", attachment: null), "cursor": integer}`.

**Ошибки.** Как у `PATCH` (кроме ошибок текста).

**Пример.** `DELETE /api/chats/65/messages/720` → `{"item": {"id": "720", "deleted": true, "text": "", …}, "cursor": 73}`

**Побочные эффекты.** Ревизия `action = delete`; `deleted_at`, новый `edited_seq`; для ответа контрагента по ячейке зеркальная запись ячейки получает текст «Сообщение удалено контрагентом.»; счётчики непрочитанного не уменьшаются; событие шины `msg`; журнал `chat_message_deleted`.

### POST /chats/{thread_id}/typing

**Назначение.** Сигнал «печатает…» противоположной стороне. Клиент шлёт его раз в ~3 с, индикатор у собеседника гаснет сам.

**Доступ.** Доступ к треду (проверка кэшируется в памяти процесса на 60 с).

**Механика.** Без записи в БД. Не чаще раза в 2 с от одного человека в одном треде — более частые вызовы молча игнорируются (тоже `204`).

**Параметры пути.** `thread_id`.

**Ответ `204`** без тела.

**Ошибки.** 400 «Некорректный id чата»; 404 «Чат не найден»; 403 — нет доступа; 401.

**Пример.** `POST /api/chats/65/typing` → `204`.

**Побочные эффекты.** Событие шины `typing` с `side` и именем (сотрудник — ФИО, контрагент — название организации).

| `kind` | string | нет (`cell_thread`) | `cell_thread` \| `cell_quote` \| `review` |

**Ошибки.**

| Код | Когда | `detail` |

## Публичный контур по ссылке-приглашению

Контур для контрагента, открывшего форму подачи КП по ссылке из письма-приглашения (без учётной записи). Это **единственная поверхность продукта, которая пишет в БД без аутентификации**, поэтому на ней три рубежа:

1. **Частота по паре «токен + IP»**: чтение (`GET`, `/updates`, `/stream`, `/read`, скачивание) — 60 в минуту; запись (отправка, правка, удаление) — 30 в минуту. Превышение — `429` «Слишком часто — подождите минуту и попробуйте снова» и событие журнала `chat_rate_limited` (бакет, последние 6 символов токена, IP).
2. **Валидация вложения** — те же правила, что у `POST /chats/{id}/messages/file`.
3. **Суточный потолок анонимной стороны на тред**: 200 реплик и 200 МБ вложений за скользящие 24 часа; превышение — `429` «Достигнут суточный предел сообщений или вложений в этой переписке. Продолжите завтра или свяжитесь с представителем <клиента>.» и событие `chat_thread_cap_reached`.

**Проверка токена** (на каждом запросе):

| Код | Когда | `detail` |
|---|---|---|
| 403 | токен не UUID или приглашения нет | «Ссылка недействительна или устарела» |
| 410 | приглашение отозвано | «Приглашение отозвано — ссылка больше не действует. Обратитесь к представителю <клиента>.» |
| 403 | организация контрагента приостановлена | «Доступ организации приостановлен. Обратитесь к администратору системы.» |

`<клиента>` — родительный падеж названия компании-клиента из настройки `CLIENT_NAME`, по умолчанию «клиента». Прочитанность анонимного контрагента ведётся на приглашение. Контрагент по ссылке видит тот же тред, что и пользователи ЛК его организации, но править может только реплики, отправленные по ссылке (без автора-пользователя).

### GET /chats/invite/{token}

**Назначение.** Переписка контрагента по ссылке: тред с лентой (последние 50 реплик) и курсор. Ручка только читает (прочитанность не меняет).

**Доступ.** По токену приглашения; лимит чтения.

**Параметры пути.** `token` — UUID приглашения.

**Ответ `200`:** `{"item": Thread (с лентой), "cursor": integer}`. Если тред ещё не создан — пустая заготовка: `id: ""`, `messages: []`, `updated_at: null`, `unread: 0`, `last_seq: 0` с названиями тендера и контрагента.

**Ошибки.** 403 / 410 — токен; 429 — частота.

**Пример.** `GET /api/chats/invite/3f1c…` → `{"item": {"id": "61", "tender_id": 100, "tender_title": "…", "supplier_id": 202, "supplier_name": "Бета Конструкции", "messages": [{"id": "611", "event_seq": 4, "author": "system", "text": "Диалог открыт.", …}], "unread": 0, …}, "cursor": 71}`

**Побочные эффекты.** Счётчик лимита частоты.

---

### GET /chats/invite/{token}/updates

**Назначение.** Дельта своей ветки после курсора — вызывается по событию потока `/stream`, а без потока — редким опросом видимой вкладки.

**Доступ.** По токену; лимит чтения.

**Параметры запроса.** `since` — integer ≥ 0, по умолчанию 0. Лимит дельты фиксирован — 300 событий.

**Ответ `200`:** как у `GET /chats/updates` (только по треду этого приглашения). Если треда нет — `{"reset": false, "cursor": N, "messages": [], "threads": []}`.

**Ошибки.** 403 / 410 / 429; 422.

**Пример.** `GET /api/chats/invite/3f1c…/updates?since=60` → `{"reset": false, "cursor": 71, "messages": [], "threads": []}`

**Побочные эффекты.** Нет.

---

### GET /chats/invite/{token}/stream

**Назначение.** Живой SSE-поток событий своей переписки по ссылке — чтобы ответ заказчика доезжал без опроса.

**Доступ.** По токену; при подключении — тот же лимит чтения и проверка приглашения. Соединение живёт не дольше **600 секунд**, затем сервер его закрывает, клиент переподключается и заново проходит проверки — отозванная ссылка не держит поток часами.

**Параметры пути.** `token`.

**Ответ `200`.** `Content-Type: text/event-stream; charset=utf-8`, заголовки `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`; сжатие для потоков отключено. Формат:

| Кадр | Когда | Содержимое |
|---|---|---|
| `retry: 3000` | первым | подсказка клиенту: переподключаться через 3 с |
| `data: {"type": "chat", "cursor": N}` | сразу после подключения | текущий курсор — клиент сверяет со своим и при отставании зовёт `/updates` |
| `: ping` | каждые 15 с без событий | heartbeat (держит соединение через прокси, позволяет заметить обрыв) |
| `data: {"type": "chat", "cursor": N, "events": [...]}` | при событиях | пачка событий **только этого тендера** (без поля `tender_id`): `{"type":"chat","kind":"msg","thread_id","seq","cursor","side"}`, `{"kind":"read","seq","side"}`, `{"kind":"typing","side","name"}`; при переподключении слушателя БД — `{"type":"chat","kind":"resync"}` |

Текста реплик в потоке нет: увидев `msg` с курсором больше своего, клиент запрашивает `/updates?since=`.

**Ошибки** (до начала потока, обычным JSON). 403 / 410 — токен; 429 — частота.

**Пример.**

```text
retry: 3000

data: {"type": "chat", "cursor": 71}

: ping

data: {"type": "chat", "cursor": 72, "events": [{"type": "chat", "kind": "msg", "thread_id": 61, "seq": 72, "cursor": 72, "side": "specialist"}]}
```

**Побочные эффекты.** Подписка на ключ организации контрагента в шине на время соединения; соединение с БД возвращается в пул сразу после проверок.

### POST /chats/invite/{token}/typing

**Назначение.** «Печатает…» стороне заказчика.

**Доступ.** По токену. Частота ограничивается в памяти процесса по токену (не чаще раза в 2 с) **до** обращения к БД; лишние вызовы молча игнорируются.

**Ответ `204`** без тела (и если треда ещё нет).

**Ошибки.** 403 / 410 — токен (только когда вызов не отсечён частотой).

**Пример.** `POST /api/chats/invite/3f1c…/typing` → `204`.

**Побочные эффекты.** Событие шины `typing` сотрудникам объекта и администраторам; имя — название организации контрагента.

### PATCH /chats/invite/{token}/messages/{message_id}

**Назначение.** Исправить свою реплику, отправленную по ссылке, в течение 15 минут.

**Доступ.** По токену; лимит записи. Править можно только реплики стороны `supplier` без автора-пользователя (реплики пользователей ЛК той же организации — нельзя).

**Параметры пути.** `token`; `message_id` — integer > 0.

**Тело запроса.** `{"text": string}` — ≤ 4000 символов.

**Ответ `200`:** `{"item": Message, "cursor": integer}`.

**Ошибки.** 404 «Сообщение не найдено» (в т. ч. если треда нет); 403 «Изменить можно только своё сообщение» / «…в течение 15 минут после отправки» / «Эта реплика пришла из сравнения…»; 400 «Сообщение уже удалено» / «Нужен текст»; 403 / 410 / 429 — токен и частота; 422.

**Пример.** `{"text": "Поправка: срок поставки 8–10 недель."}`

**Побочные эффекты.** Ревизия, `edited_seq`, событие шины `msg`, зеркало ответа в ячейке (если это ответ по ячейке); журнал `chat_message_edited` (`message_id`, `author_role: supplier`).

### DELETE /chats/invite/{token}/messages/{message_id}

**Назначение.** Мягко удалить свою реплику, отправленную по ссылке, в течение 15 минут.

**Доступ, параметры.** Как у `PATCH` выше.

**Ответ `200`:** `{"item": Message (deleted: true), "cursor": integer}`.

**Ошибки.** Как у `PATCH` (кроме ошибок текста).

**Пример.** `DELETE /api/chats/invite/3f1c…/messages/731` → `{"item": {"id": "731", "deleted": true, …}, "cursor": 74}`

**Побочные эффекты.** Ревизия `delete`, событие шины `msg`; журнал `chat_message_deleted`.

### POST /chats/invite/{token}/read

**Назначение.** Отметить свою ветку прочитанной до события. Идемпотентно, назад не откатывается.

**Доступ.** По токену; лимит чтения.

**Параметры запроса** (не тело!):

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `up_to_seq` | integer ≥ 0 | 0 | 0 — до последней реплики треда |

**Ответ `200`:** `{"ok": true, "last_read_seq": integer}` (если треда нет — `0`).

**Ошибки.** 403 / 410 / 429; 422.

**Пример.** `POST /api/chats/invite/3f1c…/read?up_to_seq=72` → `{"ok": true, "last_read_seq": 72}`

**Побочные эффекты.** Отметка на приглашение, агрегат стороны `supplier`; событие шины `read` организации контрагента и сотрудникам объекта (у сотрудника появляется ✓✓).

### POST /chats/invite/{token}/messages

**Назначение.** Отправить реплику по ссылке — текстом и/или файлом одной транзакцией; либо ответить на вопрос заказчика по ячейке СТ.

**Доступ.** По токену; лимит записи; суточный потолок треда.

**Тело запроса** (`multipart/form-data`):

| Поле | Тип | Обяз. | Ограничения / смысл |
|---|---|---|---|
| `text` | string | нет | ≤ 4000 символов |
| `file` | файл | нет | правила вложений чата; суммарный суточный вес с учётом файла ≤ 200 МБ |
| `client_msg_id` | string | нет | UUID; некорректный — игнорируется |
| `answer_to_id` | integer | нет | реплика **этого** треда, у которой есть привязка к ячейке (`quote_item_id` или `comment_id`) |

Нужен текст или файл. Тред создаётся автоматически, если его ещё нет.

**Ответ `201`:** `{"item": Message, "thread_id": string, "created": boolean, "cursor": integer}`.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 400 | нет ни текста, ни файла | «Нужен текст или файл» |
| 400 | текст > 4000 | «Сообщение длиннее 4000 символов. Отправьте длинный текст файлом…» |
| 400 | ошибки файла | «Файл больше 25 МБ» / «Пустой файл» / «Такой тип файла в переписку не принимается» / «Содержимое файла не совпадает с его типом» |
| 403 | `answer_to_id` не из этого треда | «Ответ не на реплику этого диалога» |
| 403 | реплика не про ячейку | «Эта реплика не про ячейку» |
| 403 / 410 | токен | см. выше |
| 429 | частота или суточный потолок | см. выше |

**Пример.** `multipart: text="Цена указана с учётом усиленного ригеля"; answer_to_id=722` → `201 {"item": {"id": "731", "author": "supplier", "author_user_id": null, "text": "Цена указана с учётом усиленного ригеля", "reply_to": {"id": "722", …}, "cell": {"kind": "cell_thread", "quote_item_id": 17084, "comment_id": 9301}, …}, "thread_id": "65", "created": true, "cursor": 73}`

**Побочные эффекты.**
- файл — в хранилище, вложение без автора-пользователя;
- ответ по ячейке: реплика получает `kind = cell_thread`, `quote_item_id` вопроса и ссылку-цитату; **дополнительно** создаётся запись в треде комментариев позиции тендера (`entity_type = tender_item`, контрагент-якорь, без автора) — тендерный специалист видит ответ прямо в ячейке СТ как непрочитанный; реплика связывается с этой записью;
- курсор прочтения приглашения сдвигается на свою реплику;
- уведомление ответственному за тендер (in-app + письмо с дебаунсом 15 мин), активность тендера, событие шины `msg`;
- журнал `chat_message_created` (`author_role: supplier`, `has_attachment`).

### GET /chats/invite/{token}/files/{attachment_id}/download

**Назначение.** Скачать вложение своей переписки по ссылке.

**Доступ.** По токену; лимит чтения. Три обязательные проверки: токен действует; вложение принадлежит **чату** (а не, например, досье контрагента); тред вложения — тред этого приглашения.

**Параметры пути.** `token`; `attachment_id` — integer > 0.

**Ответ `200`.** Файл: локальное хранилище — отдача файла с `Content-Disposition: attachment; filename=…`; S3 — потоковая отдача через API с `Content-Length` (без presigned-ссылки). `Content-Type` — сохранённый тип вложения.

**Ошибки.**

| Код | Когда | `detail` |
|---|---|---|
| 404 | треда нет, вложения нет, оно не из чата или из чужого треда | «Файл не найден» |
| 404 | файл ещё не загружен в хранилище | «Файл ещё не загружен в хранилище» |
| 400 | некорректный id | «Некорректный id файла» |
| 403 / 410 / 429 | токен и частота | см. выше |

**Пример.** `GET /api/chats/invite/3f1c…/files/950/download` → `200`, `application/pdf`, `schema.pdf`.

**Побочные эффекты.** Нет.
