# API: отчёты (reports)

Ручки экрана «Отчёты»: три отчёта («По тендерам», «По КП», «По контрагентам») в JSON для таблицы на экране и в `.xlsx` — целиком (GET) или ровно тем срезом, который пользователь видит на экране (POST: список строк и колонок с экрана). Отдельно — выгрузка среза реестра тендеров. Общие соглашения (аутентификация, ошибки, конверт `{items, total, limit, offset}`, лимит тяжёлых чтений) — в [overview.md](overview.md).

Связанные разделы: бизнес-логика — [../02-business-logic/analytics.md](../02-business-logic/analytics.md); экраны — [../03-screens/reports.md](../03-screens/reports.md), реестр тендеров (выгрузка среза) — см. экраны раздела тендеров в [../03-screens/](../03-screens/).

## Сводка

| Метод | Путь | Кратко | Доступ |
|---|---|---|---|
| GET | `/reports/tenders` | Отчёт по тендерам (JSON, страницами) | право `reports.view` |
| GET | `/reports/quotes` | Отчёт по КП (JSON) | `reports.view` |
| GET | `/reports/suppliers` | Отчёт по контрагентам (JSON) | `reports.view` |
| GET | `/reports/tenders.xlsx` | Отчёт по тендерам целиком в Excel | `reports.view` |
| POST | `/reports/tenders.xlsx` | Экранный срез отчёта по тендерам в Excel | `reports.view` |
| GET | `/reports/quotes.xlsx` | Отчёт по КП целиком | `reports.view` |
| POST | `/reports/quotes.xlsx` | Срез отчёта по КП | `reports.view` |
| GET | `/reports/suppliers.xlsx` | Отчёт по контрагентам целиком | `reports.view` |
| POST | `/reports/suppliers.xlsx` | Срез отчёта по контрагентам | `reports.view` |
| POST | `/reports/registry.xlsx` | Срез реестра тендеров в Excel (колонки как в таблице реестра) | `reports.view` |

Сложность блока: **M**.

## Общие правила раздела

**Доступ.** Все ручки — право `reports.view` (по умолчанию у тендерного специалиста и администратора; у СБ и юриста нет). Отказ — `403` «Недостаточно прав для этого действия — обратитесь к администратору системы» + `permission_denied` в журнале ИБ. Нет сессии — `401`.

**Периметр данных.** Строки собираются только по проектам, доступным пользователю (гранты на портфель/проект с подпроектами; администратор — всё):
- тендеры — тендеры доступных проектов;
- КП — текущие версии КП по тендерам доступных проектов;
- контрагенты — неудалённые контрагенты; при ограниченном доступе — только приглашавшиеся в тендеры доступных проектов («мои контрагенты»), сортировка по названию.

**Лимит частоты.** На весь раздел — общий лимит тяжёлых чтений на пользователя: `HEAVY_READ_RATE_LIMIT` (60) запросов за `HEAVY_READ_RATE_WINDOW` (60 с). Превышение — `429` «Слишком много запросов — попробуйте немного позже».

**Финансы («коммерческая тайна»).** Если у пользователя нет права видеть цены (`finance.view` или персональный флаг):
- в JSON финансовые поля (`minPrice`, `maxPrice`, `incompleteMinPrice`, `incompleteMissing`, `amount`, `bestPrice`) приходят `null`, а `financeMasked = true`;
- в `.xlsx` эти колонки не выводятся вовсе.

**Книга `.xlsx`.** Один лист (имя листа — «Тендеры», «КП» или «Контрагенты»), строка заголовков жирным на сером фоне. Если в книге есть хотя бы одна денежная колонка, в ячейке A1 — курсивом гриф «ГРИФ: КОММЕРЧЕСКАЯ ТАЙНА / КОНФИДЕНЦИАЛЬНО. Документ содержит сведения ограниченного доступа. Передача третьим лицам без основания запрещена.», а заголовки начинаются с 3-й строки. Форматы ячеек — форматы Excel (работают сортировка и фильтр): деньги `#,##0.00 "₽"`, целые `#,##0`, даты `ДД.ММ.ГГГГ`. В колонке «Статус» — русские подписи вместо кодов. Ответ: `200`, `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `Content-Disposition: attachment; filename="<имя>.xlsx"`.

**Журнал.** Каждое скачивание `.xlsx` пишет событие журнала ИБ `report_export` (сущность `report`, IP, детали `{"report": "<отчёт>.xlsx", "rows": N}`, для среза ещё `"scope": "screen_slice"`). JSON-ручки в журнал не пишут.

### Колонки отчётов

Ключ колонки = поле строки JSON = ключ колонки в теле среза.

**По тендерам** (`tenders`; файл `report_tenders.xlsx`):

| Ключ | Заголовок | Формат | Смысл |
|---|---|---|---|
| `number` | № | текст | номер тендера |
| `title` | Название | текст | |
| `project` | Проект | текст | путь «объект / подобъект» |
| `status` | Статус | текст | `draft` Черновик, `open` Сбор предложений, `closed` Завершён, `cancelled` Отменён |
| `kpCount` | Подано КП | целое | число поданных КП (статусы «подано», «принят», «на доработке») |
| `minPrice` | Мин. цена | деньги | минимальный итог среди **полных** КП (как «Лидер» в обзоре тендера) |
| `maxPrice` | Макс. цена | деньги | максимальный итог полных КП |
| `incompleteMinPrice` | Мин. неполного КП | деньги | самый дешёвый итог неполного КП |
| `incompleteMissing` | Неполное КП: нет ставок | целое | сколько позиций без цены в этом неполном КП; в файле всегда идёт следом за `incompleteMinPrice` |
| `responsible` | Ответственный | текст | ФИО ответственного |

Дополнительно в JSON: `id` (id тендера).

**По КП** (`quotes`; файл `report_quotes.xlsx`):

| Ключ | Заголовок | Формат | Смысл |
|---|---|---|---|
| `id` | КП | текст | `Q-<id КП>` |
| `supplier` | Контрагент | текст | юридическое название |
| `tender` | Тендер | текст | номер тендера |
| `status` | Статус | текст | `draft` Черновик, `submitted` Подано, `revision_requested` На доработке, `withdrawn` Отозвано, `accepted` Принят |
| `amount` | Сумма | деньги | итог текущей версии (0, если позиций нет) |
| `version` | Версия | целое | номер текущей версии |
| `submitted` | Подано | дата | дата подачи текущей версии (в JSON — `ГГГГ-ММ-ДД`) |

**По контрагентам** (`suppliers`; файл `report_suppliers.xlsx`):

| Ключ | Заголовок | Формат | Смысл |
|---|---|---|---|
| `name` | Компания | текст | юридическое название |
| `inn` | ИНН | текст | |
| `category` | Категория | текст | пусто, если нет |
| `status` | Статус | текст | `new` Новая анкета, `questionnaire_pending` Анкета не заполнена, `review` На согласовании, `check` Проверяется, `revision` На доработке, `approved` Одобрен, `approved_with_limit` Одобрен с лимитом, `rejected` Отклонён |
| `registered` | Регистрация | дата | дата заведения контрагента |
| `tenders` | Участий | целое | в сколько тендеров (доступных проектов) приглашён |

Дополнительно в JSON: `id` (id контрагента).

**Реестр тендеров** (`registry`, только срез; файл `registry_srez.xlsx`):

| Ключ | Заголовок | Формат | Смысл |
|---|---|---|---|
| `id` | № | текст | в ячейку пишется **номер** тендера (ключ `id` одновременно отбирает строки) |
| `title` | Название | текст | |
| `project` | Портфель / проект | текст | «портфель / объект / подобъект» |
| `kind` | Вид работ | текст | |
| `status` | Статус | текст | Сбор предложений / Завершён / Отменён / Черновик |
| `statusChanged` | Дата изменения статуса | дата | московский день |
| `owner` | Ответственный | текст | |
| `start` / `end` | Начало / Окончание | дата | даты начала и окончания тендера |
| `deadline` | Соблюдение сроков | текст | «В срок» / «С опозданием» / «Просрочен» / пусто |
| `invited` | Приглашено / откликнулись | текст | `N / M` |
| `bestPrice` | Лучшая цена | деньги | |
| `incompleteMinPrice` | Мин. неполного КП | деньги | |
| `incompleteMissing` | Неполное КП: нет ставок | целое | |
| `created` | Создан | дата | |

### GET /reports/tenders

**Назначение.** Строки отчёта «По тендерам» для таблицы на экране. Обход дерева «портфель → объект → подобъект» — тот же, что у реестра тендеров, чтобы отчёт и реестр не расходились.

**Доступ.** `reports.view`; периметр — доступные проекты.

**Параметры запроса:**

| Параметр | Тип | Обяз. | Смысл |
|---|---|---|---|
| `limit` | integer | нет | 1–200; без него — до 200 строк |
| `offset` | integer | нет | ≥ 0 |

Страница режется по уже собранному отчёту. Фильтры и сортировка — на клиенте.

**Ответ `200`:** `{items, total, limit, offset, financeMasked}`; поля строки — см. «Колонки отчётов → По тендерам» + `id`.

**Ошибки.** 401, 403, 422, 429.

**Пример.**

```json
{"items": [{"id": 100, "number": "T-2026-100", "title": "Витражи, дворовой фасад", "project": "Жилые корпуса / МКД-1",
  "status": "open", "responsible": "Петров Пётр Петрович", "kpCount": 7, "minPrice": 269413821.41,
  "maxPrice": 321568972.22, "incompleteMinPrice": 222878133.64, "incompleteMissing": 14}],
 "total": 6, "limit": 1, "offset": 0, "financeMasked": false}
```

**Побочные эффекты.** Нет.

### GET /reports/quotes

**Назначение.** Строки отчёта «По КП»: по одной строке на КП (текущая версия).

**Доступ.** `reports.view`; периметр — доступные проекты.

**Параметры запроса.** `limit`, `offset` — как у `/reports/tenders`.

**Ответ `200`:** `{items, total, limit, offset, financeMasked}`; поля — «Колонки отчётов → По КП».

**Ошибки.** 401, 403, 422, 429.

**Пример.**

```json
{"items": [{"id": "Q-112", "supplier": "ООО «Альфа Фасад»", "tender": "T-2026-100", "status": "submitted",
  "amount": 251945996.67, "version": 2, "submitted": "2026-09-25"}],
 "total": 12, "limit": 1, "offset": 0, "financeMasked": false}
```

**Побочные эффекты.** Нет.

### GET /reports/suppliers

**Назначение.** Строки отчёта «По контрагентам» — тот же состав, что уходит в `.xlsx`.

**Доступ.** `reports.view`; периметр — см. «Общие правила».

**Параметры запроса.** `limit`, `offset`.

**Ответ `200`:** `{items, total, limit, offset, financeMasked}`; поля — «Колонки отчётов → По контрагентам» + `id`. Финансовых полей в этом отчёте нет. ИНН не маскируется (см. открытые вопросы).

**Ошибки.** 401, 403, 422, 429.

**Пример.**

```json
{"items": [{"id": 202, "name": "АО «Бета Конструкции»", "inn": "7700000000", "category": "", "status": "approved",
  "registered": "2025-12-01", "tenders": 2}], "total": 10, "limit": 1, "offset": 0, "financeMasked": false}
```

**Побочные эффекты.** Нет.

### GET /reports/tenders.xlsx

**Назначение.** Отчёт «По тендерам» целиком (все строки периметра, без пагинации) в Excel, все колонки в каноническом порядке.

**Доступ.** `reports.view`.

**Параметры.** Нет.

**Ответ `200`.** Файл `report_tenders.xlsx` (см. «Книга .xlsx»). Без права на финансы колонок с ценами нет и гриф не ставится.

**Ошибки.** 401, 403, 429.

**Пример.** `GET /api/reports/tenders.xlsx` → `200`, `Content-Disposition: attachment; filename="report_tenders.xlsx"`.

**Побочные эффекты.** Событие журнала ИБ `report_export` `{"report": "tenders.xlsx", "rows": N}`.

### POST /reports/tenders.xlsx

**Назначение.** Выгрузить **именно экранный срез** отчёта по тендерам: строки и колонки в том составе и порядке, которые видит пользователь (фильтрация и сортировка живут на клиенте, поэтому срез передаётся списком id, а не фильтрами).

**Доступ.** `reports.view`.

**Тело запроса** (`application/json`, без строгой схемы — общее для всех POST-срезов):

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `ids` | array<string \| integer> | да | id строк в порядке экрана; для этого отчёта — id тендеров. Синоним — `tender_ids` |
| `columns` | string[] | нет | ключи колонок в порядке экрана; неизвестные ключи отбрасываются; пусто/нет — все колонки. Если выбрана `incompleteMinPrice`, за ней автоматически добавляется `incompleteMissing` |

Порядок строк в файле — порядок `ids`; id вне периметра пользователя молча пропускаются.

**Ответ `200`.** Файл `tenders_srez.xlsx`.

**Ошибки:**

| Код | Когда | `detail` |
|---|---|---|
| 400 | `ids` не список (или нет ни `ids`, ни `tender_ids`) | «Укажите ids — список строк среза» |
| 422 | ни одна строка не найдена в периметре (в т. ч. пустой список) | «Срез пуст — нечего выгружать» |
| 401 / 403 / 429 | см. общие правила | |

**Пример.**

```json
{"ids": [104, 100, 101], "columns": ["number", "title", "status", "minPrice", "incompleteMinPrice"]}
```

**Побочные эффекты.** `report_export` `{"report": "tenders.xlsx", "scope": "screen_slice", "rows": N}`.

### POST /reports/quotes.xlsx

**Назначение.** Экранный срез отчёта по КП в Excel.

**Доступ.** `reports.view`.

**Тело запроса.** Как у `POST /reports/tenders.xlsx`; `ids` — строки вида `Q-<id>` (или просто число); нераспознанные значения игнорируются.

**Ответ `200`.** Файл `quotes_srez.xlsx`.

**Ошибки.** 400 «Укажите ids — список строк среза»; 422 «Срез пуст — нечего выгружать»; 401 / 403 / 429.

**Пример.** `{"ids": ["Q-112", "Q-118"], "columns": ["id", "supplier", "amount", "submitted"]}`.

**Побочные эффекты.** `report_export` со `scope: "screen_slice"`.

### POST /reports/registry.xlsx

**Назначение.** Выгрузить срез **реестра тендеров** (экран реестра, а не отчёт «По тендерам»): свои колонки и подписи статусов, как в таблице реестра. Выгрузки реестра целиком нет — только срез.

**Доступ.** `reports.view`; периметр — доступные проекты.

**Тело запроса.** Как у `POST /reports/tenders.xlsx`: `ids` — id тендеров (синоним `tender_ids`), `columns` — ключи колонок реестра (см. «Реестр тендеров»).

**Ответ `200`.** Файл `registry_srez.xlsx`, лист «Тендеры». Без права на финансы колонки «Лучшая цена», «Мин. неполного КП», «Неполное КП: нет ставок» не выводятся.

**Ошибки.** 400 «Укажите ids — список строк среза»; 422 «Срез пуст — нечего выгружать»; 401 / 403 / 429.

**Пример.**

```json
{"ids": [100, 101], "columns": ["id", "title", "project", "status", "owner", "end", "invited", "bestPrice"]}
```

**Побочные эффекты.** `report_export` `{"report": "registry.xlsx", "scope": "screen_slice", "rows": N}`.
