# Глоссарий — словарь терминов

Канонические термины ТЗ. Во всех разделах используются именно они; синонимы указаны,
чтобы читатель узнавал их в интерфейсе и в именах полей API и БД.

## 1. Структура закупки

| Термин | Определение | В API / БД |
|---|---|---|
| **Портфель** | Верхний уровень группировки объектов (например, жилой комплекс или программа строительства) | `portfolios` |
| **Проект (объект) / подпроект** | Объект строительства и его части. Иерархия «портфель → проект → подпроект» без ограничения глубины. В проекте создаются тендеры | `projects`, `parent_project_id` |
| **Тендер** | Процесс сбора и сравнения КП по одной закупке. Создаётся в проекте, ссылается на одну бюджетную позицию и один или несколько видов работ, имеет срок сбора КП, участников, ответственного и статус (черновик → сбор предложений → завершён; отменён). Номер вида `T-2026-108` (латинская T, год, сквозной идентификатор) | `tenders` |
| **Предмет тендера** | Что закупается («Устройство монолитных стен»): название тендера, а не запись справочника | `tenders.title` |
| **Плановая сумма (бюджет тендера)** | Оценка стоимости закупки заранее; с ней сравнивают лучшее предложение | — |
| **Ответственный** | Тендерный специалист, ведущий тендер | — |
| **Срок сбора КП** | Даты начала и окончания приёма предложений | — |
| **«Требует внимания»** | Не статус, а хранимый флаг тендера: выставляется, когда поставщик подал КП с изменённым объёмом или специалист изменил состав ФКП (дополнил, снял/вставил позиции, поменял объём); сбросить его нельзя. Показывается только у черновиков и тендеров в сборе предложений — [tenders.md §4.3](../02-business-logic/tenders.md#43-флаг-требует-внимания) | `needs_attention` |
| **Заметки сотрудников** | Внутренние заметки по тендеру, поставщику не видны | — |

## 2. Форма и предложения

| Термин | Определение | В API / БД |
|---|---|---|
| **Шаблон (Excel-смета)** | Excel-файл Заказчика со структурой закупки: разделы, позиции, единицы, объёмы, дополнительные условия | вложение тендера |
| **Распознавание** | Превращение Excel-шаблона в структуру ФКП: детерминированный разбор и, опционально, ИИ-помощь | домен `fkp_import` |
| **ФКП — форма коммерческого предложения** | Онлайн-форма тендера, которую заполняет поставщик. Задаёт строки сравнительной таблицы. Имеет версии | `tender_fkp_versions` |
| **Раздел / подраздел** | Узел группировки позиций в ФКП, вложенность любой глубины, у каждого свой итог | `tender_sections` |
| **Позиция** | Одна строка сметы: наименование, единица измерения, объём (из шаблона), ставки и стоимость (от поставщика). В части API и ИИ-контрактов называется `work_id` / `works` | `tender_items` |
| **Дополнительные условия** | Нечисловые условия предложения: срок работ, условия оплаты, гарантия, аванс. Сравниваются без оценки «лучше/хуже» | `tender_condition_fields`, `quote_condition_values` |
| **Шаблон тендера** | Сохранённая структура тендера для повторного использования | `tender_templates` |
| **Черновик создания** | Незавершённый мастер создания тендера вместе с исходным файлом; старше `CREATION_DRAFT_TTL_DAYS` (30 дней) скрывается из списка, по прямой ссылке открывается с пометкой «просрочен» | `tender_creation_drafts` |
| **КП — коммерческое предложение** | Предложение одного поставщика по одному тендеру. Одна сущность на поставщика; повторные подачи — версии внутри неё. Редактирует только создатель | `quotes` |
| **Версия КП** | Неизменяемый снимок поданного КП. Повторная подача создаёт новую версию той же сущности; по умолчанию везде учитывается последняя | `quote_versions`, `quote_items` |
| **Ставка материалов / ставка работ** | Цены за единицу, которые поставщик вводит по позиции; их сумма — ставка за единицу | см. [tenders-comparison](../02-business-logic/tenders-comparison.md) |
| **Стоимость позиции** | Ставка за единицу × применённый объём | там же |
| **Корректировка** | Отступление поставщика от шаблона: своя (новая) позиция, изменённый объём или отказ от позиции. Требует комментария | см. [tenders-quotes](../02-business-logic/tenders-quotes.md) |
| **Отказ** | Явное «не предлагаю» по позиции. Не то же, что прочерк (не подавал) и не ноль (цена 0 ₽) | — |
| **Комментарий поставщика к позиции** | Свободный текст поставщика к позиции в версии КП; обязателен при корректировке, до 1000 символов | — |
| **Подача / повторная подача** | Отправка КП; повторная подача создаёт новую версию | — |
| **Своя позиция** | Строка, которую поставщик добавил в КП сверх ФКП; входит в итог только после решения специалиста «принять» | `quote_items.is_new_position` |
| **Доработка КП** | Возврат всего КП поставщику с комментарием специалиста; статус КП «На доработке», прежние цифры остаются в расчёте до переподачи | `revision_requested` |
| **Дозаполнение** | Пометка «дозаполнить» на отдельных строках КП (не на всём КП), которые поставщик должен заполнить заново, — ставится после решения по корректировке объёма; статус КП не меняется | `quote_items.refill_required` |
| **Ревизия тендера** | Счётчик изменений состава тендера, решений по корректировкам и подач КП; вместе с отпечатком КП — ключ кэша сравнения | `tenders.tender_revision` |
| **НДС** | Ставка по умолчанию — 22 %, задаётся настройкой; поставщик подтверждает, включён ли НДС | `vat_rate_pct` |

## 3. Участники и раунды

| Термин | Определение | В API / БД |
|---|---|---|
| **Приглашение (участник)** | Связь поставщика с тендером. Стадии: отправлено → доставлено → заполняет → подано (повторная подача — «подано повторно»), отказ | `tender_invitations` |
| **Персональная ссылка (magic-link)** | Ссылка с токеном, по которой поставщик открывает форму КП без отдельной регистрации | `/fill/{token}` |
| **Раунд** | Повторный запрос КП у выбранных участников с общим текстом и личной припиской каждому, со сроком (переторжка / уточнение) | `tender_rounds`, `tender_round_recipients` |
| **Стадия участника** | Вычисляемое для интерфейса состояние участия: «отправлено» (приглашён), «доставлено» (открыл ссылку), «заполняет» (сохранил черновик или КП на доработке), «подано», «подано повторно» (версия КП ≥ 2); отдельно — «отказ» и «доступ закрыт» (ссылка отозвана) | `tender_invitations.status` + статус КП |
| **Победитель** | Поставщик, выбранный специалистом при завершении тендера; его КП получает статус «Принят» (`accepted`). Выбор неаккредитованного победителя требует явного подтверждения | — |
| **Протокол тендера** | Документ DOCX с итогами тендера | `tender_protocols` |

## 4. Сравнение (СТ)

| Термин | Определение |
|---|---|
| **СТ — сравнительная таблица** | Сведение всех КП тендера «бок о бок» по последним версиям: строки — разделы и позиции ФКП, колонки — поставщики, итоги по разделам и общий |
| **Полный / неполный / несопоставимый итог КП** | Полный — у поставщика есть сопоставимая цена по каждой действующей позиции с объёмом > 0; неполный — есть пропуски или отказы (их число показывается: «нет ставок: N»); несопоставимый — есть нерассмотренная корректировка объёма. Место и Δ к лидеру получают только полные КП |
| **Медиана, отклонение от медианы** | Статистика цены позиции по поставщикам и отклонение конкретной цены от неё |
| **MIN / MAX / Δ к лидеру** | Лучшая и худшая цена позиции, разница с лидером |
| **«Честный минимум»** | Минимум среди обычных (не аномальных) предложений: аномалии не искажают минимум |
| **Потенциал экономии** | Насколько дешевле стала бы позиция у поставщика, если бы он дал лучшую обычную («честный минимум») цену позиции: `(ставка − минимум) × объём`, сумма по позициям — потенциал поставщика. На экране сравнения есть ещё «запас торга», заявленный самим поставщиком, — это другая величина, см. [tenders-comparison.md §5.5](../02-business-logic/tenders-comparison.md#55-потенциал-экономии-расчётный) |
| **Разброс** | `(максимальная − минимальная ставка) / медиана × 100 %` по позиции; градации: «заметный» от 15 %, «высокий» от 40 % (системные настройки) |
| **Вес позиции, ключевые позиции** | Вес — доля медианной стоимости позиции (медианная ставка × объём) в сумме медианных стоимостей всех позиций; ключевые — самые «тяжёлые» позиции, набранные по убыванию веса до накопленной доли ≥ 80 % (настройка «Доля ключевых работ») — [tenders-comparison.md §5.7](../02-business-logic/tenders-comparison.md#57-вес-и-ключевые-позиции) |
| **Аномалия** | Цена, резко выбивающаяся из ряда: отклонение от медианы позиции не меньше `max(k × медиана отклонений остальных цен; порог «заметного» разброса)`, по умолчанию `k = 3`, порог 15 %; считается при ≥ 3 ценах |
| **Основной показатель** | Какой показатель ячейки показывается крупно (стоимость позиции или потенциал) |
| **Спутники** | Дополнительные показатели ячейки (отклонение, изменение к прошлому раунду, ставка за единицу) |
| **Динамика** | Изменение цены к предыдущему раунду |
| **Срез** | Какая ставка подставляется во все метрики СТ: «Итого» (материалы + работы), «Материалы» или «Работы»; срезы «Материалы»/«Работы» считаются только по ячейкам с известной разбивкой |
| **Запас торга** | Заявленная поставщиком в строке КП готовность уступить, ₽ за единицу; отдельная от расчётного потенциала величина |
| **Избранные участники** | Отмеченные звёздочкой поставщики; в СТ стоят сразу после победителя |
| **Неотработанный комментарий** | Комментарий поставщика к позиции, который текущий пользователь ещё не отметил «Просмотрено» и на который не ответил. Состояние персональное |

Формулы — в [../02-business-logic/tenders-comparison.md](../02-business-logic/tenders-comparison.md).

## 5. Контрагенты

| Термин | Определение | В API / БД |
|---|---|---|
| **Контрагент / поставщик / подрядчик** | Организация в реестре: заполняет анкету и/или подаёт КП. «Контрагент» — для записи реестра, «поставщик» — в контексте подачи КП | `suppliers` |
| **Анкета** | Онлайн-форма самостоятельной регистрации контрагента по приглашению: реквизиты, виды работ, опыт, выручка, лицензии, контакты, согласие на обработку ПДн | `/register` |
| **Приглашение к регистрации** | Ссылка, по которой новый контрагент заполняет анкету | `supplier_registration_invitations` |
| **Контакт контрагента** | Лицо организации (ФИО, должность, телефон, e-mail). Справочные данные, хранятся зашифрованными; это **не** учётная запись | `supplier_contacts` |
| **Пользователь контрагента** | Учётная запись с ролью «поставщик», входит в кабинет поставщика; у контрагента может быть несколько пользователей | `supplier_users` |
| **Кабинет поставщика** | Рабочее место поставщика: его тендеры, КП, анкета | `/cabinet` |
| **Квалификация (аккредитация)** | Проверка контрагента по независимым осям: служба безопасности, юрист (и финансовая). Сводный статус («Аккредитован» и др.) вычисляется из частных; его проверяют при выборе победителя. Отдельно хранится **решение по квалификации** (новая анкета / анкета не заполнена / на согласовании / проверяется / на доработке / одобрен / одобрен с лимитом / отклонён), которое выставляет администратор; его проверяют при приглашении в тендер — [suppliers.md §3.7](../02-business-logic/suppliers.md#37-решение-по-квалификации-status) | `sb_status`, `legal_status`, `finance_status`, `overall_status`; решение — `suppliers.status` |
| **Проверки по реестрам** | Сведения о контрагенте из открытых реестров (ЕГРЮЛ, СРО, арбитраж, банкротства, РНП); фактический объём интеграций — в [suppliers](../02-business-logic/suppliers.md) | `supplier_checks` |
| **Оси проверки и сводный статус** | Три независимых частных статуса — «Проверка СБ», «Юридическая проверка» (шкала: не требуется / ожидает / на проверке / пройдена / пройдена с замечаниями / не пройдена) и «Финансовый блок» (ожидает / одобрено / одобрено с лимитом / отказ). Сводный статус (анкета не заполнена / черновик анкеты / на проверке / аккредитован / отклонён) вычисляется из них и вручную не меняется | `sb_status`, `legal_status`, `finance_status`, `overall_status` |
| **Пул** | Рабочая группа контрагента у Заказчика: «Основной пул», «Для переторгов», «Вне пулов». Меняется вручную с комментарием; «пройдена с замечаниями» по СБ или юристу автоматически переводит в «Для переторгов», пока пул не меняли руками | `suppliers.pool` |
| **Корзина** | Мягко удалённые контрагенты: скрыты из реестра, восстанавливаются или удаляются насовсем (право `suppliers.manage`) | `suppliers.is_deleted`, `deleted_at` |
| **История квалификации** | Неизменяемый (append-only) журнал решений по контрагенту | `supplier_qualification_history` |
| **«Не приглашать до»** | Дата, до которой контрагента нельзя приглашать в тендеры | `no_invite_until` |
| **Маска контактов** | Скрытие ИНН/почты/телефона в СТ и сравнении для ролей без права просмотра контактов (включается настройкой) | `CONTACTS_MASK_ENABLED` |

## 6. Справочники

| Термин | Определение |
|---|---|
| **Вид работ** | Операционный классификатор (монолит, кладка, отделка, инженерные сети, фасады…). Им тегируются контрагенты, по нему подбирают участников. Плоский список |
| **Бюджетная позиция** | Финансовый классификатор: статья бюджета, из которой оплачивается тендер. С видами работ напрямую не связана — их связывает тендер (одна бюджетная позиция + один или несколько видов работ) |
| **Единица измерения и алиасы** | Справочник единиц (м², м.п., шт., т…) и их написаний в сметах для распознавания |
| **Пользовательский статус** | Статус, созданный администратором (название и цвет) поверх системных |

## 7. Роли и учётные записи

| Термин | Определение |
|---|---|
| **Тендерный специалист** | Внутренний пользователь: ведёт тендеры, контрагентов и КП |
| **Служба безопасности (СБ)** | Проверка контрагентов, журнал ИБ |
| **Юрист** | Юридическая проверка контрагентов |
| **Администратор** | Пользователи, роли и права, справочники, настройки площадки |
| **Поставщик** | Внешний пользователь контрагента |
| **Лид** | Человек, оставивший заявку на демо через лендинг (функция включается флагом) |
| **Владелец площадки (суперадмин)** | Учётная запись поставщика платформы внутри установки: себестоимость ИИ, биллинг, клиенты. Не видит тендеры и КП |
| **MFA** | Второй фактор входа (TOTP-приложение) |
| **Каркас, рейл, гейт** | Каркас — общая рамка экранов за входом (топбар, боковое меню-рейл с разделами, панель раздела); гейт — проверка при переходе по адресу: пускать ли роль на маршрут, иначе увод на стартовый экран роли |
| **ЛК** | Личный кабинет пользователя контрагента (`/cabinet`) |

## 8. Биллинг ИИ

| Термин | Определение |
|---|---|
| **Клиент** | Компания, для которой развёрнута площадка; у неё свой баланс и множитель |
| **ИИ-операция** | Действие пользователя с нейросетью (анализ тендера, вопрос по таблице, распознавание файла); единица списания |
| **Обращение к нейросети** | Один запрос к модели; на нём считается себестоимость |
| **Себестоимость** | Цена обращения у провайдера в долларах × курс, заданный владельцем |
| **Токен (внутренний)** | Расчётная единица клиента: 100 токенов = 1 ₽ себестоимости при множителе 1x |
| **Множитель** | Во сколько раз списание больше себестоимости |
| **Начисление / списание / корректировка** | Движения баланса; записи не правятся и не удаляются, ошибка исправляется корректировкой со знаком минус |
| **Заявка на пополнение** | Просьба клиента начислить токены; оплата вне площадки |

Подробно — [../02-business-logic/billing.md](../02-business-logic/billing.md).

## 9. Безопасность и платформа

| Термин | Определение |
|---|---|
| **Журнал ИБ** | Защищённый от изменений (append-only) журнал значимых событий безопасности |
| **Инцидент ИБ** | Событие или группа событий, классифицированные правилами как требующие разбора |
| **ПДн** | Персональные данные (152-ФЗ) |
| **СКЗИ** | Сертифицированное средство криптографической защиты; в текущей реализации шифрование полей выполнено несертифицированным провайдером, есть интерфейс подключения другого |
| **Фоновая задача** | Задание в очереди на PostgreSQL (`background_jobs`), выполняемое воркером внутри процесса API |
| **Пакет для регулятора (РКН)** | Версионируемый снимок по одному инциденту ИБ с утечкой ПДн: черновик уведомления Роскомнадзора и сведения для него (`rkn_packages`) |
| **SIEM** | Внешняя система сбора событий безопасности; журнал ИБ может пачками передаваться в неё (опционально, `siem_settings`) |
| **SSE** | Server-Sent Events: поток событий реального времени от сервера в браузер (уведомления, чат) |
| **Presigned-загрузка** | Загрузка файла браузером напрямую в S3 по подписанной ссылке с последующим подтверждением на сервере |

## 10. Сокращения

| Сокращение | Расшифровка |
|---|---|
| **ИНН / ОГРН** | Идентификационный номер налогоплательщика (10 цифр у юрлица, 12 — у ИП) / основной государственный регистрационный номер |
| **ЕГРЮЛ, ФНС** | Единый государственный реестр юрлиц; Федеральная налоговая служба — источник реквизитов «Заполнить по ИНН» |
| **СРО, РНП** | Саморегулируемая организация (допуск к работам); реестр недобросовестных поставщиков |
| **УСН, НПД** | Упрощённая система налогообложения; налог на профессиональный доход — режимы без НДС, при которых в СТ ставится пометка «проверьте НДС» |
| **СМР** | Строительно-монтажные работы (в СТ — «Всего СМР», то есть итог по ставкам работ) |
| **РД** | Рабочая документация объекта (ссылка на неё — в пакете документов тендера) |
| **РКН** | Роскомнадзор — регулятор по персональным данным |
| **КЭП, ЭДО** | Квалифицированная электронная подпись; электронный документооборот (вне объёма) |
| **МСК** | Московское время (UTC+3): в нём показываются сроки, письма и имена файлов выгрузок |
