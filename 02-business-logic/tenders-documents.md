# Документы тендера, протокол и выгрузки

Пакет документов, который получает поставщик (рабочая документация, ТЗ, шаблоны договоров, шаблон ФКП, форма оферты), протокол заседания комиссии (docx: реквизиты заседания, место, председатель, суммы «Бюджет / Конкурс / Дельта», вопросы, решения, голосование) и выгрузки по тендеру (СТ в Excel, протокол, реестр тендеров) со штампами.

Связанные разделы: индекс — [tenders.md](tenders.md); экспорт СТ подробно — [tenders-comparison.md §12](tenders-comparison.md#12-экспорт-ст-в-excel); выбор победителя — [tenders-lifecycle.md §8](tenders-lifecycle.md#8-закрытие-тендера-и-выбор-победителя); отчёты и реестровые выгрузки — [analytics.md](analytics.md); данные — [../05-data-model/tables.md](../05-data-model/tables.md#tender_protocols); API — [../04-api/endpoints-tenders.md](../04-api/endpoints-tenders.md), [../04-api/endpoints-rounds.md](../04-api/endpoints-rounds.md); экраны — [../03-screens/tender-card.md](../03-screens/tender-card.md), [../03-screens/tender-create.md](../03-screens/tender-create.md), [../03-screens/fill.md](../03-screens/fill.md), [../03-screens/tenders-registry.md](../03-screens/tenders-registry.md).

Оценка: **L** (пакет документов с рассылкой — S; протокол с окном ввода, предзаполнением и сборкой docx по шаблону — M; выгрузки и штампы — S, без учёта Excel-выгрузки СТ, оценённой в [tenders-comparison.md](tenders-comparison.md)).

## 1. Сущности

| Сущность | Где | Поля |
|---|---|---|
| Пакет документов | поля тендера [tenders](../05-data-model/tables.md#tenders) | ссылка на РД (до 1 000 символов), вложения ТЗ, шаблона договора СМР, договора поручительства |
| Файлы | [attachments](../05-data-model/tables.md#attachments) | файлы тендера (`entity_type = tender`), исходная ведомость (шаблон ФКП) |
| Протокол | [tender_protocols](../05-data-model/tables.md#tender_protocols) | тендер (PK), JSON реквизитов, кто и когда сохранил |
| Журнал ИБ | `security_audit_log` (домен безопасности) | события выгрузок `report_export` |

## 2. Пакет документов тендера

Фиксированный набор слотов (вкладка «Документы» карточки, шаг 3 мастера; поставщик видит тот же пакет в форме КП):

| Ключ | Подпись | Вид | Кто наполняет |
|---|---|---|---|
| `rd_url` | Рабочая документация (РД) | ссылка | специалист |
| `tz_file` | Техническое задание | файл | специалист |
| `smr_contract_file` | Шаблон типового договора СМР | файл | специалист |
| `surety_file` | Договор личного поручительства | файл | специалист |
| `fkp_template` | Шаблон ФКП | файл, только чтение | система: исходная ведомость из мастера создания |
| `offer_form` | Форма оферты / КП | ссылка на форму | система: у поставщика — его персональная ссылка `/fill/<токен>` |

Правила:

- Файл сначала загружается как вложение тендера (общий механизм файлов, в т.ч. прямая загрузка в S3 по предподписанной ссылке), затем привязывается к слоту. Вложение должно принадлежать этому тендеру: «Вложение <id> не принадлежит тендеру». Пустое значение снимает документ со слота.
- При замене документа (по умолчанию, `notify=true`) всем участникам в стадиях «отправлено/доставлено/заполняет/подано» — уведомление «Обновлён документ тендера» («<название>: заменён «<слот>».») и письмо «Обновлён документ — <номер>» со ссылкой на пакет; событие ленты `documents_updated` (слоты, сколько уведомлено) видно поставщикам.
- Ответ по каждому слоту: подпись, вид, есть ли документ, ссылка/вложение (имя, размер, тип, дата загрузки), можно ли менять.
- **Документы на возврат.** Если в пакете есть «Шаблон типового договора СМР» и/или «Договор личного поручительства», форма поставщика требует приложить к КП свои экземпляры в эти же слоты перед подачей («Приложите документы: «…»»). Проверку выполняет интерфейс; в процент «заполнено» документы не входят.
- Поставщик по ссылке может скачать только документы пакета своего тендера, «Шаблон ФКП» (при `FKP_FORM_LOCKED` — защищённую копию, где открыты только ячейки ввода) и свои файлы к КП; любой другой файл — 403 «Файл недоступен по этой ссылке».

Права: правка пакета — сотрудник с доступом к объекту тендера (проверяется только доступ к объекту, см. открытые вопросы); чтение — сотрудник с доступом, поставщик по ссылке.

## 3. Протокол тендера (docx)

Протокол заседания конкурсной комиссии собирается из трёх источников с приоритетом **«введено пользователем» > «данные системы» > «значения по умолчанию из настроек»** (пустая строка и `null` — «не вводил»). Номера заседаний, комиссии и кворума как сущностей в системе нет — их вводят в окне протокола, и всё хранится одним JSON за тендером.

### 3.1. Данные системы (только чтение в окне)

| Показатель | Формула / источник |
|---|---|
| Бюджет | Плановая сумма тендера |
| Конкурс | Итог КП победителя (с НДС) — то же число, что «Итого» в СТ; нет победителя или его КП не подано — пусто |
| Дельта | `Конкурс − Бюджет`; в документе — модулем, красным при перерасходе (> 0), зелёным при экономии (< 0); нет одного из чисел — «Дельта: —» |
| Сумма договора | = Конкурс |
| НДС в сумме договора | `round₂(Сумма × ставка / (100 + ставка))`, ставка 22 % |
| Победитель | Название и **полный** ИНН (независимо от маски контактов) |
| Приглашённые | Все участники в порядке приглашения |
| Подавшие КП | Участники с КП «Подано / На доработке / Принят» |
| Версий КП победителя | Если больше одной — был торг |

### 3.2. Реквизиты, которые вводит пользователь

| Поле | Ограничение | Пусто → |
|---|---|---|
| Номер заседания | ≤ 50 | «№» без номера |
| Дата заседания | дата | «______» (прочерк для рукописи) |
| Место | ≤ 300 | настройка `PROTOCOL_PLACE`; если она пуста, а задан `CLIENT_NAME` — «переговорная/офис компании <CLIENT_NAME>»; иначе пусто |
| Тема совещания | ≤ 4 000 | «Обсуждение результатов тендера на <выполнение/поставку/оказание …> на объекте: <объект>, расположенный по адресу: <адрес>» (если название начинается с «Выполнение/Поставка/Оказание»), иначе «Обсуждение результатов тендера: <название> на объекте: …» |
| Председатель | ≤ 200 | настройка `PROTOCOL_CHAIRMAN` |
| Подпись в шапке | ≤ 200 | = председатель |
| Участники с правом голоса | до 30 строк по 200 | — |
| Секретарь, кворум | 200 / 100 | — |
| Статьи бюджета «код — сумма» | до 20 строк, код ≤ 100, сумма ≥ 0 | — (в строке «Бюджет» всё равно сумма тендера, не сумма статей) |
| Приложения | до 20 строк по 300; `null` — по умолчанию, `[]` — нет приложений | «Сравнительная таблица №1 (прил. № 1)» и, если есть победитель, «КП подрядчика (прил. № 2)» |
| Докладчик по сгенерированным вопросам | ≤ 200 | — |
| Тексты пунктов «приглашены», «получены КП», «сравнительная таблица» | ≤ 4 000; `null` — сгенерировать | §3.3 |
| Свои вопросы (текст + докладчик) | до 30 | — |
| Аванс, срок выполнения работ | ≤ 300 | «______» |
| Текст решения №1 | ≤ 4 000; `null` — сгенерировать | §3.3 |
| Прочие решения (текст + исполнитель) | до 20; `null` — по умолчанию, `[]` — нет | «Подготовить пакет документации для оформления договора (протокол тендера, расчет стоимости)» |

Лишние поля в JSON — ошибка (защита от опечаток); весь документ ≤ **64 КБ** («Протокол больше 64 КБ»). Сохранение (`tenders.manage`) записывает только введённое — умолчания не записываются, чтобы смена настроек или названия тендера доходила до протокола; права на финансы для сохранения не нужно.

### 3.3. Сгенерированные пункты

- **Приглашены:** «На основании запроса о проведении тендерной процедуры по выбору подрядной организации был сделан запрос на выполнение комплекса работ следующим компаниям: <список>» и «Итого: N (число прописью) компаний» (склонение: «1 (одна) компания», «3 (три) компании», «15 (пятнадцать) компаний»; прописью до 99). Нет приглашённых — «…комплекса работ: ______».
- **Получены КП:** «Получены коммерческие предложения от N (прописью, родительный падеж) компаний: <список>» или «Коммерческие предложения не получены».
- **Сравнительная таблица:** «По результатам полученных КП сведена сравнительная таблица №1 (приложение № 1 к протоколу КК № <номер>)». Если у победителя одна версия КП — дописывается «. КП <победитель> - <сумма> руб.»; если версий больше (был торг), сумма не пишется — её вписывает комиссия.
- **Решение №1** (исполнитель «Коллегиально»): «Утвердить в качестве подрядной организации: **<победитель> ИНН <ИНН>** на сумму договора **<сумма> руб.**, в т.ч. НДС 22% в размере <НДС> руб. На следующих условиях: - Аванс: <аванс> (или строка целиком, если аванс начинается с «Без…») - Срок выполнения работ: <срок>». Нет победителя — прочерки.

Деньги в протоколе — формат «69 508 644,44 руб.» (разряды и «руб.» через неразрывный пробел).

### 3.4. Структура документа

Документ собирается по шаблону docx (поставляется с системой):

1. Шапка: «Протокол заседания комиссии по подведению итогов тендера», «Председатель тендерной комиссии», «_________________ /<подпись>/ (подпись)».
2. Строка сумм: «Бюджет: <сумма>» со статьями «код - сумма», «Конкурс: <сумма>», «Дельта: <модуль>» (цветом).
3. «ПРОТОКОЛ Заседания конкурсной комиссии № <номер>», «Дата: <дата> г. Место: <место>».
4. «Тема совещания:», «Председатель:», «Участники (с правом голоса):», «Секретарь:», «Кворум:», «Приложения:» (в два столбца со сквозной нумерацией).
5. «Рассматриваемые вопросы:» — таблица «№ | Содержание вопроса | Докладчик» (три сгенерированных пункта + свои).
6. «Решение:» — таблица «№ | Содержание решения | Решение/Исполнитель» (решение №1 + прочие).
7. «Результаты голосования / подписи членов конкурсной комиссии:» — таблица «Ф.И.О | за/против | подпись», строка на каждого участника с правом голоса.

Таблицы идут в потоке одна под другой (без «плавающего» позиционирования).

### 3.5. Права и аудит

- Открыть окно и выгрузить протокол — сотрудник с доступом к объекту **и правом видеть цены**; без него — 403 «Протокол содержит суммы договора: нужно право видеть цены». Сохранить реквизиты — `tenders.manage`.
- Файл: `<id тендера>_protokol_ГГГГ-ММ-ДД_ЧЧММ.docx` (МСК).
- Выгрузка пишет событие журнала ИБ `report_export` (отчёт «protocol.docx», номер тендера, победитель, был ли сохранённый черновик, ИНН победителя полный).
- Протокол можно выгрузить и до завершения тендера (без победителя — с прочерками).

## 4. Выгрузки по тендеру и штампы

| Выгрузка | Формат | Где описано | Имя файла | Штамп/легенда |
|---|---|---|---|---|
| Сравнительная таблица | .xlsx (формулы, группировки, листы КП по флагу) | [tenders-comparison.md §12](tenders-comparison.md#12-экспорт-ст-в-excel) | `<id>_sravnenie_ГГГГ-ММ-ДД_ЧЧММ.xlsx` | Легенда строкой 2: «Полная выгрузка · дата-время МСК · состав · вид экрана · показатели», пометки о скрытых ценах и контактах; свойства книги «Сравнение КП — <номер>» |
| Протокол | .docx | §3 | `<id>_protokol_ГГГГ-ММ-ДД_ЧЧММ.docx` | — |
| Реестр тендеров (экранный срез) | .xlsx | [analytics.md](analytics.md) | срез реестра | Гриф «ГРИФ: КОММЕРЧЕСКАЯ ТАЙНА / КОНФИДЕНЦИАЛЬНО. Документ содержит сведения ограниченного доступа. Передача третьим лицам без основания запрещена.» — только если в выгрузке есть денежные колонки |
| Отчёты «По тендерам», «По КП» (целиком и срезом) | .xlsx | [analytics.md](analytics.md) | по отчёту | тот же гриф при денежных колонках |

Общие правила выгрузок:

- Время в имени файла и в легенде — московское.
- Каждая выгрузка пишет событие `report_export` в журнал ИБ (кто, IP, что выгружено, параметры).
- Без права на финансы денежные колонки пусты (реестр срезает «Лучшую цену»), а СТ прямо пишет «Цены скрыты: нет права на финансовые данные.»
- Тяжёлые выгрузки ограничены по частоте на пользователя (`HEAVY_READ_RATE_LIMIT` / `HEAVY_READ_RATE_WINDOW`).
- Реестр выгружается тем же набором и порядком колонок, что на экране (колонки, «№», статусы); требуется право `reports.view`.

## 5. События

| Событие | Где | Видно поставщику |
|---|---|---|
| `documents_updated` | лента тендера | да |
| `report_export` (comparison.xlsx / protocol.docx / реестр) | журнал ИБ | нет |

## 6. Граничные случаи

- Тендер без исходного файла (перенесён из прежней системы): слот «Шаблон ФКП» пуст; Excel-выгрузка СТ собирает листы КП в форме ФКП сама.
- Победитель не подавал КП (выбран формально): «Конкурс», «Сумма договора» и «Дельта» пусты, в решении — прочерки суммы.
- Протокол при скрытых контактах: ИНН победителя всё равно полный (решение по протоколу).
- Замена документа без рассылки (`notify=false`) не пишет событие в ленту.

## 7. Пример

Тендер `T-2026-111`, бюджет 1 000 000,00 ₽, победитель «Гамма» (одна версия КП, итог 897 000,00 ₽). Окно протокола: Конкурс 897 000,00 руб.; Дельта = 897 000 − 1 000 000 = −103 000 → в документе «Дельта: 103 000,00 руб.» зелёным; НДС = 897 000 × 22 / 122 = 161 754,10 руб. Сгенерировано: «…следующим компаниям: ООО «Альфа», ООО «Бета», ООО «Гамма»», «Итого: 3 (три) компании», «Получены коммерческие предложения от 3 (трёх) компаний: …», «…сведена сравнительная таблица №1 (приложение № 1 к протоколу КК № 12). КП ООО «Гамма» - 897 000,00 руб.», решение №1: «Утвердить в качестве подрядной организации: ООО «Гамма» ИНН 7700000003 на сумму договора 897 000,00 руб., в т.ч. НДС 22% в размере 161 754,10 руб. На следующих условиях: - Без аванса. - Срок выполнения работ: 2 месяца». Файл `111_protokol_2026-10-21_1530.docx`.
